# 40 多天实战方法论：打造能持续替你经营的 Agent 团队

过去四十天，我一直在把 agent 塞进真实工作流里。

我关心的点很简单：每天真的会发生的事，能不能交给它。分析、跟进、写作、整理、监控、复盘、提醒、状态同步。每天都要发生，发生了就要处理，处理完还要能沉淀，下次继续接着跑。

跑到一定阶段后，我的判断越来越稳定：

决定 agent 能不能长期交付的关键变量，常常不在模型，落点在 harness（执行框架）。

模型像引擎，决定单次输出上限。harness 像整车的结构和规程，决定这台机器能不能每天启动，遇到故障能不能恢复，随着时间能不能越跑越稳。

我把 harness 理解成五件事的组合：节律怎么跑，状态怎么存，记忆怎么更新，工具怎么暴露，错误怎么闭环。你把这五件事做顺了，agent 才会从“会说话”变成“能经营”。

模型强，会让你惊艳一两次。harness 稳，才会让你放心交付一百次。

## 从几个聪明助手，到一套工作系统

大多数人一开始做 agent，会从“造几个助手”开始。写作一个，研究一个，分析一个，写代码一个。

很快就会撞墙。原因也很直白：这些助手是能力碎片，缺少系统性。

今天写了草稿，明天忘了优先级。今天做了判断，换个会话像第一次见面。工具越堆越多，信息越塞越满，表面更强，内部更乱。你会发现你在管理一堆“临时聪明”，没有管理一套“持续经营”。

后来我直接换了思路。

我不再把 agent 当成独立的小工具，我把它们当成同一套系统在不同工作面上的执行接口。重要的不是它们叫什么，重要的是任务如何分流，信息如何流动，决策如何沉淀，异常如何闭环。

讨论 agent 时，角色清单很适合展示。运行机制才决定能不能落地。

## 长期系统的核心是 heartbeat

很多 agent 系统在技术层面都能还原成循环：模型输出工具调用，系统执行工具，结果回灌上下文，模型继续推。

这个循环没问题。问题通常出在默认前提：任务开始才启动，任务结束就退出。

真实工作不长这样。真实工作是一条不断延续的状态流。今天的判断影响明天的执行，上午发现的问题可能晚上才处理完，昨天的结论决定今天的优先级。你要跑的是经营，不是一次性任务。

所以我把系统核心放在 heartbeat。

我用的框架（比如 OpenClaw 这一类）提供按频率唤醒的机制，系统定期把 agent 拉起来，让它按一份检查清单执行。机制是框架能力，真正决定纪律水平的是清单内容。

我的清单很朴素，每次唤醒固定做五件事。

第一，回顾最近发生了什么。第二，把遗漏信息写进日记。第三，扫描其他工作面的产出，找依赖和阻塞。第四，检查定时任务的健康状态。第五，刷新当前状态板。

这五件事没技术门槛，价值却很硬：系统状态保持新鲜，下一次唤醒可以直接从文件恢复上下文，执行链能不断衔接现实。

长期系统里最稀缺的往往不是智能，稀缺的是纪律。heartbeat 就是把系统不断拉回现实的那根绳子。

## 我踩过最大的坑：把更多上下文等同于更聪明

刚开始搭系统时，我也干过一件很典型的事：凡是觉得可能有用的东西，全塞进上下文。

当时我的直觉是，背景越全越安全，agent 越不容易跑偏。

真实结果反过来。信息一多，系统会进入一种危险状态：看起来读了很多，抓不住重点。推理链很完整，细节不断偏移。任务越长，错误率越高，恢复成本越大。

我后来把整个系统改成渐进式加载。

框架的记忆通常能做分层，你可以决定哪些文件每次都加载，哪些按需读取。关键不在能力是否存在，关键在你的分层策略是否能支撑行动。

我用三层：

- 第一层只放当前状态：最重要的优先级，正在推进的事项，系统健康情况。这一层必须短，必须新，必须可覆写。
- 第二层是当天发生过什么，属于短期记忆。需要还原脉络时才拉出来。
- 第三层是长期知识：教训、决策、项目说明、标准流程。它们放在文件系统里，通过索引访问，平时不背在身上。

Agent 不需要随时背着所有知识，它需要知道知识放在哪里。

一旦接受这个原则，系统会变轻很多。token 只是表象，真正的收益来自注意力收敛，工具选择更果断，恢复路径更清晰。渐进式加载不是锦上添花，它是长期系统的生存条件。

## 系统变稳，往往靠删

这四十天里，最反直觉的一件事是：系统变好，经常来自删除。

刚开始做 harness 很容易进入“再补一个模块”的状态。再加个巡检，再接个工具，再加层自动化，再补个自愈流程。看起来更专业。

真实运行后复杂度会繁殖。每一层自动化都带来长期维护义务，每一个工具都带来选择成本和出错面，每一个自愈流程都可能制造新的噪音。

我曾经做过一个巡检流程：每天定时扫描系统健康，发现问题自动创建工单并更新看板。听起来很完整。跑了一个月，工单堆了二十多个，大多是误报。它凌晨五点检查“今天的内容有没有生成”，生成任务八点才跑，于是它每天都忠实制造一个“文件缺失”的问题。

Agent harness 里稀缺的不是能力，稀缺的是清晰度。

任何设计如果不能显著降低认知负担，就会变成摩擦源。过度细化的巡查，频繁的低价值告警，名义上自动化却需要你每天盯的流程，这些都不该存在。

加东西之前我会问一句：能不能先删一个，这是工程诚实。

## 模型会变，但 Harness 会复利

如果一个系统的价值绑定在某一个模型上，它就很脆弱。

模型更新太快了。今天最强，明天可能就被替换。你可以偏爱某个模型的写作风格，也可以偏爱另一个模型的推理习惯，生产环境里模型选择本质上是持续运营决策。

我的系统会按成本、速度、稳定性、任务类型选择不同模型，这个选择会变，甚至会高频变化。只要外层 harness 稳，模型切换就不会伤筋动骨。

文件结构不用重建，状态同步不用重写，记忆分层不用推倒，heartbeat 也不会失效。

我越来越确定，真正会复利的是 harness。

你写下来的每条 lesson 是资产。你修过的一次错误恢复流程是资产。你打磨过的状态板结构、技能索引、调度规范、记忆生命周期，都是资产。模型更换只会让这些资产继续放大。

## 人格层也属于 Harness

真实使用之后，我还有一个判断越来越坚定：人格层也是 harness 的一部分，而且影响巨大。

原因很简单。规则覆盖不了所有模糊决策瞬间。证据不足时要不要收缩，草稿很差时要不要推倒重写，任务不明确时先追问还是先交付一个可落地初稿。这些决定靠一堆规则很难写全。

这时起作用的，是 agent 对“自己该以什么姿态工作”的内部设定。

在很多框架里，这层通常通过一个人格文件来定义，比如 SOUL.md。它承载的内容包括性格、边界、决策风格、什么时候该推回，什么时候该承认不确定。

我观察到一个非常明显的差异。

同样一个任务，判断可信度，数据不足。缺少人格设定的 agent 往往会给出看似完整的分析，结论写得很自信。人格设定清晰的 agent 会直接提示证据不足，给出下一步需要的数据和行动。

同一个模型，同一个任务，变量只有人格文件。输出从“顺滑结论”变成“可运营的谨慎”。

长期系统里，一个会编答案的 agent 很危险，因为你很难发现它在编。人格层让“不确定就说不确定”变成默认行为，这会显著降低长期风险。

## 实战里最难的部分叫运维

如果只看表面，agent 系统最吸引人的是输出能力。能写、能查、能分析、能自动给结果。

一旦放进持续工作流，痛点会转移。真正难的是运维。

第一，记忆生命周期很难。信息什么时候写入，写到哪里，哪些进当日日志，哪些升级成长期知识，哪些需要更新旧文件，哪些只是重复。难点不在写进去，难点在让知识库不发霉。

第二，跨 session 的一致性很难。对话是局部，文件是共享。重要信息没有及时文件化，系统认知迟早会分裂，执行面之间会互相错过。

第三，定时调度永远不是设好就结束。超时、投递失败、配置缺失、重复执行、上游波动，这些都会持续出现。你维护的是一个与外界交互的活系统。

本质上它和传统运维很像，对象从服务器容器变成 prompt、文件、任务链、以及一组会犯错的执行体。

## 想开始就从最小 Harness 配置起步

很多人看完这类文章，第一反应是复制结构，做几个 agent，配几条自动流程，拉几个工作面，期待系统自己长出来。

我更建议从最小 harness 起步。

如果你用 OpenClaw 或类似框架，起点只要三个文件。

第一，SOUL.md。定义身份。告诉 agent 它是谁，如何做判断，遇到不确定时怎么处理，什么时候应该直接推回。两百字够用，边界和决策风格要清晰。

第二，NOW.md。维护当前状态。这个状态板要被优先读取，只写当前最重要的事：正在推进什么，优先级如何，哪些完成，哪些有风险。它要短，要新，要可覆写。

第三，HEARTBEAT.md。设计固定节律。写一份检查清单，规定每次唤醒时检查什么，写什么，更新什么，什么时候通知你。框架负责唤醒频率，你负责清单质量。

这三份文件加起来可能不到一千字，已经足够构成最小可行 harness。你甚至不用写代码，你需要想清楚三件事：我的 agent 是谁，现在该关注什么，多久检查一次。

等它真的跑起来，再按真实需求往上加。需要长期知识，再建 memory 目录做索引。需要任务切换能力，再写 skill 文件按需加载。需要固定节奏产出，再配定时调度。

顺序很重要。起点复杂会把系统压垮，纪律还没形成，能力先把注意力打散了。

## 结语

如果今天让我把整篇文章压缩成一句话，我会这样写：

模型提供智能，Harness 提供纪律。对一个 one-person company 来说，后者更稀缺。

我现在越来越把 agent 看成一套可持续经营的基础设施。节律、状态、记忆、边界、恢复，这几层一旦成形，就会随着使用不断变厚。

Agent 时代最值得建设的，是你自己的 harness。它能把零散的智能变成可复利的系统能力。

一个人也能跑出团队感。前提是，你先把让团队持续运转的那套基础设施建出来。
