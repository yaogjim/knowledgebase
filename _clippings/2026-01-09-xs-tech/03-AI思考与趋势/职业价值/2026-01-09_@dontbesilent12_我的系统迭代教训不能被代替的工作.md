**dontbesilent** @dontbesilent12 2026-01-06

这个过程我用 claude code 实现了自动化

skill 1：用我的系统提示词写文案

我（人类）：评价文案的好坏，提供 feedback

skill 2：判断我的 feedback 是否足以迭代提示词，如果不够，就通知我，如果足够，则触发 skill 3

skill 3：根据历史所有版本的提示词、提示词的产出、我对产出的 feedback，迭代出新的提示词，然后触发 skill 1

于是 claude code 可以做出一个能代替我写文案的 agent

这里，我发现，我唯一不能被 claude code 代替的工作就是：我能判断文字的好坏

我知道它好还是不好，为什么好，为什么不好

也许这就是我的业务基石

> 它写得很烂，但是提示词的框架很好，可以通过有限次数的迭代，改进得很好
>

> 
> 1、哪句写得不好
> 
> 2、为什么不好
> 
> 3、什么情况下可以这么写

**程序员Left** @coder\_left [2026-01-08](https://x.com/coder_left/status/2009311936987775105)

非常同意

我在实践AI写作的过程中，也发现了这个问题

我去用一个简单的提示词，很难让AI发出看起来就像我说的话的文章，反而看起来就像是机器写的

我的反思是：AI可以代替你说话，但是不能代替你表达你的思想，这是我们进行AI写作需要把关的地方

这跟AI coding有异曲同工之妙
