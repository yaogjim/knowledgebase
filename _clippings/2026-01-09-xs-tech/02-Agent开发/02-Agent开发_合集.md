### 你有没有试过让 AI 帮你写代码

**安仔** @geekshellio [2026-01-08](https://x.com/geekshellio/status/2009309705387311105)

你有没有试过让 AI 帮你写代码，结果发现它只会给建议，真正干活还得你自己动手？

我要的不是一个顾问，是一个可以真正帮忙的助手。

但 Claude Agent SDK 的出现改变了这个游戏规则，它让 AI 真的能像工程师一样接手问题，自己读文件、跑命令、改代码，把事情从头到尾搞定。

作者 Dabit 这篇文章其实是在教你怎么用 Claude Agent SDK 从零开始搭建一个代码审查 Agent。

他选了个很实用的场景，就是让 AI 自动检查代码里的 bug、安全漏洞、性能问题，然后给你结构化的反馈报告。

以前你要自己写 Agent 的话，得不停地调用 API，检查模型是不是要用工具，执行工具，再把结果喂回去，这个循环写起来特别烦。

SDK 直接把这个循环封装好了，你只需要告诉它要干什么，它自己就能跑起来。

而且它内置了一堆工具，读文件、写文件、编辑代码、跑 bash 命令、搜索文件内容，这些你都不用自己实现。

文章从最简单的例子开始教你。

先装个 Claude Code CLI，然后创建项目，写几行代码就能让 Claude 列出当前目录的文件。

这个入门例子特别友好，让你先感受一下 SDK 的工作方式。

它返回的是一个异步生成器，会不断 stream 出消息，你可以看到 Claude 在想什么、在用什么工具、最后得出什么结果。

接下来就是重头戏了，搭建代码审查 Agent。

你给它指定一个目录，它就会自动去读代码文件，用 grep 搜索可疑的模式，然后给你列出所有问题。

作者还特意写了个有 bug 的示例代码来演示，比如数组越界、没做空值检查、在日志里打印敏感信息这种典型错误。

Agent 跑起来之后真的能把这些问题都找出来。

但光是文本输出还不够实用对吧？如果你要把这个 Agent 集成到 CI/CD 流程里，你需要结构化的数据。

SDK 支持用 JSON Schema 定义输出格式，你可以让它返回一个包含问题列表、严重程度、文件位置、修复建议的 JSON 对象。

这样你就能程序化地处理这些结果，比如自动生成报告或者触发告警。

权限管理这块也很有意思。

默认情况下 SDK 会在执行工具之前问你要不要批准，但你可以设置成自动批准读操作，或者完全绕过权限检查。

如果你想要更细粒度的控制，还能写个自定义的权限处理函数，比如允许读文件但禁止修改 env 配置文件这种规则。

更高级的玩法是创建子 Agent。

比如你的主 Agent 负责整体协调，然后它可以把安全审查的任务委派给一个专门的安全 Agent，把测试覆盖率分析委派给另一个测试 Agent。

这些子 Agent 可以用不同的模型，比如复杂任务用 Opus，简单任务用 Haiku 来省钱，这种架构在处理复杂项目的时候特别有用。

文章还讲了一些生产环境需要考虑的东西。

比如 Session 管理，你可以保存会话 ID，后续继续对话，Claude 会记住之前的上下文。

还有 Hooks 机制，可以在工具执行前后插入自定义逻辑，比如记录审计日志或者拦截危险命令。

成本追踪功能也很实用，每次运行结束都会告诉你花了多少钱，用了多少 token。

如果内置工具不够用，你还能通过 MCP 扩展自定义工具。

作者举了个例子，写了个计算代码复杂度的工具，然后把它注册到 SDK 里，Claude 就能调用这个工具了。

这个扩展性真的很强，基本上你想让 Agent 做什么都可以实现。

最后作者给了个生产级的完整示例，把前面讲的所有功能都整合进去了。

这个 Agent 不仅能做代码审查，还会实时显示进度，按严重程度分类问题，给出详细的修复建议，最后生成一个漂亮的报告。

你可以直接拿这个代码改改就用到自己的项目里。

说实话看完这篇文章最大的感受就是，Claude Agent SDK 把复杂的 Agent 开发变得像写普通应用一样简单，你只需要专注于业务逻辑，底层的那些脏活累活它都帮你搞定了。

如果你正在考虑给团队引入 AI 工具，或者想自动化一些重复性的代码审查工作，这个 SDK 绝对值得试试。
