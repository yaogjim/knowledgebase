**Andrej Karpathy** @karpathy 2025-10-17

  
上周能来参加德瓦克什的节目是我的荣幸，我认为提问和对话都非常精彩。

我刚才也重温了这期播客。首先，是的我明白，很抱歉我说话太快了:)。这其实对我不利，因为有时候我的语言线程会跑在思考线程前面，导致有些解释可能没讲清楚。有时候我也担心自己会不会偏离主题太远，或者过度深入某些相对次要的内容。总之有几点需要说明/补充：

关于 AGI 时间线的讨论。我对于 AGI 时间线的评论似乎是早期反响中最热门的部分。所谓“智能体十年”的说法源自这条早前推文 https://x.com/karpathy/status/1882544526033924438…——本质上我的 AI 发展时间预测比旧金山 AI 圈派对或推特时间线上的主流观点要悲观 5-10 倍，但相较于日益增长的 AI 怀疑论者仍显乐观。这种表面矛盾并不冲突：我认为我们既见证了 LLMs 近年来的巨大进展（1），同时仍有大量工作待完成（包括基础工作、系统整合、物理世界的传感器与执行器、社会适应性、安全防护（越狱攻击、数据投毒等）），以及实现真正 AGI 所需的研究突破——直到创造出能胜任任意工作岗位且优于人类的实体。总体而言，十年本该是 AGI 发展的激进时间表，只是当下过度炒作的反差让它显得保守了。

动物 vs 幽灵。我早先关于萨顿播客的论述 https://x.com/karpathy/status/1973435013875314729…。我怀疑是否存在某种单一简单算法，释放到世界中就能从零开始学习一切。如果有人造出这样的东西，我将被证明错误，而这将成为人工智能领域最不可思议的突破。在我看来，动物完全不是这样的例子——它们通过进化预先封装了大量智能，其学习过程总体而言相当有限（例如：斑马出生时的情况）。戴上工程思维的帽子，我们不会重走进化之路。但借助 LLMs，我们偶然发现了一种替代方法，通过预测互联网上的下一个词元，在神经网络中“预封装”大量智能——不是通过进化，而是通过预测。这种方法在智能领域催生了一种不同的实体。与动物截然不同，更类似幽灵或精魂。但我们可以（也应该）逐渐让它们变得更像动物，某种程度上这正是许多前沿研究的重点。

关于强化学习。我已经多次批评过强化学习了，比如 https://x.com/karpathy/status/1944435412489171119…。首先，这就像“用吸管汲取监督信号”，我认为其信号/浮点运算效率极低。强化学习还存在严重噪声问题——一个生成结果可能包含大量错误却得到鼓励（如果碰巧蒙对答案），反之蕴含真知灼见的词元可能反遭抑制（如果后续出现失误）。过程监督和 LLM 评判机制也存在缺陷。我认为未来会出现替代性学习范式。我长期看好“智能体交互”方向，但不看好“强化学习”https://x.com/karpathy/status/1960803117689397543…。 最近看到不少论文，在我看来都沿着我提出的"系统提示学习"方向找对了路子，但我认为 arXiv 上的构想与前沿 LLM 实验室真正大规模通用落地之间仍存在差距。总体而言，我相当乐观地认为这个维度的剩余工作很快会取得重大进展，甚至可以说 ChatGPT 的记忆功能等都是新型学习范式的早期部署实例。

关于"认知核心"——我早前提出的这个概念，核心思想是通过精简 LLM 架构、限制其记忆能力或主动剥离记忆，来增强模型的泛化能力。否则模型会过度依赖已记忆的内容。 人类无法轻易记住大量信息，如今看来这反倒更像是一种特性而非缺陷。或许这种记忆限制本身就是一种正则化机制。另附我之前关于模型规模发展趋势为何“看似倒退”的推文，以及为何“模型必须先变大才能变小”的思考：https://x.com/karpathy/status/1814038096218083497… 穿越回杨立昆的 1989 年。这就是我在播客中仓促描述的那篇推文：https://x.com/karpathy/status/1503394811188973569… 核心问题是：凭借 33 年算法进步的经验，能在多大程度上提升杨立昆当年的成果？当时的实验结果究竟受算法、数据、算力中哪个因素制约？这正是值得研究的典型案例。 纳米聊天 。 我对 ChatGPT 训练/推理流程的端到端实现（核心要素精简版）详见链接。关于 LLM 智能体，我的行业观察是当前工具开发存在能力超前的问题。我身处一个自认为的中间态世界——期待与 LLM 协作，实现优势互补。而行业却憧憬着全自主实体并行协作编写代码、人类失去价值的未来。举例来说，我不需要能离线运行 20 分钟、最终生成千行代码的智能体，更没准备好同时督导十个这样的智能体团队。我倾向于可控的渐进式协作：让 LLM 实时解释编写中的代码，向我验证其正确性，主动调取 API 文档演示准确用法，在不确定时减少假设并主动与我协商。 我期望在学习过程中不断提升编程能力，而非被动接受海量看似可行的代码。我认为工具应当更切实际地展现其能力边界及行业适配性，若处理不当，恐怕会导致大量低质代码在软件中堆积，进而增加漏洞与安全风险。https://x.com/karpathy/status/1915581920022585597… 关于职业自动化——放射科医师如何成功应对 https://x.com/karpathy/status/1971220449515516391…，哪些职业更易被自动化取代及其原因。  
  
物理学 。儿童早期教育应引入物理并非要培养物理学家，而是因为这门学科最能激活大脑思维。 物理学家是智慧的胚胎干细胞 https://x.com/karpathy/status/1929699637063307286… 我还有一篇长文在草稿箱里躺了将近一年，希望尽快完成。
