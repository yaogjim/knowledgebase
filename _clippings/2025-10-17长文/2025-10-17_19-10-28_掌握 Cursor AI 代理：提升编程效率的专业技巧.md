### 掌握 Cursor AI 代理：提升编程效率的专业技巧

本文将深入探讨一系列使用 Cursor AI 代理的专业技巧，旨在帮助开发者充分利用这一强大工具，优化编码、调试和项目管理的工作流程。我们将从任务规划、代码审查，到自定义工作流和高级交互功能，逐一详细解析。

#### 使用计划模式 (Plan Mode) 高效规划功能开发

计划模式是 Cursor 代理的一项核心功能，它能让 AI 深入分析你的代码库，理解现有架构，并为你规划出高质量的功能实现方案。这不仅能节省开发者前期调研和设计的时间，还能确保新功能的实现路径与项目现有逻辑保持一致。

要启用计划模式，首先可以通过快捷键 `Command + N` 创建一个新的聊天窗口，以确保对话上下文的纯净。接着，使用快捷键 `Shift + Tab` 即可轻松切换到计划模式。

在视频演示中，开发者希望在其个人网站上添加一个新页面，用于展示他在 Spotify 上最喜欢的艺术家。这是一个非常适合使用计划模式的场景，因为它涉及到与现有功能的集成（网站已经集成了 Spotify API 来显示当前播放的曲目）。

开发者向处于计划模式的代理发出了指令：“让我们创建一个新页面来显示我在 Spotify 上的顶级艺术家。”

代理在接收到指令后，并没有立即开始编写代码，而是首先对整个代码库进行了研究和分析。它识别出了项目中已有的 Spotify 集成、认证处理逻辑以及现有的组件和页面结构。基于这些信息，代理提出了一系列关键问题以澄清需求细节，确保最终生成的计划精准无误。这些问题包括：

1.  **URL 路径**：新页面应该位于哪个 URL？例如 `/artists` 还是 `/music`？
2.  **显示数量**：需要显示多少位顶级艺术家？例如前 10 名、前 20 名还是前 50 名？
3.  **时间范围**：数据的统计时间范围是什么？是最近四周（短期）、最近六个月（中期），还是所有时间（长期）？
4.  **显示内容**：每位艺术家需要显示哪些信息？是只显示名字和链接，还是包含图片、流派和热度分数？

这种交互式的澄清过程至关重要，它避免了因需求模糊而导致的后期返工。开发者根据 AI 的提问给出了明确的答复：

*   路径定为 `/music`。
*   显示前 10 名艺术家。
*   同时展示“所有时间”和“最近三个月”两个时间维度的数据。
*   关于显示内容，开发者让代理“运用其最佳判断”，给予 AI 一定的自主决策空间。

在收集完所有必要信息后，代理生成了一个详细的 `plan.md` 文件。这个计划文件结构清晰，包含了：

*   **概述 (Overview)**：简要说明要构建的功能。
*   **实施步骤 (Implementation Steps)**：分步拆解任务，例如“修改 Spotify API 函数以接受时间范围参数”、“创建新的顶级艺术家组件 (TopArtists Component)”、“创建音乐页面路由”。每一步都引用了需要修改或创建的具体文件名和函数名，如 `lib/spotify.ts` 和 `components/last-played.tsx`。
*   **关键文件 (Key Files)**：列出将要被触及的所有核心文件。
*   **待办事项列表 (To-Do List)**：生成一个可勾选的任务清单，方便开发者跟踪进度。

开发者在审查计划后，进行了一些微调，比如删除了计划中关于“撰写音乐品味简介”这一非必要步骤，然后点击“构建 (Build)”按钮。代理随即开始根据最终确定的计划执行编码任务。

然而，在初次执行后，页面加载时出现了权限错误。这展示了开发过程中的真实挑战。开发者没有自行调试，而是将错误信息直接复制粘贴回聊天窗口。代理识别出这是因为新的 API 端点需要额外的 Spotify 权限。它迅速给出了解决方案：指导开发者如何更新 Spotify 应用的权限范围，并重新进行 OAuth 授权以获取新的刷新令牌 (refresh token)。在开发者按照指引更新了认证信息后，页面成功加载，并完美地展示了两个时间维度的顶级艺术家列表。这个完整的流程不仅展示了计划模式的强大规划能力，也体现了其在协助调试和解决问题方面的智能。

#### 善用上下文菜单与 `@branch` 进行代码审查

在软件开发中，代码审查是保证代码质量的关键环节。Cursor 代理提供了一系列强大的上下文感知命令，能够极大地简化这一过程。通过在聊天框中输入 `@` 符号，可以唤出一个功能丰富的上下文菜单。

这个菜单允许你将各种信息注入到与 AI 的对话中，使其能够更精准地理解你的意图。菜单中的选项包括：

*   **文件和文件夹 (Files & Folders)**：引用项目中的任意文件或整个目录。
*   **代码 (Code)**：引用当前选中的代码片段。
*   **文档 (Docs)**：引入公共的 API 文档或技术资料。
*   **Git 相关**：执行与版本控制相关的操作。
*   **过去的聊天 (Past Chats)**：引用之前的对话内容。
*   **规则 (Rules)**：应用预设的编码规范或 linting 规则。
*   **终端 (Terminal)**：引用终端的输出内容。

其中，`@Git` 命令族尤其强大，它包含了一个非常有用的子命令：`@branch`。这个命令允许 AI 访问并分析特定 Git 分支上的所有代码变更。

演示中，开发者在完成了“顶级艺术家”页面功能后，通过 `Command + Shift + P` 调出命令面板，创建了一个名为 `top-artists` 的新 Git 分支。随后，他在一个新的聊天窗口中，使用了 `@branch` 命令，并向代理发出指令：“审查所有变更，看看是否存在任何问题。”

这个 `@branch` 标签会自动将当前分支与主分支（例如 `main`）之间的差异（diff）作为上下文提供给 AI。代理接收到这些变更信息后，开始进行全面的代码审查。它的输出通常包含以下几个部分：

*   **总体评估 (Overall Assessment)**：对代码变更的整体评价，例如“这次变更看起来很不错，实现遵循了代码库中的现有模式。”
*   **发现的问题 (Issues Found)**：指出代码中可能存在的潜在问题、错误或可以改进的地方。在演示中，AI 发现了一个“潜在的缓存持续时间不匹配 (Potential Cache Duration Mismatch)”的问题。它指出，一个函数设置的缓存时间是 24 小时，而另一个相关的组件设置的重新验证时间（revalidate）远短于此，这可能导致组件无法及时获取到最新的数据。这是一个非常细致且有价值的发现，人类审查者可能会忽略这一点。
*   **值得肯定的地方 (What Looks Good)**：列出代码中的优点，例如“OAuth 范围已正确更新”、“错误处理周全”、“类型安全良好”等，给予开发者积极的反馈。
*   **建议 (Suggestions)**：提出具体的修改建议来解决发现的问题。

通过这种方式，`@branch` 命令将 AI 转变为一个不知疲倦的代码审查助手。它不仅能发现逻辑错误和潜在风险，还能评估代码是否遵循了项目规范，并从多个维度提供富有建设性的反馈，极大地提升了团队的代码质量和开发效率。

#### 创建自定义命令简化重复工作流

对于开发者而言，许多工作流程是重复性的，例如创建 Pull Request、运行测试、或者格式化文档。Cursor 允许用户通过创建自定义命令来自动化这些流程，将一系列复杂的步骤封装成一个简单的指令。

创建自定义命令的流程非常直观：

1.  **找到 `.cursor` 文件夹**：在你的项目根目录下，找到名为 `.cursor` 的隐藏文件夹。
2.  **创建 `commands` 目录**：在该文件夹内，创建一个名为 `commands` 的新目录。
3.  **编写命令文件**：在 `commands` 目录中，创建一个 Markdown 文件（`.md` 后缀）。该文件的文件名将成为你的命令名。例如，创建一个名为 `pr.md` 的文件，那么你就可以通过 `/pr` 来调用这个命令。
4.  **定义命令提示 (Prompt)**：在 Markdown 文件中编写的内容就是这个命令的核心提示。你可以详细描述希望代理执行的任务、遵循的规则以及输出的格式。

在视频的演示中，开发者创建了一个 `/pr` 命令，用于自动化创建 GitHub Pull Request 的过程。他在 `pr.md` 文件中定义了以下指令：

> 你的任务是创建一个 PR（Pull Request），需要包含一个描述性的标题。始终使用 GitHub CLI（命令行工具）。如果你还没有创建一个 commit（提交），请先执行 commit 操作。

这个提示清晰地定义了任务目标（创建 PR）、工具（GitHub CLI）和前置条件（必须有 commit）。

当开发者在聊天窗口中输入 `/pr` 并执行时，代理便会遵循这些指令开始工作。它的执行过程如下：

1.  **检查状态**：首先，代理会运行 `git status` 来检查当前工作区的状态，确认有哪些文件被修改了。
2.  **创建提交**：由于检测到有未提交的更改，并且提示中要求“先执行 commit 操作”，代理会自动执行 `git add .` 和 `git commit -m "feat: Add Spotify top artists page"` 等命令，创建一个包含所有变更的提交。它甚至能智能地生成一条符合规范的提交信息。
3.  **创建 Pull Request**：在代码提交后，代理接着调用 GitHub CLI 命令，如 `gh pr create --title "Add Spotify Top Artists Integration" --body "..."`，来创建 Pull Request。它同样会自动生成一个合适的标题和描述。
4.  **返回结果**：任务完成后，代理会在聊天窗口中返回一个指向刚刚在 GitHub 上创建的 Pull Request 的链接。

通过这个简单的 `/pr` 命令，开发者将检查状态、提交代码、编写标题和描述、创建 PR 这一系列繁琐的步骤，全部自动化了。这种自定义命令的能力极具扩展性，你可以为任何重复性的工作流创建命令，无论是部署到测试环境、生成样板代码，还是根据模板创建新的组件，从而极大地解放生产力。

#### 利用图像输入实现可视化编程

除了处理文本和代码，Cursor 的 AI 代理还具备多模态能力，能够理解和分析图像内容，并将其作为编程的参考依据。这个功能为 UI/UX 开发带来了革命性的变化，让开发者可以直接根据设计稿或参考截图来构建和修改界面。

要使用此功能，你只需将一张图片（可以是通过截图工具复制到剪贴板的，也可以是本地文件）直接粘贴到聊天输入框中。代理会识别并显示这张图片，然后你就可以围绕它下达指令了。

在视频中，开发者已经创建了一个纯文本的顶级艺术家列表页面。他希望将这个页面的样式修改得更像 Spotify 年度总结 (Spotify Wrapped) 的那种视觉风格。为此，他找到了一个类似风格的 Instagram Story 截图，上面以卡片和数字排行的形式展示了榜单。

他将这张截图粘贴到聊天框中，并给出了一个结合了文本和图像的复合指令：

> 让 `@top-artists.tsx` 和 `@/app/music/page.tsx` 这两个文件（通过 `@` 符号精确引用文件）的显示效果更接近这张图片，并加上艺术家的照片。

代理在接收到这个多模态输入后，进行了以下分析和操作：

1.  **图像分析**：它“看”懂了截图中的视觉元素，包括红色背景、大号的数字排行、方形的艺术家图片、以及旁边的艺术家名字。
2.  **代码分析**：它检查了被引用的 `@top-artists.tsx` 和 `@/app/music/page.tsx` 文件的现有代码，了解当前的实现方式（一个简单的有序列表）。
3.  **任务规划**：结合图像和现有代码，代理规划出了一系列必要的修改步骤：
    *   **获取图片数据**：首先，需要修改 `lib/spotify.ts` 文件中的 API 请求函数，使其在获取艺术家数据的同时，也能获取到他们的图片 URL。
    *   **更新组件结构**：接着，修改 `top-artists.tsx` 组件，使用 `<div>` 和 `<img>` 标签来重构列表项，创建卡片式布局。它添加了样式类 (className) 来实现布局，比如使用 Flexbox 来排列数字、图片和文字。
    *   **配置外部图片源**：由于艺术家的图片来自 Spotify 的 CDN（内容分发网络），需要在 Next.js 的配置文件 `next.config.js` 中添加相应的域名白名单，以允许 Next.js 的 Image 组件加载这些外部图片。
4.  **执行修改**：代理生成了所有必要的代码变更，开发者审查后直接应用。

最终，当页面刷新时，原本朴素的文本列表变成了一个视觉效果丰富、与参考图高度相似的排行榜。每个列表项都包含了醒目的数字、艺术家的专辑封面或照片，以及他们的名字。开发者评价说，AI 的实现“非常忠实于”原图。这个案例完美展示了图像输入功能如何将视觉设计稿无缝地转化为实际的前端代码，大大缩短了从设计到实现的链路。

#### 灵活管理对话：复制对话与时间回溯

在与 AI 代理进行复杂的编程任务时，有效地管理对话历史和上下文至关重要。Cursor 提供了两种强大的功能来应对这一需求：复制对话（Forking/Duplicating Chats）和时间回溯（Checkpoints）。

**复制对话 (Duplicate Chat)**

这个功能允许你从当前对话的任意节点“分叉”，创建一个包含所有历史上下文的全新对话副本。这在以下场景中非常有用：

*   **探索不同方案**：当你面对一个问题有多种可能的解决方案时，可以为每一种方案创建一个对话分支。这样，你可以在不污染主对话的情况下，分别尝试不同的实现路径，最后再决定采用哪一个。
*   **隔离任务**：如果一个对话中已经包含了大量关于某个功能的上下文，而你现在想基于此开始一个稍微不同的新任务，复制对话可以让你继承所有相关知识，而无需从头开始。

要复制对话，只需点击聊天记录右上角的“...”菜单，然后选择“复制对话 (Duplicate Chat)”即可。虽然这是一个便利的功能，但讲者也提醒，为了获得最佳的模型性能，通常建议保持每个对话的上下文尽可能精简和专注。

**时间回溯 (Checkpoints)**

这是一个更为强大的功能，它允许你在对话历史中“倒带”，将项目文件和聊天状态完全恢复到之前的某个时间点。每一次 AI 的回复和代码修改，都可以被视为一个“检查点 (checkpoint)”。

在视频演示中，AI 根据开发者的要求，将排行榜上的数字样式变得更小了。但在看到结果后，开发者觉得还是之前的大数字效果更好。此时，他并没有手动改回代码，也没有重新发出指令，而是使用了时间回溯功能。

操作步骤如下：

1.  **找到目标检查点**：向上滚动聊天记录，找到修改数字样式之前的那次 AI 回复。
2.  **点击回溯按钮**：在那个聊天记录的右上角，有一个类似“撤销”或“回溯”的图标。
3.  **确认操作**：点击该图标后，系统会弹出一个确认框，提示“是否要丢弃此检查点之后的所有更改？”
4.  **恢复状态**：确认后，Cursor 会自动撤销之后进行的所有文件修改，并将聊天状态重置回那个时间点。

瞬间，代码文件中的 CSS 类名和组件结构都恢复到了之前的版本，网页上的数字也变回了原来的大尺寸样式。这个功能就像一个针对 AI 编程过程的“版本控制系统”，让你能够无风险地进行各种尝试，即使 AI 的修改不尽如人意，也能一键恢复到满意的状态。尽管如此，讲者最后还是强调，这个功能不能完全替代 Git。学会使用 Git 进行分支管理和提交，是进行更持久和更可靠的版本控制的最佳实践。结合使用 Cursor 的检查点功能和 Git，可以为开发工作流提供双重保障。

#### 保持高效：关注上下文窗口并开启新对话

为了从 AI 代理处获得最高质量的响应并有效控制成本，开发者需要养成两个重要的习惯：时刻关注上下文窗口的使用情况，并为不同的任务频繁开启新的对话。

**关注上下文窗口指示器 (Context Gauge)**

大型语言模型（LLM）的性能与其处理的上下文（Context）长度密切相关。上下文窗口指的是模型在一次交互中能够“记住”和处理的信息量，包括你的指令、历史对话、以及你提供的代码文件。当上下文过长时，模型可能会“忘记”早期的信息，导致其响应质量下降、偏离主题，甚至出现错误。

Cursor 在代理面板的右下角提供了一个非常直观的**上下文窗口指示器**。这个指示器会实时显示：

*   **已用上下文百分比**：例如，“11.8%”。
*   **具体的 Token 数量**：例如，“23.6k / 200k context used”，这表示在模型 200,000 个 Token 的总容量中，当前对话已经使用了 23,600 个 Token。

通过时刻留意这个指示器，你可以判断当前对话是否过于臃肿。如果百分比过高（例如超过 70-80%），就意味着模型性能可能会开始下降，此时就应该考虑精简上下文或开启新的对话。

**频繁开启新对话 (Start New Conversations Frequently)**

这是管理上下文最直接有效的方法。许多初学者容易犯的一个错误是，在一个冗长的聊天线程中不断添加新的、不相关的任务。例如，在一个关于修复后端 Bug 的对话中，又去要求 AI 添加一个新的前端功能。这样做会导致上下文变得混乱，既包含了旧的 Bug 信息，又混入了新的功能需求，AI 很难再给出专注且高质量的回答。

正确的做法是遵循“一个任务，一个对话”的原则。每当你开始一个全新的、相对独立的任务（例如实现一个新功能、修复一个特定的 Bug），都应该使用快捷键 `Command + N` 来开启一个全新的聊天会话。

这样做的好处是：

*   **保持上下文纯净**：新的对话从零开始，你可以精确地只添加与当前任务相关的代码文件和信息。
*   **提升模型性能**：专注的上下文能让模型更好地理解任务目标，从而生成更准确、更相关的代码和建议。
*   **降低成本**：更少的上下文 Token 意味着更低的 API 调用成本。

你可以使用 `/summarize` 命令来对长对话进行总结和压缩，但这通常不如直接开启一个新对话来得干净利落。养成频繁开启新对话的习惯，是成为 Cursor 高效用户的关键一步。

#### 快捷键、用量统计与通知：提升用户体验的实用技巧

除了核心的编程辅助功能，Cursor 还内置了许多贴心的细节设计和高级选项，可以进一步提升你的开发体验。这些功能集中在“设置”菜单和快捷键配置中，以下是一些特别实用的技巧。

**实用的快捷键**

*   **`Command + I`**：这是最常用的快捷键之一，可以快速打开或聚焦到代理聊天窗口，让你无需离开键盘即可与 AI 互动。
*   **`Command + /`**：这个快捷键允许你快速切换正在使用的 AI 模型。例如，你可以在需要快速生成代码时切换到速度更快的模型（如 Claude 4.5 Sonnet），而在需要进行深度分析或复杂推理时切换到能力更强的模型（如 GPT-4）。

Cursor 允许用户在设置中自定义几乎所有的快捷键，你可以根据自己的习惯进行配置。

**用量摘要 (Usage Summary)**

对于使用按量付费模型的用户来说，实时了解自己的 API 使用情况非常重要。在 `设置 (Settings) -> AI 聊天 (AI Chat)` 中，可以找到“用量摘要”选项。你可以将其设置为：

*   **自动 (Auto)**：默认选项，只在你的用量接近月度限额时才显示。
*   **总是 (Always)**：始终在聊天窗口底部显示一个用量条。

启用“总是”后，你可以清晰地看到已使用的额度百分比，以及额度重置的日期。这对于成本控制和预算管理非常有帮助。

**通知与提示音**

*   **完成提示音 (Completion Sound)**：当 AI 完成一个耗时较长的任务（如执行一个完整的计划）时，你可能已经切换到其他窗口工作了。在设置中启用这个选项后，任务完成时会播放一个提示音，提醒你可以回来检查结果了。
*   **系统通知 (System Notifications)**：这是一个比提示音更强的提醒方式。启用后，当任务完成或需要你授权执行某个命令（如终端操作）时，Cursor 会发送一个原生的操作系统通知。

**生成 Mermaid 图表**

Cursor 代理能够生成 Mermaid 格式的图表代码，用于数据流、架构或流程的可视化。这是一项非常强大的文档和沟通工具。在视频中，开发者要求代理“为 Spotify 流程生成一个 Mermaid 图表”。AI 随即生成了一张非常详尽的序列图，清晰地展示了从用户发起请求、进行 OAuth 认证、交换 Code 获取 Token，到后续使用 Token 获取数据的完整流程，涉及用户、App、Spotify API 等多个参与方之间的交互。这对于理解复杂的业务逻辑或向团队成员解释系统架构非常有帮助。

**全新的三栏式代理布局 (New Agent Layout - Beta)**

Cursor 正在测试一种全新的界面布局，你可以在 Beta 设置中启用它。这种布局将界面分为三个部分：

*   **左栏**：显示所有代理对话的历史列表，方便你快速切换和回顾。
*   **中栏**：当前的主对话窗口。
*   **右栏**：专门用于显示代码的差异对比（Diff View）。

这个新布局使得同时查看对话、代码变更和历史记录变得更加方便。更重要的是，它旨在与外部工具进行更深度的集成，例如连接到浏览器来读取网络请求日志和 DOM 结构，或者直接在界面中运行和交互终端命令，预示着未来 AI 代理将具备更全面的环境感知和执行能力。
