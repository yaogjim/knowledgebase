# LotusDecoder 使用了一个月的openclaw， 发现适合的人群相对较窄。 - 有

**LotusDecoder**

使用了一个月的openclaw， 发现适合的人群相对较窄。 - 有一定技术维护能力，部署和维修都需要动手，包括请得到人和使用 claude code 来拯救。 - 对错误、掉线、杀自己包容性大，经常卡顿是很恼火的。 - 愿意投入，硬件上隔离运行，云服务器，容器，独立mac。软件上花钱买优质api token。 这一个月里，经过了，将小龙虾，从linux云服务器，开一个claudeflare的docker容器，搬到mac studio主用户下，再从主用户迁移到隔离用户。让openclaw写了推文下载成文档并翻译识图，写了待办事项的web，和朋友在discord拉一个群聊，让两个openclaw的bot在群聊里互相聊天，一起排bug 和学习各自的记忆机制。 首先，小龙虾的自杀率是很高的，让他自己改了配置，傻乎乎地改了，然后再喊他没响应，发现是把自己给玩死了。后面给本地 workspace/ 目录下，加装了 ta 自己的源代码和官方doc，告诉他，以后修改自己设置请千万千万去看一眼官方doc，搞不定再看源代码，再修改，然而没什么用，迷之自信，随手就改了，改出问题，又是一副躺在地上要死的样子。所以，玩小龙虾，得自己很有耐心去挽救ta，还要有一定的bug分析能力。 其次，能力是很局限的，如果让它写一段代码，这个很看model 能力了，即使是 opus-4.6 ，写简单的脚本还好，写稍微复杂点，再结合到 discord ，那要反复返工打磨，如果调用 claude-code 来做开发，常规的exec和刚出ACP还是经常报错的，所以实际在社交软件上聊天消息搞生产力编程，还是很不好用的。 这两点稳定性和功能性局限，使我认为还是需要更换一款适合编程开发的24小时助理型agent，我初步考虑使用 hermes agent 或 pi /bub 的自研了。 最后再来说， 适合人群呢，我猜测是属于，文字、网络、线上社交任务多的，有一些技术或愿意学习的人，空余时间多和容错高的，不用于复杂编程开发或系统性事务的，曾经很少做过工作自动化的，有经济投入意愿的，因为目前 opus-4.6 是玩的最爽的，这样的人群比较适合上手玩起来，可以感受到ai助理带来的活人感气息，给自己生活和工作带来很多帮助便利。
