# trader-c 我把在open claw部署在飞书上的agent team，31人团队解散

**trader-c**

我把在open claw部署在飞书上的agent team，31人团队解散了 之前那31个AI Agent的设计架构是直接把我想要的效果给AI说得出来的 这种方式存在两个问题：一是输出结果比较杂乱，agent太多，使用起来比较麻烦； 二是如果事先提示词限制，搞出来agent team效果趋向于平庸值，无法达到我们想要的超越平庸值的高级效果。 而如果训练那31个agent，耗费的时间和精力以及对配额来说太不划算了 所以我把之前那31个Agent能实现的功能和效果，通过已有的文档让Claude code进行梳理和总结，明确这31个Agent各自能达到什么效果、具备什么功能。 我将Claude总结出的31个Agent的功能描述复制下来，作为基础需求输入。 然后提出新的设计目标： 设计一个Team，使用Open claw部署在飞书上。 设计时加入了一个关键条件，即以德鲁克的管理学原则作为组织设计的理论依据。Claude据此给出了一个10人团队的方案。 我对这个10人团队的组织架构进行蒙特卡洛模拟，让系统将该架构模拟运行1万次，检验在运行过程中可能出现问题的环节，识别出因缺少哪些功能而可能导致破产或失败的风险点。 模拟完成后，Claude code根据结果又补充了3个agent。 最终形成了一个13人的团队架构。我在设计中还加入了一个约束条件：可靠性优先于精简性，避免架构过于复杂，因为过于复杂会导致数据冗余，反而影响整体运行效果。 这就是我现在使用的agent team 的设计架构，等搞好了看看效果
