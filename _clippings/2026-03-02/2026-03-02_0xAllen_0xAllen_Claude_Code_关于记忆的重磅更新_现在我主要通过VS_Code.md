# Claude Code 关于记忆的重磅更新

现在我主要通过VS Code 配合 Claude Code 进行日常的工作。但是遇到一个很头疼的问题就是把AI调教了很久。结果关闭IDE下次打开以后又啥都不记得了。 虽然我前期按照 OpenViking 进行了记忆的改造，但是记忆比较依赖人工还是不够灵活。所以如何让AI记着我以前打磨他的所有关键信息成了生产力限制的一个瓶颈。

Claude Code最近更新的自动记忆，可以以后让AI拥有长期记忆，用的时间越久以后CC越懂你。

# 以前用CC


# 01.功能介绍

Claude Code 的自动记忆（Auto Memory）功能允许 AI 助手在对话过程中自动识别、提炼并持久化保存关键信息，无需用户手动干预。

## 一、 核心特性

1\. 完全自动化：Claude 会主动监控对话，识别值得长期保存的信息

2\. 智能提炼： 自动判断信息的重要性和相关性

3\. 跨会话持久化： 记忆内容在新会话中自动加载

4\. 低维护成本： 用户无需手动管理，偶尔检查即可

5\. 结构化存储： 使用 Markdown 格式，易于阅读和编辑

## 二、记忆内容类型

Claude 会自动记录以下类型的信息：

1.  用户偏好：工作流习惯、沟通风格、工具选择
2.  设计决策：架构选择、技术方案、权衡考量
3.  项目约定：命名规范、文件结构、开发流程
4.  技术经验：已解决的问题、最佳实践、避坑指南
5.  关键上下文：项目背景、业务逻辑、核心概念

# 02\. 安装步骤

方法一：手动创建（推荐）

在项目根目录创建 \`MEMORY.md\` 文件即可

方法二：让 Claude 创建

直接在对话框中提出要求，比如：请启用自动记忆功能

* * *

# 03\. 使用方法

开启这个功能以后，就不需要做任何事情了。后续和CC所有沟通都会被识别关键信息，然后CC自动写入Memory.md文件，下次开启会话时自动加载。

在使用过程中同样支持直接要求CC记录某些关键信息或者删除、修改某些记忆信息。因为这个记忆默认加载的是前200行，所以MD文件的规则尽量往简单的写，而且做好层级的管理。比如你文件夹下还有其他不同的项目，建议针对每个项目创建单独的MD，然后在根目录的MD文件中写上索引就可以。

workspace/ 工作区/

├── MEMORY.md              # 全局记忆（通用偏好、工作习惯）

├── project-a/ ├── 项目-a/

│   └── memory.md          # 项目 A 的专属记忆

├── project-b/ ├── 项目-b/

│   └── memory.md          # 项目 B 的专属记忆

总结，这是CC记忆体系一次全新的变化，如果有兴趣也可以研究一下 Openviking架构，基于文件体系的理念来对这套记忆系统进行更深层次的优化。
