# Muratcan Koylan You should treat context engin

**Muratcan Koylan**

You should treat context engineering as an ongoing process rather than a one-time task done only before starting a project. 50% of AGENTS\[.\]md files in open source projects were never modified after the first commit. And the main problem with the updated ones is adding more instructions. Not restructuring, not removing outdated ones but just piling on. This is the opposite of how context engineering should work. More context isn't better context. From my experience, agents follow instructions but unnecessary requirements make tasks harder. You should never "dump everything into one file"; instead, create multiple instruction files. An agent working on tests doesn't need your deployment instructions. An agent writing code doesn't need your contribution guidelines. You can place files in subdirectories so instructions apply only to that part of the codebase. You can use separate Skill files for different tasks. The architecture of your context should mirror the architecture of your project. So instead of one file for everything, multiple files with update protocols! The paper is "Context Engineering for AI Agents in Open-Source Software", pretty concise but has some good insights like common instruction writing styles.
