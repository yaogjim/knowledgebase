## Impeccable

The vocabulary you didn't know you needed. 1 skill, 17 commands, and curated anti-patterns for impeccable frontend design.

> **Quick start:** Visit [impeccable.style](https://impeccable.style) to download ready-to-use bundles.

## Why Impeccable?

Anthropic created [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design), a skill that guides Claude toward better UI design. Impeccable builds on that foundation with deeper expertise and more control.

Every LLM learned from the same generic templates. Without guidance, you get the same predictable mistakes: Inter font, purple gradients, cards nested in cards, gray text on colored backgrounds.

Impeccable fights that bias with:

- **An expanded skill** with 7 domain-specific reference files ([view source](/pbakaus/impeccable/blob/main/source/skills/frontend-design))
- **17 steering commands** to audit, review, polish, distill, animate, and more
- **Curated anti-patterns** that explicitly tell the AI what NOT to do

## What's Included

A comprehensive design skill with 7 domain-specific references ([view skill](/pbakaus/impeccable/blob/main/source/skills/frontend-design/SKILL.md)):

| Reference | Covers |
| --- | --- |
| [typography](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/typography.md) | Type systems, font pairing, modular scales, OpenType |
| [color-and-contrast](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/color-and-contrast.md) | OKLCH, tinted neutrals, dark mode, accessibility |
| [spatial-design](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/spatial-design.md) | Spacing systems, grids, visual hierarchy |
| [motion-design](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/motion-design.md) | Easing curves, staggering, reduced motion |
| [interaction-design](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/interaction-design.md) | Forms, focus states, loading patterns |
| [responsive-design](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/responsive-design.md) | Mobile-first, fluid design, container queries |
| [ux-writing](/pbakaus/impeccable/blob/main/source/skills/frontend-design/reference/ux-writing.md) | Button labels, error messages, empty states |

### 17 Commands

| Command | What it does |
| --- | --- |
| `/teach-impeccable` | One-time setup: gather design context, save to config |
| `/audit` | Run technical quality checks (a11y, performance, responsive) |
| `/critique` | UX design review: hierarchy, clarity, emotional resonance |
| `/normalize` | Align with design system standards |
| `/polish` | Final pass before shipping |
| `/distill` | Strip to essence |
| `/clarify` | Improve unclear UX copy |
| `/optimize` | Performance improvements |
| `/harden` | Error handling, i18n, edge cases |
| `/animate` | Add purposeful motion |
| `/colorize` | Introduce strategic color |
| `/bolder` | Amplify boring designs |
| `/quieter` | Tone down overly bold designs |
| `/delight` | Add moments of joy |
| `/extract` | Pull into reusable components |
| `/adapt` | Adapt for different devices |
| `/onboard` | Design onboarding flows |

### Anti-Patterns

The skill includes explicit guidance on what to avoid:

- Don't use overused fonts (Arial, Inter, system defaults)
- Don't use gray text on colored backgrounds
- Don't use pure black/gray (always tint)
- Don't wrap everything in cards or nest cards inside cards
- Don't use bounce/elastic easing (feels dated)

Visit [impeccable.style](https://impeccable.style#casestudies) to see before/after case studies of real projects transformed with Impeccable commands.

## Installation

Visit [impeccable.style](https://impeccable.style), download the ZIP for your tool, and extract to your project.

**Cursor:**

```
cp -r dist/cursor/.cursor your-project/
```

> **Note:** Cursor skills require setup:
> 
> 1.  Switch to Nightly channel in Cursor Settings → Beta
> 2.  Enable Agent Skills in Cursor Settings → Rules
> 
> [Learn more about Cursor skills](https://cursor.com/docs/context/skills)

**Claude Code:**

```
# Project-specific
cp -r dist/claude-code/.claude your-project/

# Or global (applies to all projects)
cp -r dist/claude-code/.claude/* ~/.claude/
```

**Gemini CLI:**

```
cp -r dist/gemini/.gemini your-project/
```

> **Note:** Gemini CLI skills require setup:
> 
> 1.  Install preview version: `npm i -g @google/gemini-cli@preview`
> 2.  Run `/settings` and enable "Skills"
> 3.  Run `/skills list` to verify installation
> 
> [Learn more about Gemini CLI skills](https://geminicli.com/docs/cli/skills/)

**Codex CLI:**

```
cp -r dist/codex/.codex/* ~/.codex/
```

## Usage

Once installed, use commands in your AI harness:

```
/audit # Find issues
/normalize # Fix inconsistencies
/polish # Final cleanup
/distill # Remove complexity
```

Most commands accept an optional argument to focus on a specific area:

```
/audit header
/polish checkout-form
```

**Note:** Codex CLI uses a different syntax: `/prompts:audit`, `/prompts:polish`, etc.

### 🤖 AI

**主旨概括：**  
Impeccable 是一套专门帮助 AI 做出更好前端设计的 “设计语言工具包”。它通过**更细的设计知识、17 个指令和明确的反模式约束**，减少 AI 常见的审美套路和低级设计问题。

---

## 1. 这是什么：一个让 AI 更会做设计的工具
- 项目名叫**Impeccable**，核心定位是：  
  **“你原本不知道自己需要的设计词汇表”**。
- 它主要包含：
  - **1 个设计 skill**
  - **17 个命令**
  - **一套整理好的反模式规则**
- 目标是提升 AI 在**前端界面设计**上的表现，让生成结果更专业、更有控制力。

---

## 2. 为什么要做：解决 AI 设计输出 “千篇一律” 的问题
- 文章指出，大模型都学过很多相似的通用模板，所以如果没有额外引导，常会犯类似问题：
  - 爱用**Inter**字体
  - 爱用**紫色渐变**
  - 喜欢**卡片套卡片**
  - 喜欢在彩色背景上放**灰色文字**
- Impeccable 的作用就是对抗这种 “默认偏见”，方法包括：
  - 提供**扩展版设计 skill**
  - 加入**7 个领域参考文件**
  - 提供**17 个可操控命令**
  - 明确告诉 AI **哪些设计不要做**

---

## 3. 核心内容：7 个设计参考模块
Impeccable 把前端设计拆成 7 个关键领域，帮助 AI 更系统地理解设计：

- **typography（字体排版）**  
  包括字体系统、字体搭配、比例尺、OpenType。
- **color-and-contrast（颜色与对比）**  
  包括 OKLCH、带色中性色、深色模式、可访问性。
- **spatial-design（空间设计）**  
  包括间距系统、网格、视觉层级。
- **motion-design（动效设计）**  
  包括缓动曲线、错峰动画、减少动态效果。
- **interaction-design（交互设计）**  
  包括表单、焦点状态、加载模式。
- **responsive-design（响应式设计）**  
  包括移动优先、流式设计、容器查询。
- **ux-writing（UX 文案）**  
  包括按钮文案、报错信息、空状态提示。

---

## 4. 17 个命令：让 AI 按需审查、优化和润色
文章给出了**17 个命令**，可以针对不同设计任务精确操作。重点包括：

- **/teach-impeccable**：一次性初始化，收集设计上下文并保存配置
- **/audit**：检查技术质量，如无障碍、性能、响应式
- **/critique**：做 UX 设计评审，看层级、清晰度、情绪表达
- **/normalize**：统一到设计系统标准
- **/polish**：上线前最后润色
- **/distill**：去掉多余复杂性，保留本质
- **/clarify**：优化不清楚的 UX 文案
- **/optimize**：提升性能
- **/harden**：处理错误、国际化和边界情况
- **/animate**：加入有目的的动效
- **/colorize**：更策略性地使用颜色
- **/bolder**：让无聊设计更有冲击力
- **/quieter**：让太激进的设计更克制
- **/delight**：增加 “惊喜感”
- **/extract**：提炼成可复用组件
- **/adapt**：适配不同设备
- **/onboard**：设计引导流程

**例子：**
- `/audit`：查找界面问题
- `/normalize`：修复不统一样式
- `/polish`：最终清理细节
- `/distill`：删掉多余设计元素

部分命令还支持指定范围，比如：
- `/audit header`
- `/polish checkout-form`

---

## 5. 反模式规则：明确告诉 AI “不要这样设计”
这是文章很重要的一部分。Impeccable 不只是教 AI “该怎么做”，还强调 “不要怎么做”：

- 不要使用**过度滥用的字体**，如 Arial、Inter、系统默认字体
- 不要在**彩色背景上放灰色文字**
- 不要使用**纯黑或纯灰**，而是建议带一点色调
- 不要把所有内容都放进卡片，也不要**卡片里再套卡片**
- 不要使用**bounce /elastic**这类过时的弹跳缓动效果

这类规则很实用，因为很多 AI 设计问题正是来自这些 “常见但俗套” 的选择。

# Impeccable 最佳实践

## 1. 先做一次初始化
首次在项目里使用时，先执行：

- `/teach-impeccable`

目的：
- 让 AI 了解你的品牌、产品类型、用户、已有设计风格
- 避免后续每次都从 “通用模板审美” 开始

**建议提供的信息：**
- 品牌气质：专业 / 极简 / 年轻 / 高端
- 目标用户：C 端 / B 端 / 内部系统
- 参考产品：你喜欢和不喜欢的案例
- 技术约束：组件库、设计系统、是否要兼容深色模式

---

## 2. 不要一上来就`/polish`
很多人会直接要求 “美化一下”，这通常效果一般。  
**更好的顺序是：**

1. `/audit` —— 先找问题  
2. `/normalize` —— 统一设计系统  
3. `/distill` —— 去掉冗余  
4. `/polish` —— 最后润色

这个流程比直接 polish 更稳定。

---

## 3. 用 “小范围命令”，不要总是改全站
优先聚焦具体模块，而不是整页一起改。

例如：
- `/audit header`
- `/polish checkout-form`
- `/clarify empty-state`
- `/animate onboarding`

**好处：**
- 改动更可控
- 更容易回滚
- 不会把原本正常的区域一起改坏

---

## 4. 一次只追求一个目标
不要在一条命令里同时要求：
- 更高级
- 更活泼
- 更极简
- 更有品牌感
- 还要提升转化

这样容易让结果冲突。  
**最佳做法：单轮只解决一个核心问题。**

例如：
- 先`/distill`，减少复杂度
- 再`/colorize`，增加品牌识别
- 最后`/polish`，统一细节

---

## 5. 把它当 “设计评审器”，不只是 “美化器”
Impeccable 最强的地方，不只是生成样式，而是**指出问题**。

优先多用：
- `/audit`：查无障碍、性能、响应式问题
- `/critique`：看层级、清晰度、情绪表达
- `/clarify`：优化按钮、提示、报错文案
- `/harden`：补齐异常、边界状态、i18n

这比单纯 “做得更好看” 更有价值。

---

## 6. 先收敛，再增强
如果当前页面已经很乱，先用：

- `/normalize`
- `/distill`

等结构、样式、信息层级稳定后，再考虑：

- `/animate`
- `/colorize`
- `/delight`
- `/bolder`

**原则：**  
先解决秩序，再追求惊艳。

---

## 7. 明确约束，避免 AI 回到俗套设计
Impeccable 的价值之一是帮助你避开常见 AI 审美套路。  
在提示里最好主动补充约束，例如：

- 不要卡片套卡片
- 不要用过度流行的默认字体
- 不要灰字压在彩色背景上
- 不要纯黑纯灰
- 不要过时的弹跳动效

这样能进一步减少 “模板味”。

---

## 8. 动效只在有意义时使用
使用`/animate`时，不要只说 “加点动画”。  
最好说明动画的目的：

- 引导注意力
- 提示状态变化
- 改善加载体验
- 让 onboarding 更自然

**原则：**  
动效应该服务理解，而不是炫技。

---

## 9. 文案问题优先用`/clarify`
如果问题本质是 “用户看不懂”，优先不要改视觉，先改文案。

适合场景：
- 按钮不知道点了会发生什么
- 错误提示太技术化
- 空状态太冷淡
- 表单说明不明确

视觉不能替代清晰表达。

---

## 10. 发布前固定跑一遍 “四件套”
上线前建议固定执行：

- `/audit`
- `/harden`
- `/adapt`
- `/polish`

分别确保：
- 技术质量没问题
- 异常和边界情况完善
- 多设备体验正常
- 视觉细节收尾完成
