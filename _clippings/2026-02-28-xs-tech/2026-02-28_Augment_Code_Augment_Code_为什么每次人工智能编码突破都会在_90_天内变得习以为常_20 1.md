# 为什么每次人工智能编码突破都会在 90 天内变得习以为常

2023 年，自动补全功能简直神奇。它给出的三行正确建议会让你惊叹不已。但到了 2024 年中期，它一旦出错，你就会感到恼火。神奇之处已荡然无存。

聊天功能第一次能帮你解释代码库时，你简直惊呆了。六个月后，你却沮丧地发现它无法自动应用修复。于是智能编辑功能出现了，这真是太棒了。直到你意识到自己仍然需要监控每一次更改。之后，智能代理接管了工作，你感觉自己仿佛拥有了超能力，持续了一周。而现在，当智能代理在执行任务的过程中丢失上下文时，你却感到恼火。

每一次突破，在你还没完全适应之前，就成了你的新基准。一月份让你惊叹的事情，到了三月份就习以为常了。惊奇感消退，期望值不断攀升，下一个突破必须更加出色才能引起你的注意。

这就是享乐主义的恶性循环。在人工智能编程领域，它的运行速度前所未见。

WWDC 以前是一年一次。你会观看主题演讲，花几个月时间消化各种变化，然后发布一些使用新 API 的产品。之后，你还要等将近一年时间，才能迎来下一波浪潮。

在人工智能领域，我们每个月都会迎来相当于一次 WWDC 的变革。Sonnet 从 3.5 到 3.7 再到 Opus 4.5，短短不到 12 个月的时间。MCP 仅用了一个季度就发布并成为标准。在大多数团队完成规划周期之前，智能体就已经从实验性的新概念变成了默认的工作流程。

移动领域每年都有一次 WWDC。React 于 2013 年发布；Hooks 于 2019 年问世——六年时间足以消化一次范式转变。而云基础设施的发展速度却如同 re:Invent 大会一般：每年一次，发布大量公告，然后需要 11 个月的时间来筛选出真正重要的内容。

不是你反应慢。而是时代在以前所未有的速度变革。

过去需要十年才能完成的事情，现在一年就能完成。过去需要一年才能完成的事情，现在三个月就能完成。

## 为什么跑步机的速度会不断加快

人工智能辅助开发的每一个新时代都由两件事开启：

Model capability. What the AI can actually do.

Developer trust. What we're willing to let it do.

你肯定见过那些令人印象深刻的演示，但它们从未真正融入到任何人的实际工作流程中。这就是功能强大却缺乏信任。你也肯定体会过另一种情况：承诺的功能与实际使用时的效果之间存在差距。

当两者齐头并进时，时代才会转变。模型发布并不会立即改变人们的工作方式。功能会先出现。信任的建立需要更长时间。你需要亲眼看到它在你的代码库中运行，尤其是在某个周二下午，当你疲惫不堪，只想确保它不会让你产生幻觉的时候。

信任随后建立，一个新时代就此开启。

这就是循环往复的原因：每一代模型都会减少之前那些让你吃亏的错误。因此，信任建立得更快，采用率上升得更快，下一个基准线出现得更快。循环不断收紧。

不到三年时间，我们就从“逐行检查”转变为“审核 PR”。现在我们进入了多代理领域：多个代理并行工作，使用 Git 工作树进行隔离，规范作为协调层。

我们已经可以看到接下来的发展趋势：云端代理。它们由您的软件开发生命周期 (SDLC) 触发，而非由您手动提示。它们主动出击，会在您发现问题之前主动联系您。例如，当 PR 提交后，代理会运行分析；当错误激增时，代理会展开调查；当依赖项更新发布时，代理会在夜间进行兼容性测试。

## 终点线一直在移动

周二下午，当你疲惫不堪，只想让跑步机运转起来的时候，你根本不会记得它以前是什么样子。你只会注意到它仍然做不到的事情。这就是跑步机。你跑得越来越快，终点线却在不断后退。

如果你觉得自己永远跟不上进度，别担心，你并不孤单。我和一些从事这方面工作的人交流过，他们也有同样的感受。我认识的最优秀的从业者也并非完全掌握了所有方法。他们都在不断尝试，分享有效的经验，坦诚地承认无效的教训。这个行业的每个人都在公开、实时地重新学习他们的工作方式。

18 个月之内，如今批量接受代理 PR 的开发者，对于协调十个代理的感受，就会像现在对一行代码自动补全一样。这将成为最低标准，新的基准线。而之后的一切，我们再来讨论。

问题不在于未来是否会到来，而在于当未来到来时，你是否已经形成了相应的肌肉记忆，能够以那种速度工作。
