**Michael Truell**

# 人工智能软件开发的第三个时代

几年前我们开始开发 Cursor 时，大部分代码都是一次敲击一个键编写的。Tab 键自动补全改变了这一切，开启了人工智能辅助编码的第一个时代。

随后智能体出现，开发者开始转向通过同步的提示-响应循环来引导智能体。那是第二个时代。如今，第三个时代即将到来。它的特点是智能体能够独立处理更大规模的任务，运行时间更长，且所需的人工指导更少。

因此，Cursor 的主要功能不再是编写代码，而是帮助开发者构建软件生产工厂。这个工厂由大量的代理组成，开发者可以与这些代理作为队友进行交互：提供初始指导、配备独立工作所需的工具，并审查他们的工作成果。

Cursor 的许多同事已经开始采用这种工作方式。我们合并的 PR 中，超过三分之一是由运行在云端独立计算机上的代理创建的。我们认为，一年后，绝大多数的开发工作都将由这类代理完成。

# 

从 Tab 到代理商

Tab 非常擅长识别哪些低熵、重复性工作可以实现自动化。在近两年的时间里，它产生了显著的效益。

随后模型得到了改进。智能体能够掌握更多上下文信息，使用更多工具，并执行更长的操作序列。开发者的习惯也开始转变，这种转变在夏季缓慢发生，并在最近几个月迅速发展。

这种转变如此彻底，以至于如今许多光标用户根本不会使用 Tab 键。2025 年 3 月，Tab 键用户数量大约是代理用户的 2.5 倍。而现在情况正好相反：代理用户数量是 Tab 键用户的 2 倍，并且光标中代理的使用量也激增。

过去一年，Cursor 中的代理使用量增长了 15 倍以上。

但这种转变正在让位于更大的变革。Tab 时代持续了近两年。第二个时代，即大部分工作都由同步代理完成的时代，可能不会持续一年。

# 

云代理和工件

与 Tab 相比，同步代理的工作层级更高。它们处理需要上下文判断的任务，但仍然能让开发者随时了解每一步的进展。然而，这种实时交互方式，再加上同步代理会争用本地机器上的资源，意味着一次只能使用少量同步代理。

云代理消除了这两个限制。每个代理都在独立的虚拟机上运行，​​开发人员可以将任务交给代理，然后去做其他事情。代理会花费数小时完成任务，不断迭代和测试，直到对输出结果充满信心，并返回可快速查看的内容：日志、视频录制和实时预览，而不是差异对比。

这使得并行运行代理成为可能，因为工件和预览提供了足够的上下文信息，无需从头开始重建每个会话即可评估输出。人的角色也从指导每一行代码转变为定义问题和设定审查标准。

# 

Cursor 内部正在进行转变

在 Cursor，我们内部合并的 PR 中有 35% 现在是由在云虚拟机中自主运行的代理创建的。我们发现，采用这种新工作方式的开发人员具有以下三个特点：

1.  代理商几乎 100% 的代码都是自己编写的。
 
2.  他们花时间分析问题、审查代码/成果，并提供反馈。
 
3.  他们同时启动多个代理程序，而不是手把手地指导一个程序完成。
 

在软件开发领域，这种方法要成为标准做法，还有很多工作要做。在工业规模上，单个开发人员可以勉强解决的不稳定测试或损坏的环境，一旦出现问题，就会演变成中断所有代理运行的故障。更广泛地说，我们仍然需要确保代理能够尽可能高效地运行，并拥有所需的全部工具和上下文信息。
