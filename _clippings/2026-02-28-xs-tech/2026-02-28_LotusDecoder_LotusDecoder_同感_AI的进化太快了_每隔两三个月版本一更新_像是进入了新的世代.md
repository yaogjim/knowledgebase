# LotusDecoder 同感，AI的进化太快了，每隔两三个月版本一更新，像是进入了新的世代

**LotusDecoder**

同感，AI的进化太快了，每隔两三个月版本一更新，像是进入了新的世代。

翻译：

为什么每一次 AI 编程的突破在 90 天内就会让人习以为常

2023年时，自动补全（Autocomplete）简直是魔法。你会因为一个正确的三行代码建议而惊呼。到了2024年中期，当它出错时你就会感到恼火。曾经的魔法变成了如今的最低标准。 当对话功能（Chat）第一次向你解释你自己的代码库时，你感到非常震撼。六个月后，你会因为它不能自己去应用修复而感到沮丧。于是智能编辑（Smart edit）出现了，那真的不可思议。直到你意识到自己仍然需要像保姆一样盯着每一个更改。随后智能体（Agents）接管了，有一个星期的时间你感觉自己拥有了超能力。而现在，当智能体在任务中途丢失上下文时，你会感到十分烦躁。 在你还没完全适应之前，每一次突破都已经成为你新的基准线。一月份让你惊叹的东西，到了三月份就变成了理所当然。惊奇感消退，期望值不断攀升，下一个新事物必须足够惊艳才能引起你的注意。 这就是“享乐适应跑步机”（hedonic treadmill）。而在 AI 编程领域，它的运转速度是我们前所未见的。 过去，苹果开发者大会（WWDC）一年才一次。你看完主题演讲，花几个月时间消化这些变化，发布使用了新 API 的产品，然后几乎有一年的时间缓冲，直到下一波浪潮袭来。 在 AI 领域，我们每个月都在经历相当于一次 WWDC 的变化量。从 Sonnet 3.5 到 3.7 再到 Opus 4.5，只用了不到十二个月。MCP（模型上下文协议）在一个季度内就发布并成为了标准。大多数团队还没完成他们的计划周期，智能体就已经从实验性的新奇事物变成了默认的工作流。 移动开发曾经是一年一次 WWDC。React 在 2013 年问世；Hooks 在 2019 年才到来——人们有六年的时间来消化这一范式转变。云基础设施则以 AWS re:Invent 的节奏推进：一年一次，涌现大量重磅发布，然后用十一个月的时间去弄清楚哪些才是真正重要的。 并不是你太慢。而是时钟走得比以往任何一次技术变革都要快。 过去需要十年的事情现在只需要一年。过去需要一年的事情现在只需要一个季度。 为什么这台“跑步机”会不断加速 开启每一个 AI 辅助开发新时代的两个关键因素是： \* 模型能力（Model capability）。 即 AI 实际能做什么。 \* 开发者信任（Developer trust）。 即我们愿意让它做什么。 你见过那些令人印象深刻、但从未真正进入任何人实际工作流的演示。这就是有能力但缺乏信任。你也体会过另一面：承诺的效果与你坐下来实际使用时的效果之间的巨大落差。 当这两者对齐时，时代就会更迭。模型的发布并不会立刻改变人们的工作方式。能力总是率先出现，而建立信任则需要更长的时间。你需要在一个疲惫的周二下午，当你只希望这东西不要产生幻觉的时候，亲眼看到它在你的代码和你的仓库中发挥作用。 随后，信任跟上步伐。一个新时代就开始了。 以下是让这台跑步机产生复利效应的原因：每一代模型犯下的、曾经让你焦头烂额的错误都变得更少。因此信任建立得更快，采用速度加速，下一个基准线也来得更早。整个迭代周期正在缩紧。 在不到三年的时间里，我们从“我会检查每一行代码”变成了“我会审查一下 PR”。现在我们已经进入了多智能体（multi-agent）领域：多个智能体并行工作，使用 git worktrees 进行环境隔离，以规范（specs）作为协调层。 而且我们已经可以看到接下来正在成型的是什么。云端智能体。由你的 SDLC（软件开发生命周期）触发，而不是由你的提示词（prompts）触发。它们是主动的。当它们在你之前发现问题时，会主动联系你。一个 PR 合并了，智能体会运行分析。错误率飙升，智能体会开启调查。发布了依赖项更新，智能体会在连夜测试其兼容性。 终点线在不断后移 在一个疲惫的周二下午，当你只需要这个工具能正常工作时，你不会记得它以前是什么样子。你只会注意到它还有什么做不到。这就是那台跑步机。你跑得越来越快，但终点线一直在向后推移。 如果你觉得自己永远赶不上，你不是一个人。我和开发这些东西的人聊过，他们也有同感。我认识的最优秀的从业者也还没把这一切摸透。他们正在不断实验，分享有用的经验，承认行不通的教训。这个行业里的每一个人都在公开地、实时地重新学习该如何工作。 在十八个月内，今天大量一键接收智能体 PR 的开发者，在面对协调十个智能体时，感受将与他们现在用 Tab 键补全单行代码时的感受一样平淡。那将成为最低标准，成为新的基准线。而我们将转而谈论在那之后会出现的新事物。 问题不在于那个未来是否会到来。而在于当它到来时，你是否已经建立了以那种速度工作的肌肉记忆。
