Don't Build Agents, Build Skills Instead  
不要构建智能体，而要构建技能  
  
来自 Anthropic @barry\_zyj 和 @maheshmurag 在 @aiDotEngineer Code Summit 的专题演讲，探讨了 AI Agent 发展的下一个关键阶段：从单纯追求“Agent”的架构，转向赋予它们具体、可复用的“Skills”。  
  
核心痛点：高智商 vs. 专业经验

AI Agent 面临的一个主要矛盾：有智商，缺经验。

· 比喻： 他们用了一个很形象的比喻——“Mahesh（智商 300 的数学天才）” vs. “Barry（经验丰富的税务专家）”。

· 现状： 目前的大模型 Agent 就像那个数学天才，虽然极其聪明，具备从头推导复杂原理的能力，但如果你让它去报税，它可能因为缺乏具体的“税务代码”和“流程知识”而一筹莫展，或者效率低下。

· 需求： 在真实的工作场景中，我们往往更需要那个“税务专家”，即一个能够稳定执行特定领域流程、拥有程序性知识的角色，而不是每次都从第一性原理去重新思考的天才。  
  
解决方案：什么是“Skills”？

为了填补这一鸿沟，Anthropic 提出了 “Skills” 的概念。

· 定义： Skills 是将程序性知识打包成的最小单元，Agent 可以根据需要动态加载这些单元。

· 形式： 它非常轻量级。一个 Skill 可能只是一个文件夹，里面包含了一些脚本（作为工具）和核心的指令文件（通常是 Markdown 格式）。

· 特点：

· 可移植（Portable）： 可以在不同的 Agent 之间共享。

· 可组合（Composable）： 就像乐高积木一样，你可以通过组合不同的 Skills 来让一个通用的 Agent 瞬间具备跨领域的专业能力。

· 低门槛： 它的本质不是复杂的代码工程，而是对“如何做某事”的清晰描述和工具封装。  
  
愿景：从“构建 Agent”到“沉淀知识”

这次的演讲不仅仅是关于技术的，更是关于组织如何利用 AI 的战略思考：

· 企业知识库的进化： 未来的企业竞争壁垒，在于谁能构建一个不断进化的“技能库”。这些技能由企业内部的专家定义，并随着 Agent 的使用反馈不断优化。

· Agent 的自我进化： 演讲提出了一个令人兴奋的未来图景——Agent 不仅是技能的使用者，最终将成为技能的创造者。它们能从工作中总结经验，自己编写新的 Skills，从而实现自我进化。

· 统一的 Agent： 你不需要为每个任务都单独“训练”或“微调”一个新模型，而是维护一个通用的、强大的 Agent，通过“加载”不同的 Skills 瞬间切换角色（比如上一秒是文档分析师，下一秒是代码审查员）。  
  
总结

这个视频传递的最重要信息是：不要迷恋“复杂的 Agent 架构”，要把精力花在提炼和封装具体的“专业知识”上。

对于开发者和企业来说，这意味着应该开始思考：如何将你们团队内部的“隐性知识”转化为标准化的“Skills”，让 AI 真正成为懂业务的专家，而不仅仅是聪明的通用助手。
