# Yanhua 看完K神的推文，隐隐感觉未来可能的几个风口（仅代表个人观点）： 风口一：AI-

**Yanhua**

看完K神的推文，隐隐感觉未来可能的几个风口（仅代表个人观点）：

风口一：AI-Native API / CLI 基础设施 现在99%的产品还在维护给人看的HTML文档和点击式界面。

机会：帮各行业的传统服务快速接入 AI-native 接口。

谁先做好"让AI能直接用"的适配层，谁就是下一个 Twilio/Stripe。风口二：垂直领域的传感器数据开放 健康/医疗、金融、工业设备……大量数据被锁在私有系统里。

机会：做数据的"解放者"：标准化、开放这些数据，让AI可以调用。风口三：个人AI上下文管理 你的健康数据、消费记录、工作日志、偏好……分散在几十个App里。

机会：做统一的个人上下文层，成为AI的"长期记忆"。

这可能是下一个比操作系统更底层的基础设施。风口四：AI Skills / 工具库生态 就像 Karpathy 提到的"skill libraries"，AI需要调用各种预定义的能力。

机会：类似App Store，但卖的不是App，而是AI可以调用的技能包。MCP 协议现在就在做这件事。风口五：人机协作的新交互范式 Karpathy 说他还是发现了bug、需要介入修正。

机会：设计新的人机协作界面——不是让人完全甩手，而是找到人介入的最优节点。

一句话总结： 未来的软件不是你下载的东西，而是AI根据你的需求即兴演奏出来的一首曲子。风口在于：谁来提供乐器（传感器/API），谁来写乐谱（Skills），谁来记住你喜欢什么风格（上下文层）。
