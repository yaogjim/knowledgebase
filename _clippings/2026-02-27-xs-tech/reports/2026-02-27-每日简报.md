### 1. DualPath：打破 Agent LLM 推理的存储带宽瓶颈

**来源**: arXiv 论文 | **作者**: 北京大学、清华大学、DeepSeek-AI | **字数**: ~8000

#### 核心发现

这篇论文揭示了当前 AI Agent 系统面临的根本性瓶颈：**KV-Cache 存储 I/O 已成为限制多轮推理性能的关键因素**，而非计算能力。

**研究亮点**:
- 在主流的分层架构中，从外部存储加载 KV-Cache 会造成存储 NIC 带宽饱和
- DualPath 提出双路径 KV-Cache 加载机制：除了传统的"存储→预填充"路径，新增"存储→解码→预填充"路径
- 通过 RDMA 计算网络传输，避免网络拥塞
- 动态负载均衡调度器在预填充和解码引擎之间分配负载

**实际效果**:
- 离线推理吞吐量提升最高 **1.87 倍**
- 在线服务吞吐量平均提升 **1.96 倍**
- 不违反延迟 SLO 前提下实现性能突破

**为什么重要**: 这篇论文直接指向了当前 Agent 系统的核心痛点——随着上下文窗口增长和多轮对话普及，KV-Cache 的存储和传输成本正在成为系统设计的决定性约束。这与 AlexZ 提到的"KV Cache 前缀一致性"原则形成呼应。

### 2. OpenClaw 从中级到高级完整教程

**来源**: X/Twitter | **作者**: OneHopeA9 | **字数**: ~6000

#### 内容概览

这是目前最完整的 OpenClaw 配置和使用教程，涵盖从工作规范建立到高级功能应用的全流程。

**四大学习阶段**:

1. **工作规范建立** (30-60 分钟)
   - 创建 AGENTS.md 工作手册
   - 定义 session 启动流程
   - 设置记忆写入规范
   - 配置安全边界

2. **记忆系统优化** (60-120 分钟)
   - 启用 memoryFlush 防止信息丢失
   - 优化日志格式提升检索精度
   - 配置自动维护机制
   - 调整 embedding 模型

3. **高级功能应用** (120-240 分钟)
   - 部署子 Agent 实现任务分发
   - 创建 Cron 定时任务
   - 开发自定义 Skill
   - 配置多渠道接入

4. **性能调优** (1-2 天)
   - 调整模型参数
   - 优化 token 使用
   - 配置缓存策略
   - 监控系统性能

**关键洞察**: OpenClaw 采用分层记忆设计——短期记忆写入按日期追加的日志文件，长期记忆沉淀进核心 MEMORY.md 文件。这种设计的优势是透明可审计，用户可以直接查看和修改记忆内容。

### 4. 真正强的 Agent，最后都会长出一套分层记忆系统

**来源**: X/Twitter | **作者**: Ray Wang | **字数**: ~4500

#### 核心判断

"记忆不是 Agent 的附属模块，记忆就是 Agent 的基础设施。"这是本文的核心论点。

**五类主流方案**:

1. **OpenClaw 类 - 可解释记忆层**
   - 直接把记忆写进 Markdown 文件
   - 用户能看到、能检查、能修改
   - 优势：透明可调试
   - 问题：依赖主动写入，缺少自动更新机制

2. **QMD 类 - 混合检索后端**
   - 关键词全文检索 + 向量检索 + 本地重排序
   - 解决"能搜准也能搜广"的问题

3. **Viking/OpenViking - 上下文数据库路线**
   - 事件抽取、用户建模、长期画像
   - 把记忆提升为 Agent 的核心资产

4. **Letta/MemGPT - 自管理记忆路线**
   - 借鉴操作系统内存分层思想
   - Agent 自己决定哪些内容进入当前上下文

5. **Mem0 - 智能更新路线**
   - 解决"新信息来了以后，旧记忆怎么办"的问题
   - 新增、修改、合并、忽略、删除、归档的决策层

**认知科学启发**:

- 短期记忆和长期记忆必须分开
- 情景记忆（发生过什么）和语义记忆（总结出什么）是两回事
- 不会遗忘的记忆系统，最后通常也不会真正理解重要性

**未来方向**: 分层记忆架构——最底层保留原始事件和交互日志，中间层做摘要聚类，高层沉淀稳定规则和长期偏好。

### 5. Agent 设计的核心约束与原则

**来源**: X/Twitter | **作者**: AlexZ | **字数**: ~4000

#### 物理约束（不可违抗的现实）

**C1. 上下文窗口有限且昂贵**
- 128K token ≈ 一本 300 页的书
- 50 轮对话可能花$75
- 上下文是最稀缺的资源

**C2. KV Cache 前缀一旦改变，全部重算**
- 前缀匹配：$0.30/M
- 前缀不匹配：$3.00/M
- DualPath 论文证明：Agent 多轮推理中 KV-Cache 命中率≥95%
- 瓶颈不在算力，在"把缓存搬回来的 I/O"

**C3. 注意力在中间衰减**（Lost in the Middle）
- LLM 对 prompt 开头和末尾的 token 注意力最强
- 重要信息必须在开头或末尾

**C4. LLM 输出不可靠**
- 会循环、会幻觉、会忘记、会偏移
- 系统必须有独立于 LLM 的防护机制

**C5. 工具执行不可预测**
- bash 命令可能跑 0.1 秒或 10 分钟
- 任何工具调用都必须可取消、可超时、可截断

**C6. 信息有不同的半衰期**
- 决策：整个 session
- 错误教训：当前任务
- 文件内容：下次修改前
- 命令输出：几分钟
- 中间推理：当前轮次

#### 设计原则

**P1. KV Cache 前缀一致性** ← [C1, C2]
- 最高优先级约束
- system prompt 永远不变
- 信息只通过 tool_result 追加到末尾

**P2. Append-Only 上下文** ← [C1, C2, C3]
- 上下文只能追加，不能插入、不能重排

**P3. 按需加载一切** ← [C1, C3]
- System prompt 只放"索引"，完整内容等需要时才注入

**P4. 渐进降级** ← [C1, C6]
- 三阶段 Pruning：Soft Trim → Hard Clear → 分级压缩

**P5. 末尾复述** ← [C3, C4]
- 关键工作状态必须被复述到上下文末尾

**P6. 系统级不信任** ← [C4]
- 四层循环检测：Generic Repeat、Poll No Progress、Ping-Pong、Circuit Breaker

**P7. 可中断性** ← [C5]
- 三种中断粒度：Steering、Abort、Session Reset

**P8. 信息只转换，不消失** ← [C6]
- 被 pruning 的内容必须仍然可检索

**P9. 可观测性优先** ← [全部]
- 必须追踪的指标：prefix_stability_ratio、cache_hit_ratio 等

**P10. 文件系统即记忆** ← [C1, C3]
- Agent 通过文件读写管理工作状态，不需要专门的"记忆"抽象
