最近思考了一下宝玉老师提出的 应用开发范式

LLM + Agent SDK + Sandbox + git + Tools + Data。

我认为，这里变数最大的就是 Data。

大量企业的 Data 是 in House 的，零监督的清洗大概率噪声高到没法用，必须做一个很重的交付，就像 Palantir 一样。

@dotey

---

**IndenScale** @david0520782123 [2026-01-04](https://x.com/david0520782123/status/2007689586324238487)

即使成功交付，如果企业坚持 Self Host，那么网络效应和产品改进的飞轮也很难跑起来。在 模型第一方应用 + 通用 Agent 挤压下，没有低垂果实了。

除非可以实现，企业使用同一套本体论相互通信， Agent 应用可以对齐领域本体论，而非对齐某个企业的内部流程。

实现这些才能从集成外包走向产品公司。

---

**IndenScale** @david0520782123 [2026-01-04](https://x.com/david0520782123/status/2007690863582089236)

可能我们得等到企业内部成长出一批 AI 原生的业务专家，可以使用标准接口，给 Agent 提供 Ontology ，以及业务规则中的约束，每个 SOP 节点的交付模板，才能让agent在工作过程中，持续自我校验，完成数百上千的步骤。

在合并进入生产数据库前，还要执行一次对接生产数据库u的CI，确保没有数据冲突。
