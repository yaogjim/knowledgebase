# 苹果 M4 神经网络引擎内部结构（第一部分）：逆向工程 --- Inside the M4 Apple Neural Engine, Part 1: Reverse Engineering

我们如何绕过 CoreML 并直接与硬件通信 关于“我们”的说明： 在本系列文章中， “我们” 指的是 maderix （人类）和 Claude Opus 4.6 （Anthropic 公司出品）组成的合作团队。逆向工程、基准测试和训练代码均由双方协作开发——人类的直觉驱动探索，人工智能则负责数据推理和分析。我们认为这种人机协作模式是一种新颖且自然的系统研究方式：一方作为 架构师 ，凭借直觉进行设计；另一方则作为 工程师 ，负责编写代码和设计实验。 这一切始于一个简单的问题： 能否在苹果公司的神经网络引擎上训练模型？ 苹果 不想让你知道答案。他们不公开 ANE 的指令集架构（ISA），也不提供内部架构文档。他们甚至不提供直接编程的方法——所有操作都通过 CoreML ，这增加了多层抽象、优化和开销，使得几乎不可能理解硬件的实际运行机制。 所以我们进行了逆向工程。 在几天的时间里，我们绘制了从 CoreML 到 IOKit 内核驱动程序的整个软件堆栈，发现了如何在没有 CoreML 的情况下在 ANE 上编译和执行程序，破解了二进制格式，测量了真正的峰值性能（剧透：苹果的“38 TOPS”数字具有误导性），并最终在专为推理而设计的芯片上 训练了一个神经网络 。 这是三篇系列文章的第一部分。本文将介绍逆向工程——我们如何层层剥开 M4 神经网络引擎的本质，以及如何直接与之交互。 什么是神经网络引擎？ ANE 不是 GPU，也不是 CPU。它是一个 图执行引擎 ——一个固定功能的加速器，它接收一个编译好的神经网络图，并将其作为一个原子操作一次性执行。你不需要发出单独的乘加指令。你提交的是一个描述整个计算图的编译程序，硬件会从头到尾执行它。 苹果在 A11（2017 年）中首次引入了神经网络引擎，当时采用的是双核设计。此后每一代产品都对其进行了扩展： 我们正在研究的是 M4 的 ANE（代号 H16G ）。它有 16 个核心，队列深度为 127 个评估请求，独立的 DVFS（动态电压/频率调节），以及在空闲时将功耗降至 0 毫瓦的硬性功耗门控。 现有技术 我们并不是第一个对 ANE 内部运作进行探究的人。 hollance/neural-engine — CoreML 不会以 ONNX 或 protobuf 格式将神经网络发送到 ANE。它使用 MIL （机器学习中间语言）——一种类型化的 SSA（静态单赋值）表示，其形式如下： MIL 的可读性出乎意料地好。每个值都以精度和形状进行类型化。操作都命名清晰，并接受关键字参数。函数签名明确声明了具有显式维度的输入张量。 张量布局遵循 ANE 的原生 NCDHW + Interleave 格式： [Batch, Channels, Depth, Height, Width] 。对于 1024×1024 矩阵，这在 4D 中变为 [1, 1024, 1, 1024] 。 E5 二进制：编译格式 当 ANECompiler 处理 MIL 程序时，它会生成一个 E5 二进制文件 ——一个具有以下几个部分的 FlatBuffer 结构文件： 有趣的是：一个 1024×1024 的矩阵乘法运算编译后大小为 2688 字节 ，而一个 128×128 的矩阵乘法运算编译后大小也为 2680 字节 ，几乎完全相同。E5 二进制文件并非编码矩阵乘法算法本身，而是编码一个 参数化程序， 其行为在运行时由张量描述符控制。这种“微代码”更像是一种配置，而非传统的机器代码。 这意味着： ANE 硬件可能只有少量固定的计算原语（卷积、矩阵乘法、逐元素运算），这些原语由张量形状描述符参数化。E5 二进制文件描述的是要链接哪些原语以及如何连接它们，而不是计算本身。 记忆之路：圣杯 基于文件的编译方法虽然可行，但存在一个问题：它需要将 MIL 文本写入磁盘，创建目录结构，并让编译器指向该目录。对于训练模型而言——我们需要每隔几步就使用更新后的权重重新编译——这种文件系统往返操作是不可接受的。
