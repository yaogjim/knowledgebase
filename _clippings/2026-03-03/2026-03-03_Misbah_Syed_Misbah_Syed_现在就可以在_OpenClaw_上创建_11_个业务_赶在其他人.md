# 现在就可以在 OpenClaw 上创建 11 个业务（赶在其他人之前）

每一次重大平台变革都遵循着同样的模式。平台上线，人们试用，然后少数开发者意识到， 真正的利润并不在平台本身，而是在围绕它构建的一切。

iPhone App Store 于 2008 年推出。到 2023 年，移动应用经济规模已达 9350 亿美元。Docker 于 2013 年发布，并催生了 Kubernetes、云原生以及整个容器生态系统。AWS Lambda 开启了无服务器经济时代。GPT-3 则开启了人工智能应用层的新篇章。

现在，同样的事情再次发生。这次是 OpenClaw。

GitHub 上已有超过 24 万颗星标，超过 4 万个 fork。创始人 Peter Steinberger 刚刚被 OpenAI 聘用。该项目正在向开源基金会转型。其生态系统的发展速度之快，令人难以捉摸。

但大多数人忽略了一点：对于开发者来说，真正的机会不在于 OpenClaw 本身，而在于围绕它构建的一切。

不妨把 OpenClaw 看作是人工智能领域的 Linux 内核时刻。Linux 并非只催生了一家公司，它孕育了 Red Hat、Ubuntu、Docker、Kubernetes 以及价值数十亿美元的基础设施层。OpenClaw 正在为自主人工智能代理做着同样的事情。而且就在此刻，实时发生。

我花了数周时间研究代码库、分支、生态系统缺陷以及开发者社区的讨论（包括一篇尖锐的评论）。Y Combinator 讨论在以代理人为先的经济模式下），机遇地图远比大多数人意识到的要大得多。

这是完整的分析报告。把它收藏起来，方便以后查看。也可以转发给那个老是说“我应该用人工智能做点什么”的朋友。

让我们开始吧。

## 1\. 分叉经济：构建更好的版本

OpenClaw 的代码超过 43 万行，功能强大。但它也臃肿、复杂，而且（据思科人工智能安全团队称）存在严重的安全隐患。SecurityScorecard 发现，63% 的暴露实例配置错误。技能市场也曾出现恶意提交。OpenClaw 的一位维护者在 Discord 上警告说：“如果你连命令行都不会用，那么这个项目对你来说太危险了，无法安全使用。”

那不是问题，而是一个机会。

市场迫切需要专注且目标明确的替代方案。而叉子经济已经开始做出响应。

已发货产品

这个领域发展迅猛。Nanobot（仅用 4000 行 Python 代码，由香港大学开发）证明，只需 1%的代码就能实现 99%的功能。ZeroClaw 则用 Rust 重写了整个流程，硬件成本仅为 10 美元。NanoClaw 为安全敏感型部署增加了容器隔离功能。IronClaw 则面向生产团队，提供模块化的自动化流水线。

它们各自基于相同的建筑风格，开辟出不同的市场定位。

哪些方面仍然完全开放

有趣的地方来了。目前还没有人建造过：

- 针对特定行业的工具。HealthClaw 用于 HIPAA 合规性。LegalClaw 内置文档感知功能。FinClaw 提供审计跟踪，并确保从一开始就符合合规要求。
- 适用于教室的教育爪 。
- 最大限度保护隐私的爪子 ，完全在设备本地运行，采用本地模型，绝不向服务器发送数据。
- 企业级强化版本， 具备 SOC 2、RBAC 和团队管理功能。

每一种限制都会创造一个市场空白。每一个市场空白都是一个商机。

## 2\. 技能经济：经纪人应用程序

技能之于 OpenClaw，正如应用之于 iPhone。经纪人所需的每项能力都是一项可构建、可销售、可组合的技能。

OpenClaw 的 ClawHub 市场已经拥有数千个技能。它们都是纯 JavaScript 代码，并附带 manifest.json 文件。安装只需一条命令：\`openclaw skills install github:clawhub/browser-automation\`。AIsa Skills 已经在 ClawHub 上推出了统一的 API 支付层。OpenClaw Club 等第三方市场也支持此功能。openclawskills.online 能够独立进行策展、排名和审核技能。

但问题在于：质量。

思科测试了第三方技能，发现数据泄露和提示注入会在用户不知情的情况下发生 。KoiSecurity 的 Clawdex 扫描器有所帮助，但验证工作仍然主要依赖人工。

显而易见的解决方案： 一个自动化的技能安全管道。在每个技能提交到注册表之前，都对其进行安全检查。可以把它想象成针对代理功能的 npm 审计。如果你开发了这个功能并且它运行良好，那么所有 Claw 实现都需要它。

技能类别图

除了安全技能之外，人们实际需要掌握的技能清单非常庞大：

- 效率提升： 邮件分类、日历优化、CRM 自动记录、后续跟踪
- 开发：CI/CD 管理、代码审查自动化、基础设施监控
- 内容： 社交媒体日程安排、研究和撰写、SEO 监控
- 财务： 发票生成、费用分类、Stripe 集成
- 文档生成： 按需制作合同、报告和演示文稿
- 应用构建： 让代理商能够搭建和部署移动及 Web 应用的技能
- 行业特定领域： 房地产市场比较、医疗预约流程、法律文件审核、电子商务库存

那么，它的商业模式呢？它涵盖多个层面。免费增值模式提供高级功能。API 密集型技能采用按使用量计费。企业级许可提供符合合规要求的软件包。技能即服务 (SaaS) 并提供托管服务级别协议 (SLA)。

你可以围绕清单上的任何一个类别建立一家真正的公司 。

## 3\. 乐高积木：可组合代理模块

并非所有人都需要完整的代理套件。有些开发人员只需要可以集成到现有系统中的特定构建模块。

这就是其背后的全部论点爪子套装将 AI 代理框架视为乐高积木。每个组件（模型运行时、内存后端、工具、通道、队列、沙箱）都是可替换的，并实现了共享接口。ClawKit 包含 10 个组件，涵盖 10 个类别：11 个 LLM 运行时、20 个通道、11 个内存后端、22 个工具等等。

想从 OpenAI 切换到 Ollama？只需更改一个组件，无需更改整个代理。想用 Telegram 而不是命令行界面 (CLI)？操作方法相同。

```bash
  git clone https://github.com/misbahsy/ClawKit 
  cd ClawKit 
  npm install && npm run build 
  npx clawkit init my-claw --template minimal 
  cd my-claw && npm start
```

这样就得到了一个带有命令行界面、SQLite 内存和 shell/文件工具的可用代理。需要更多功能？运行 \`clawkit add tool-git tool-web-search\`。需要更少功能？运行 \`clawkit remove tool-web-search\`。

全栈预设配置了全部 17 种工具、混合内存与 RRF 融合、浏览器自动化、子代理生成等功能。最小预设配置则是一个仅需约 20 行配置文件的微型机器人。

对于想要更精简方案的开发者来说，ClawKit Lite 这是一个大约 1000 行代码的套件，包含三个可插拔接口：通道、提供商和技能。克隆它，选择你的通道（Telegram、WhatsApp），选择你的提供商（Claude Agent SDK、OpenAI Codex、树莓派），添加技能，然后运行。无需 Docker，也无需任何框架开销。它只是一个带有可插拔组件的消息总线。

为什么可组合性在这里至关重要： 它构建了依赖生态系统，相当于代理程序的 npm，从而确保了长期应用。每个模块都可以独立进行测试、审计和盈利。正是这种可组合性，使得生态系统摆脱了在 OpenClaw 的 43 万行代码和从零开始构建之间“非此即彼”的选择困境。

## 4\. 一键部署和托管服务

还记得那条关于 63% 已部署实例配置错误的统计数据吗？默认网关绑定到 0.0.0.0:18789，监听所有网络接口，包括公网。大多数用户启动实例后都不会更改这个设置。再加上跳过身份验证、未修补的 CVE 漏洞以及配置文件中明文的 API 密钥，这就造成了一个亟待解决的业务问题。

已发货产品

- DigitalOcean 提供一键部署功能，配备安全加固的镜像，起价为每月 12 美元。
- Hostinger 提供一键式 VPS 部署服务，每月仅需 4.49 美元起。
- OpenClawd 是一个托管平台，拥有预先加固的云环境。连接 WhatsApp 或 Telegram 只需不到十分钟。
- Clawable.ai 提供“为团队和企业定制部署”
- EasyClaw 在 Product Hunt 上定位为安装速度最快的产品。

哪些地方还开着？

- 移动优先部署， 您可以通过手机管理您的代理。
- 通过白标部署 ，代理机构可以为客户部署品牌代理和爪子。
- 使用一个控制面板管理数十个代理和爪子的多代理车队 。
- 欧盟、中东和印度的数据驻留区域云合规性 。
- 为本地优先用户预配置了树莓派和家用服务器镜像 。
- 具有自动补丁和零停机更新功能的自更新托管代理 。

“感兴趣的非开发者”和“会使用 Claw 的人”之间的差距仍然太大。整个生态系统需要一条真正意义上的无代码路径。可以把它想象成“Claw 版的 Vercel”。如果你能做到这一点，肯定会有客户排队等着你。

## 5\. 交叉爪便携性：标准玩法

这是一个至今无人解决的结构性问题。

为 OpenClaw 编写的技能在 Nanobot 中无法使用。NanoClaw 的 Claude Code 技能也无法迁移到 IronClaw。每个代码库都有其自身的技能格式和发现机制。

MCP 规范了工具，A2A 规范了代理之间的通信。但是更高层次的“技能”（它结合了指令、工具和上下文）概念却完全没有标准化。

一个技能如果只对一只爪子有效，那么它应该对任何一只爪子都有效。但事实并非如此。

机遇： 一种适用于所有 Claw 实现的通用技能格式规范。相当于代理技能的 OCI（开放容器倡议）规范。类似这样的东西。agentskills.io 它定义了一个标准清单、执行契约和权限模型，任何 Claw 都可以导入该模型。

我知道，我知道。基础设施标准听起来很枯燥。但一旦生态系统发展到一定规模，需要它的时候，它的价值就会达到数十亿美元。ClawKit 的组件注册表方法（每个组件都实现一个共享接口，而不管底层 LLM 或通道如何）是朝着这个方向迈出的具体一步。但跨 Claw 移植的全面实现仍有待探索。

如果你曾经了解过 OCI 在容器领域的应用，你就知道这是怎么回事了。

## 6\. 多智能体协调

大多数 Claw 系统将智能体视为与单个用户对话的单一实体。但现实世界的应用场景越来越需要能够协作的智能体 。例如，研究智能体收集数据，写作智能体撰写内容，编辑智能体润色稿件。所有智能体协同工作。

NanoClaw 通过 Agent SDK 支持“代理群”，OpenClaw 也具备基本的多代理路由功能。但是，目前还没有人能够实现优雅的多代理编排，并无缝地在多个 Claw 和多代理环境中共享状态和解决冲突。

协议领域发展日新月异。谷歌的 A2A 协议（现已并入 Linux 基金会）正逐渐成为代理间通信的标准。MCP 负责工具连接，A2A 负责协调。Twilio 近期推出了 A2H（代理到人）协议，用于切换场景。微软 Foundry 则将 A2A 作为一流的预览工具。

但是顶层的编排层呢？真正让一群智能体有效协同工作的那个层呢？目前还相当开放。

机遇： 一个轻量级的多智能体协调层，可在任何 Claw 平台上运行。并非又一个协议。这是一个实用的编排框架，能够处理智能体团队的共享状态、冲突解决、任务分解和进度跟踪。

这与文中提出的“群体智能”论点直接相关。Y Combinator 讨论 ：由大量更便宜、成本更低的模型协同工作来解决以前需要最昂贵的基础模型才能解决的问题的系统。

能够使集群高效运转的协调器本身就是一个独立的产品类别。而且目前还没有人拥有它。

## 7\. 代理原生基础设施

这是最不显眼的一类，但它也可能是规模最大的一类。

随着智能体从实验阶段过渡到能够采取实际行动的全天候系统，它们需要的基础设施并非当初为它们设计的。

代理人的沟通渠道

Twilio 已将自身定位为“人工智能代理经济的核心基础设施”。但轻量级的“代理专用 Twilio”仍有发展空间。例如，代理拥有并运营的专属电话号码、短信功能和电子邮件地址。目前已有专门用于代理电子邮件的 Agent Mail 服务。赋予代理独立通信身份的基础设施领域正蓄势待发。

金融和经济体系

谷歌的代理支付协议 (AP2) 和通用商务协议 (UCP) 正在为此奠定基础。Shopify 的 Agentic Storefronts 让 ChatGPT、Perplexity 和 Copilot 等人工智能代理能够发现商家。

但是，从使用“人工货币”的代理人向自主代理人经济（代理人之间进行交易）的过渡才刚刚开始。代理人之间交易的支付渠道、担保系统和计费基础设施都需要从零开始构建。

那是一家公司。

身份与责任

代理人并非法律实体，但他们代表人类行事，并做出具有实际后果的决策。“责任同步”（允许代理人作为经济主体行事，同时保持清晰的责任链的结构）的法律和技术框架仍是一个尚未解决的领域。

如果你既是律师又是程序员，这可能是你的机会。

代理优化文档和发现

这 Y Combinator 讨论这一点被明确指出：软件的上市策略正在从说服 Stack Overflow 上的用户转向说服终端上的智能体。“打造智能体想要的产品。”

开发者工具需要针对智能体进行设计。文档需要提供 .txt 和 .md 两种版本，并采用 LLM 解析结构。类似于“智能体版 Yelp”（智能体可以对服务提供反馈，帮助其他智能体做出更佳决策）的新型发现层亟待构建。

## 8\. 可观测性、测试和安全工具

凌晨 3 点，你的爪子突然做出奇怪的动作，你该如何找出原因 ？

会话日志确实存在，但目前还没有类似应用程序性能监控 (APM) 的工具来监控 Claw 系统。无法追踪工具调用，也没有仪表盘展示其运行机制。ZeroClaw 内置了一些可观测性特性，但整个生态系统仍然处于盲目摸索的状态。

以下是目前尚不存在的工具栈：

- 代理 APM。 追踪从消息到响应的完整推理链。工具调用延迟。令牌使用情况。决策质量指标。每次对话成本。基本上就是代理领域的 Datadog。
- 代理测试框架。 如何测试您的代理是否正确处理提示注入？解析模糊邮件时是否不会出现错误？API 宕机时是否能优雅降级？可以把它想象成代理行为测试框架，类似于 Playwright。
- 成本监控。 跟踪每个客服人员、每项技能、每次对话的 LLM API 支出。当客服人员开始循环消耗代币时发出警报。
- 大规模安全扫描。 思科发现恶意技能的安装率高达 26%。如果没有进行适当的扫描，每次安装技能都是一场赌博。自动化漏洞检测是基本要求。
- 合规工具。 审计跟踪、数据保留策略、访问控制。企业级层面目前尚不存在，但一旦大型企业认真部署代理， 就必须具备这一层面。

这是典型的“用镐和铲子”策略。当大家都在开发代理程序时，你则负责开发大家安全运行这些代理程序所需的工具。这些工具中的每一个都是独立的产品，并且目前都有实际的需求。

## 9\. 语音、多模态和离线

大多数代码库都专注于文本消息。OpenClaw 的 macOS 应用支持语音唤醒。PicoClaw 通过 Groq 为 Telegram 语音消息提供 Whisper 转录功能。但该生态系统尚未认真解决摄像头输入、屏幕共享或实时语音对话等问题。

随着模型变得多模态，智能体也需要是多模态的。

机遇： 一个可与任何 Claw 代码库的通道系统兼容的共享语音/视觉适配器层。语音输入和输出作为一个可组合的模块。摄像头和屏幕识别作为一个可插拔的技能。它是文本优先的代理框架与即将到来的多模态未来之间的桥梁。

另一方面：离线和本地优先的人工智能。

目前所有代码库都需要通过 API 访问云端 LLM 提供商（Ollama 和 vLLM 除外，它们使用本地模型）。真正意义上的本地优先操作，包括在消费级硬件上运行功能强大的本地模型，仍然是一个遥远的目标。PicoClaw 专注于边缘计算，ZeroClaw 仅支持 SQLite 内存，两者最为接近，但模型本身仍然是瓶颈所在。

另一个机遇： 与针对特定智能体任务而非一般对话进行优化的精简量化模型紧密集成。例如，一个无需联网即可在笔记本电脑上完全运行的智能体，能够处理日历管理、本地文件管理和个人知识管理。

隐私保护方面的应用场景真实存在，但尚未得到充分满足。谁能解决这个问题，今年就前途无量了。

## 10\. 专业服务和业务自动化

每个企业都想拥有竞争优势，但大多数企业却无法做到这一点。而这正是你企业面临的挑战。

提供安装和部署服务。 为企业定制 Claw 部署方案。安全加固。与 Salesforce、HubSpot、Shopify 和 QuickBooks 等现有工具集成。需要这项服务的企业并不在 GitHub 上。他们会搜索“企业 AI 助手”，但却一无所获。你需要找到他们。这正是我们正在做的事情。Clawable.ai。

定制代理开发。 为特定工作流程量身打造的智能爪。多代理架构。为细分行业开发定制技能。这是深厚的领域知识与技术执行的完美结合。

培训与教育。 面向企业的研讨会。OpenClaw 构建在线课程。面向进入代理经济领域的开发者的训练营。认证项目。“活力程序员”群体庞大且不断增长。他们需要结构化的学习路径，才能从兴趣走向高效。

全面实现业务自动化。 Y Combinator 讨论报告重点介绍了非技术出身的 CEO 们如何利用智能代理实现整个部门的自动化，而这些部门以前需要人工团队才能完成。这并非纸上谈兵，而是正在发生的现实。帮助企业部署这些自动化系统的服务提供商正在建立具有持久性的经常性收入来源。

持续管理。 代理监控和维护服务包。性能优化。安全监控和事件响应。托管服务层将一次性部署转变为按月合作。这才是关键所在。您需要的不是一次性费用，而是长期服务包。

## 11\. 爪形市场和代理经济

除了个人技能之外，还有一整个市场提供完整的爪形配置、模板和预构建的工作流程。

爪形模板。 针对特定角色预配置的爪形和代理。行政助理代理。销售拓展代表代理。客户支持代理。内容创作代理。每一款都是用户可以购买、部署并立即使用的产品。

工作流市场。 预构建的自动化流程。“线索到达、资格审查、安排演示、跟进。” 企业无需从零开始构建，即可购买并部署完整的工作流程。

代理间服务。 这是更宏大的论点。不仅是代理服务于人类，代理也为其他代理提供服务 。例如，其他代理可以雇佣的研究代理；其他代理可以委托处理的支付代理；以及审查其他代理输出的合规性检查代理。 Y Combinator 讨论特别强调了经纪人交流信息、分享技巧和协作的平台。经纪人社交网络是一种新型的基础设施类别。

白标代理商市场。 企业向其客户销售配置好的代理商。代理商电商领域的 Shopify。

评分和信誉系统。 技能和经纪人的信任度评分。在一个增长速度远超任何人手动管理能力的市场中，质量信号至关重要。

## 这扇窗户有何不同之处

OpenClaw 的这次变革与以往的平台变革有几点不同。

开源设计， 没有把关人。OpenClaw 正在转型为基金会。其协议（MCP、A2A、UCP）是开放标准，由中立机构管理。任何人都可以进行构建。

即时通讯优先。 代理程序存在于人们常用的通讯平台，例如 WhatsApp、Telegram、Slack、Discord 和 Signal。无需安装新应用，也无需学习新界面。

行动导向。 这些客服人员不只是聊天。他们还会预订机票、管理邮件、部署代码、处理付款，并与其他客服人员协调工作。对话与执行之间的差距正在迅速缩小。

协议栈正在快速成熟。MCP 用于工具。A2A 用于代理协调。UCP 和 AP2 用于商业。A2H 用于人工交接。代理互操作性的基础标准正在逐步建立。

企业级市场尚未完全成熟， B2B 机遇也远未开发，大多数企业仍在评估阶段。那些现在就构建合规、可审计、可管理的代理基础设施的公司 ，将在企业级市场浪潮到来时占据主导地位。

这个生态系统诞生还不到三个月。市场上的大多数人还在摸索 OpenClaw 究竟是什么。而且，上述每个类别都可能出现多个赢家。

## 好吧，那么究竟该从哪里开始呢？

实话实说，你不需要在第一天就培养出“代理技能的全面性”。你需要做的就是选定一个方向，然后交付一些成果。

1.  选择你的层级。 你是要在分支层、技能层、基础设施层还是服务层进行建设？每个层级都有不同的资金需求、时间安排和竞争格局。
2.  找到痛点。 安全性、简易性和部署是目前最大的三个痛点。任何能够减少这些方面摩擦的产品都会立即获得市场需求。
3.  从小处着手，快速交付。先专注于一项技能，一个模块，一个部署服务，服务于一个垂直行业。生态系统更青睐那些积极交付的实干家，而不是只会等待的规划者。
4.  构建产品时要注重可组合性。 最终的赢家不会是单一的整体式产品，而是可以与各种组件无缝集成的模块。让你的产品能够兼容任何接口、任何协议、任何渠道。
5.  着眼于生态系统，而非产品。 平台和市场将创造最大价值。单个工具固然重要，但协调层才是真正发挥作用的关键所在。

## 底线

OpenClaw 不仅仅是一个开源项目，它更是一个全新经济体系——代理经济——的基础层。而对于移动应用来说，我们现在所处的阶段相当于 2009 年 1 月。App Store 已经上线，首批应用也开始获得关注，但 99% 的机会尚未被发掘。

问题不在于这个生态系统是否会发展壮大，而在于你是会参与建设，还是会在一旁看着别人建设。
