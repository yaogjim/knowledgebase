# LangSmith Agent Builder 现已推出公测版

**视频链接：** https://www.youtube.com/watch?v=PqS3k_S_k8U

今天我们非常激动地宣布，LangSmith Agent Builder（LangSmith Agent 构建器）现已进入公开测试阶段（Public Beta）。

LangSmith Agent Builder 是一种构建无代码 Agent（智能体）的全新方式。它不是一个工作流构建器，而是一个真正的 Agent 构建器。一切都由 Agent 自身驱动——这是一个配备了非常详细的提示词（Prompt）、一系列工具，甚至一些子 Agent 的 Agent。

我们试图让构建和维护 Agent 变得尽可能简单。我们打造了一种体验，让你能够通过聊天来创建 Agent，并且在这个过程中引入了“记忆”的概念，这样它们就能在你与其互动时自然地记住各种事物。

### Agent 的三大主要应用场景

在过去的一个月里，我们看到用户针对数百种不同的用例创建了数千个 Agent。其中已经涌现出三大主要类别：

1.  **深度调研 (Deep Research)：** 深度调研是一项本质上非常需要代理能力（Agentic）的任务，需要大量的规划、深入挖掘细节以及总结归纳。因此，我们要看到围绕销售、市场营销和招聘等场景出现了各种用例。
2.  **自动化触发器 (Triggers/Automations)：** 我们引入了“触发器”概念，即当某个事件发生时触发 Agent。我们看到了从产品、技术支持到开发者教育等各种自动化场景的出现。我们在内部也大量使用这些功能。
3.  **生产力任务 (Productivity Tasks)：** 当然，还有经典的生产力任务，例如围绕 Email、Slack 以及维护个人日历的所有事务，这些都是该 Agent 能带来的巨大解锁。

### 公测版的新功能

你今天就可以在 langchain.com 免费试用 Agent Builder。作为公测发布的一部分，我们还增加了一些新功能：

*   **通过 MCP 服务器引入自有工具 (Bring Your Own Tools)：** 支持 Model Context Protocol (MCP)。
*   **工作区 Agent (Workspace Agents)：** 支持与团队共享和自定义 Agent。
*   **多模型支持 (Multi-model Support)：** 你可以为你的任务选择最合适的模型。

### 演示：构建一个 LinkedIn 招聘 Agent

让我们深入了解一个具体的例子。

首先，在 LangChain 的工作区中，我们可以看到由不同团队成员创建的各种工作区 Agent。点击“我的 Agent”，可以看到我自己用于处理个人任务的 Agent。

现在，我想通过创建一个 Agent 的全过程来演示。我想创建一个 LinkedIn 招聘专员，用于为 LangChain 正在招聘的各种职位寻找候选人。

**1. 初始对话与需求明确**
我在对话框中输入：“创建一个 LinkedIn 招聘专员”。
仅仅这两个词显然不足以创建一个可靠的 Agent。因此，系统会自动进行调研，查看我们有哪些可用工具，然后向我提出一系列后续问题，以确保能创建正确的设置。

它问我主要目的是什么（基于特定标准搜索候选人），是否需要定期运行（手动触发），以及需要提取哪些信息（姓名、详细资料、LinkedIn 链接等）。我一一回答了这些问题。

**2. 生成 Agent 配置**
提交回答后，系统开始按部就班地创建 Agent。我们可以看到它首先勾勒出 Agent 的轮廓，然后添加工具——这里我将使用 Exa 的 LinkedIn 搜索工具（Exa LinkedIn Search），接着它开始编写系统提示词（System Prompt）。

**3. 测试与调试模式**
Agent 创建完成后，我进入了一个拥有详细提示词和工具配置的界面。这里有一个测试聊天模式，我可以在此运行 Agent。更重要的是，我可以使用“调试模式”（Debug Mode），这意味着每当 Agent 试图调用工具时，它会暂停并等待我的批准。

这非常有用，因为我可以借此纠正它的行为，而它会利用“记忆”功能来更新自己的操作逻辑。

**4. 修正 Agent 行为**
我尝试运行一个搜索：“寻找已部署工程师（Deployed Engineers）”。
Agent 想要直接调用 Exa LinkedIn 搜索工具。但这并不是我想要的。
我告诉它：“你应该先问后续问题，以便更好地理解职位描述（JD），请记住这一点。”

**5. 记忆更新与自我修正**
Agent 接收到反馈后，首先做的是更新它的记忆。它读取自己的系统提示词，根据我的指令对文件进行了编辑。我们可以看到旧的指令和新的指令之间的对比——新指令中增加了“首先询问澄清问题”的要求。

批准更新后，系统提示词被修改。如果我现在刷新页面，或者开始一个新的对话线程，会发现 Agent 记住了这个要求。当我再次要求它寻找工程师时，它不再直接搜索，而是开始询问一系列关于职位类型、经验要求、技术栈等具体的资格问题。

### 实际案例：Go-To-Market 招聘专员

这就是我在过去一个月里实际使用的真实 LinkedIn 候选人搜索工具。

我们可以看到正在招聘“Go-To-Market 招聘专员”的职位。当我与 Agent 互动时：
1.  它首先询问一系列澄清问题。
2.  我提供答案后，它会去检查是否已存在该职位的搜索标准文件。因为我告诉过它要记住所有职位的 JD。
3.  如果没有现成文件，它会创建一个新文件，以便未来复用。
4.  接着，它会执行我设定的“初始校准搜索”（Initial Calibration Search），即只搜索 3-5 名候选人让我过目。
5.  我查看结果并给出反馈（例如：这个不错，那个不行，或者一定要在旧金山等硬性条件）。
6.  Agent 甚至可以启动一个“子 Agent”来处理特定的反馈循环。
7.  根据我的反馈，它会调整搜索词，再次运行搜索，直到我确认候选人方向正确。

**最终结果输出**
当我们完成校准，告诉它“这些看起来不错，给我找 50 个候选人”时，它会执行更全面的搜索。最后，它不仅仅是把结果以此列出，而是将它们保存到一个文件中。

这是 Agent Builder 的一大优势，Agent 可以访问文件系统。在这个案例中，它将找到的 50 名候选人保存为一个文件，我可以下载、分享或复制这个文件。
