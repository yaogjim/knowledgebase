# DEC. 15, 2025

DEC. 15, 2025

![Train a GPT2 model with JAX on TPU for free](https://storage.googleapis.com/gweb-developer-goog-blog-assets/images/train-gpt2-model-with-jax-on-tpu-banner.original.png)

生成式人工智能在生成文本、图像和代码方面表现卓越。现在，是时候让它用于生成与上下文相关的界面了。今天，我们正式发布 A2UI 项目，以便我们能与他人合作，共同探索这一早期阶段的形式和实现。A2UI 旨在解决代理在生成式或基于模板的用户界面响应中面临的互操作性、跨平台等特定挑战。A2UI 允许代理生成最适合与代理当前对话的界面，并将其发送到前端应用。我们已为部分产品开发了 A2UI，现在希望与社区携手，帮助完善 A2UI 规范，增加更多传输方式、客户端渲染器及集成功能。

A2UI 是一个开源项目，它包含一种经过优化的格式，专门用于表示可更新的代理生成型用户界面，以及一组初始渲染器。该项目允许代理生成或填充丰富的用户界面，这些界面可在不同宿主应用中展示，并由 Lit、Angular 或 Flutter 等多种 UI 框架渲染（更多框架将陆续支持）。渲染器支持一组通用组件和/或客户端声明的自定义组件，这些组件会被组合成布局。客户端负责渲染，并能将其无缝集成到自身品牌化的用户体验中。编排代理和远程 A2A 子代理均可生成用户界面布局，这些布局以安全消息的形式传递，而非可执行代码。

## 问题：智能代理需与用户界面交互

设想一个帮助你预订餐厅座位的智能助手。纯文字交互可能会出现一种不流畅的反复交流：

用户：（正在输入）“预订一张两人桌。”

Agent: "好的，是哪天？"

用户：（正在输入）“明天。”

**Agent:** "What time?"

用户：(正在输入) “可能 7p”

Agent：“那个时间我们没有可预订的时段了，还有其他时间吗？”

你什么时候订的？

"Agent: "我们在 5:00、5:30、6:00、8:30、9:00、9:30 和 10:00 有空，这些时间你方便吗？”"

这可能会很慢且效率不高。更好的体验应该是让代理能够快速生成或使用一个简单表单，其中包含日期选择器、时间选择器和提交按钮。借助 A2UI，LLMs 可以从一系列小部件中构建定制化界面，为当前的具体任务提供一个图形化、美观且易用的界面。

## 挑战：跨信任边界的渲染

我们正进入多智能体网格时代。谷歌的智能体正在与思科、IBM、SAP 和 Salesforce 的智能体沟通，以解决复杂任务。这就是我们共同创建智能体间（A2A）协议并捐赠给 Linux 基金会的原因：确保智能体即使在不共享内存、工具或上下文的情况下也能协作。

然而，这种去中心化引发了用户界面方面的问题。

如果你的代理位于应用程序内部，它可以直接操作视图层（例如 DOM）。但在多代理环境中，执行任务的代理通常是远程的——在后台运行、部署在不同的服务器上，或者由不同的组织所有。它无法直接接触你的用户界面，必须发送消息。

从历史上看，从远程不可信来源渲染 UI 意味着发送 HTML 或 JavaScript 并在 iframe 中进行沙箱处理。这种方法资源消耗大，视觉上可能不连贯（很少能与应用的原生样式相匹配），并且在安全边界方面引入了复杂性。

我们需要一种方式来传递既像数据般安全，又像代码般富有表现力的 UI。

## 解决方案：UI 规范是一系列消息

A2UI 提供了一种标准格式，该格式既可以即时生成结构化输出，也可以用作模板并填充数据。生成此响应的代理可能是远程的 A2A 代理，也可能是用户正在交互的编排器。JSON 负载可通过 A2A、AG UI 以及其他潜在的传输方式发送至客户端。客户端应用程序使用自身的原生 UI 组件进行渲染。这意味着客户端保留对样式和安全性的完全控制权，从而确保代理的输出始终给人以原生应用的感觉。

## 核心理念：安全、可更新与解耦

我们以几个关键原则为核心设计了 A2UI：

- 安全第一：运行由 LLM 生成的任意代码可能带来重大安全风险。A2UI 是一种声明式数据格式，而非可执行代码。您的客户端应用程序维护一个“目录”，其中包含受信任且预先批准的 UI 组件（例如 `Card` 、 `Button` 、 `TextField` ），代理只能请求渲染该目录中的组件。这有助于您降低 UI 注入和其他漏洞的风险。
- 对 LLM 友好且支持增量更新：用户界面以带有 ID 引用的组件平面列表形式呈现，这使得 LLMs 能够轻松逐步生成，从而实现渐进式渲染和响应式用户体验。代理可根据新的用户请求，在对话过程中高效地对用户界面进行增量更新。
- 与框架无关且可移植：A2UI 将 UI 结构与 UI 实现分离开来。代理会发送组件树及其关联数据模型的描述。您的客户端应用负责将这些抽象描述映射到其原生组件——无论是 Web 组件、Flutter 组件、React 组件、SwiftUI 视图，还是其他任何形式。代理发出的相同 A2UI JSON 负载可以在多个基于不同框架构建的不同客户端上进行渲染。

## 探索代理驱动的 UI 生态系统

代理驱动的用户界面领域正快速发展，优秀的工具不断涌现以解决技术栈中的不同部分。我们不将 A2UI 视为这些框架的替代品，而是将其定位为一种专门的协议，旨在解决互操作、跨平台、生成式或基于模板的响应这一特定问题。

为了帮助您选择合适的工具或工具组合，以下是我们梳理这一领域的方式：

**1\. 构建“宿主”应用的用户界面**

如果你正在构建一个全栈应用（即用户交互的“宿主”UI），除了构建实际的 UI 之外，你还可以使用一个框架（例如 AG UI、Vercel AI SDK，以及适用于 Flutter 且已在其内部使用 A2UI 的 GenUI SDK）来处理这些“管道”：状态同步、聊天记录和输入处理。

- A2UI 的适用场景：它具有互补性。如果通过 AG UI 连接宿主应用，宿主应用可以将 A2UI 用作渲染来自宿主代理以及第三方或远程代理的响应的数据格式。这让你两全其美：宿主应用功能丰富且有状态，能够安全地渲染来自其无法控制的外部代理的内容。
- A2UI with A2A：你可以直接通过 A2A 发送到客户端前端。
- A2UI 与 AG UI：AG UI 提供脚手架，可轻松构建和部署支持 A2UI 的应用。
- 采用 REST 和其他传输方式的 A2UI 是可行的，但尚未推出。

**2\. 用户界面作为“资源”（MCP 应用）**

模型上下文协议（MCP）最近推出了 MCP 应用，这是一项整合了 MCP-UI 和 OpenAI 工作成果的新标准，以支持服务器提供交互式界面。这种方法将用户界面视为一种资源（通过 `ui:// URI` 访问），工具可返回该资源，通常会在沙箱化的 `iframe` 中渲染预构建的 HTML 内容，以确保隔离和安全性。

A2UI 的独特之处在于，它采用‘原生优先’的方法，这与 MCP 应用的资源获取模式截然不同。A2UI 代理并非获取不透明的有效载荷并在沙箱中展示，而是直接发送原生组件的蓝图。这让 UI 能够完美继承宿主应用的样式和无障碍功能。在多代理系统中，编排代理可轻松理解子代理发来的轻量级 A2UI 消息内容，进而实现代理间更流畅的协作。

**3\. 平台特定生态系统（OpenAI ChatKit）**

像 ChatKit 这样的工具为在 OpenAI 生态系统内专门部署代理提供了高度集成且优化的体验。

A2UI 的独特之处在于：它专为两类开发者设计。一类是构建自己的代理型界面（适用于 Web、Flutter 和原生移动平台）；另一类是针对企业网格（如 A2A），在这类场景中，代理需要在信任边界之间进行通信。A2UI 以牺牲代理为代价，赋予客户端对样式设置的更多控制权，从而与宿主客户端应用实现更高的视觉一致性。

从项目启动之初，A2UI 就与谷歌内外的多个团队合作构建，以解决实际问题。我们很高兴在重要合作伙伴的支持下推进构建工作。

**AG UI 与 CopilotKit：一个强大的组合**

> 代理用户交互协议 (AG-UI) 连接基于代理的后端与基于代理的前端。它为开发者提供了构建丰富全栈代理应用的实用构建模块。AG-UI 全面支持 A2UI 规范，以实现由代理动态生成的丰富声明式生成式界面。AG-UI 还与 A2A 协议实现了完整的握手机制，以实现与任何 A2A 系统的无缝全功能集成。我们很高兴能够提供 AG-UI 与 A2UI 之间的零日兼容性。 — Atai Barkai，CopilotKit 和 AG UI 的创始人

**Opal：驱动实验性 AI 迷你应用**

Opal 允许数十万用户使用自然语言构建、编辑和分享 AI 小程序。谷歌的 Opal 团队一直是 A2UI 的核心贡献者。除了协助开发 A2UI 之外，该团队还使用它进行快速原型开发，并将其集成到核心应用构建流程中。Opal 中的 A2UI 将使任何人能够构建针对每个使用场景、具有动态生成式定制用户界面的 AI 小程序。未来几周内，您将能够在 Opal 中看到并体验 A2UI 的实际运行。

> A2UI 是我们工作的基础。它使我们能够灵活地让 AI 以新颖的方式驱动用户体验，而不必受固定前端的束缚。它的声明式特性和对安全性的重视，让我们能够快速且安全地开展实验。" —— Dimitri Glazkov，Opal 团队高级工程师

**Gemini 企业版：企业代理的自定义用户界面**

Gemini Enterprise 使企业能够构建强大的、定制化的 AI 代理。A2UI 正在被集成，以便这些企业代理能在宿主应用中渲染丰富的、交互式的用户界面。

> 我们的客户不仅需要他们的智能代理回答问题，更需要这些代理引导员工完成复杂的工作流程。A2UI 将使在 Gemini Enterprise 平台上开发的开发者能够让其代理生成动态、定制化的用户界面，以满足从数据录入表单到审批仪表板等各类任务的需求，从而极大地加速工作流程自动化。—— Fred Jabbour，Gemini Enterprise 产品经理

**Flutter：跨平台生成式 UI 的应用体验**

Flutter 及其 GenUI SDK 可帮助您借助 Gemini（或其他 LLMs）生成动态、个性化的用户界面，从而显著提升生成式人工智能（GenAI）和基于代理的用户体验的可用性与满意度。这些生成式用户界面遵循您既定的品牌指南，并采用您自有品牌的小部件库。GenUI SDK 将 A2UI 用作远程服务器端代理与应用之间的 UI 声明格式。

> 我们的开发者选择 Flutter，因为它能让他们快速打造富有表现力、品牌鲜明的自定义设计系统，且这些系统在所有平台上都表现出色。A2UI 非常适合 Flutter 的 GenUI SDK，因为它确保每个用户在所有平台上都能获得高质量的原生体验。

**AI 驱动的 Google：代理式用户界面标准化**

随着谷歌在全公司范围内推进人工智能的应用，A2UI 为团队提供了一种标准化方式，让 AI 代理能够交换用户界面（而非仅交换文本）。这种互操作性支持代理在任何前端进行渲染，支持每个界面包含多个代理或每个代理对应多个界面的工作流程，并使内部开发的代理能够轻松对外暴露，例如在 Gemini Enterprise 中。

> 就像 A2A 允许任何代理跨平台通信一样，A2UI 标准化了用户界面层，并通过编排器支持远程代理用例。这对内部团队而言极为强大，使他们能够快速开发代理——在这些代理中，丰富的用户界面已是常态而非例外。随着 Google 进一步深入生成式用户界面领域，A2UI 为可在任何客户端渲染的服务端驱动界面提供了理想平台。

## 入门：试用 A2UI

理解 A2UI 的最佳方式是看它实际运作。

- 首先访问 a2ui.org，阅读快速入门指南和文档。
- 接下来，进入 samples 文件夹，尝试一个客户端界面和一些后台示例代理，比如餐厅查找器。

如何启动餐厅查找器：

```shell
git clone https://github.com/google/A2UI.git
export GEMINI_API_KEY="your_gemini_api_key"

# Run the restaurant finder A2A agent
cd A2UI/samples/agent/adk/restaurant_finder
uv run .

# Run the lit client that uses the A2UI lit renderer library
cd A2UI/samples/client/lit/shell
npm install
npm run dev
```
