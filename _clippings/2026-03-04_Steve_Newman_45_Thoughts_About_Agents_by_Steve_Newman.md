# 45 Thoughts About Agents - by Steve Newman

AI 栈中演进最快且可能产生最大影响的那一层 关于我们在这一演进过程中确切处于哪个阶段，存在诸多争论 我有史以来最受欢迎的帖子之一是 35 个关于 AGI 的思考以及 1 个关于 GPT-5 的思考 ，这是一堆关于 AGI 发展路径的思考（并附带一个对 GPT-5 的讽刺性评论）。 这里是一组全新的思考，这次主题是 AI 代理。 我很难抽出时间写这个：我深陷于 使用 代理中，以至于很难抽出时间写 关于 代理的内容。这不是一个孤立的现象；很多人在推特上发消息说，他们正利用每一分钟沉迷于凭感觉编码。 这尤其由当前 AI 编码代理惊人的生产力所驱动， 尤其是在以发挥其优势的方式使用时 。我正在使用 Claude Code 为自己个人打造一套极其宏伟的生产力工具。单个子项目就涉及与 Gmail、Slack、WhatsApp、Twitter、Signal、短信、Substack、Pocket Casts、Notion、Google Drive、Google 联系人、Google 日历等的深度集成。就在去年，我甚至想都不敢想这样的项目，更不用说作为副业了。借助如今的工具，我在一个周末内就完成了大部分集成工作。AI 模型为应用提供了利用所有这些数据所需的智能，而编码代理则处理繁琐的集成工作。 作为一名高产的程序员，我工作了数十年，2023 年初突然停止了编码工作，这让我在编程上手生了不少。这种生疏感丝毫没有成为阻碍。事实上，我怀疑这或许反而有帮助——我原本需要摒弃的习惯已经淡化了，而且我很容易就养成了让 AI 编写所有代码的习惯。我仍然在用我的高级设计经验来指导 AI 代理；有趣的是，这些技能一点也不生疏。 我很好奇，底层编码技术与高级设计技能之间，究竟是什么原因使得后者更容易保留，以及这对哪些人类技能将保持相关性有什么启示。 似乎我的经验并不独特——显然，很多原本不再自己编写代码的工程师现在又重新投身其中了 这是一个更广泛现象的例子： AI agents 将会改变工作的本质 。一些工作会变得更高效，一些会消失，一些新工作会出现。一些工作会变得更有趣，因为 AI 会自动化处理令人讨厌的部分；一些工作会变得更有压力，因为 AI 会自动化处理轻松或有回报的部分。在这篇文章中，我不会探讨工作和劳动者整体上会受到何种影响的问题。但我确实想强调，事情会在很多方面发生变化，而且往往难以预测。 我能够重新投入编码，因为 Claude Code 已经变得足够强大，我无需编辑，甚至无需查看实际代码就能高效工作。我的印象是，在 11 月 Opus 4.5 发布之前情况并非如此。 阈值效应是 AI 影响的巨大不可预测性来源 对 AI 的影响。 为什么代理如此重要 突然，所有的 AI 新闻似乎都在谈论代理。OpenClaw 引起了轰动 因为它是一个能够自主行动的 AI 代理。在最近的“SaaS 末日”中，软件即服务（SaaS）公司的市值下跌超过一万亿美元，在编码代理将使大众市场软件过时的担忧推动下 编码代理将使大众市场软件过时 。当人们谈论他们从最新模型（如 Opus 4.6 和 GPT-5.3-Codex）中获得的成果时，他们指的是用这些模型来驱动类似 Claude Code 的代理。 人工智能代理之所以产生如此大的影响，其中一个原因是 它们是 AI 架构中进化最快的那一层 。基础模型是一个巨大的单体——一个包含数万亿神秘数值权重的单一数据文件。更新它，即使是像 Opus 4.5 → 4.6 这样的增量发布，也是一个大工程。相比之下，代理是传统软件，可以进行增量更新——在这里调整一个提示词，在那里添加一个新的集成。模型发布间隔数月；Claude Code 有时会有 一天内多次发布 。代理的‘发布→获取反馈→改进→发布’周期可以非常快。 实际上，我之前关于变革最快发生在哪里的说法是错误的： 有些用户改变自身行为的速度甚至比智能代理还要快 。我的 Twitter 时间线上充满了人们发现的各种疯狂但富有成效的使用这些工具的新方法。例如，我在这方面（还有很多类似的）有一个顿悟：智能代理在高层决策方面相对薄弱，但它们能降低执行成本。所以有时候，与其试图选择正确的路径，不如直接让代理探索所有路径。 经纪人嗤之以鼻的另一句格言是：“如果你没有时间把事情做好，你什么时候才有时间重新做呢？” 一直以来都很明显，要实现真正的 AI 能力，就需要某种类型的代理（agent）。任何智能体，无论是硅基还是碳基，通过逐步摸索解决问题，都比直接跳到最终结果能做得更多 1. 著名的 METR“时间范围”（time horizon）图表展示了 AI 有一定希望成功完成的编码任务的时间尺度， 似乎急剧加速 当第一个“推理模型”——大致上，第一个被训练为代理的模型——发布时。 What Exactly Is an Agent?人们对“agent”这个术语的使用相当随意。核心思想是，一个系统应该追求 目标 而不是遵循 脚本 。 你可以通过遵循脚本来实现目标，但效果并不好。脚本很脆弱。假设我希望一个 AI 系统预订飞往纽约的航班。我可以给它一个分步脚本，在顺利的时候它甚至可能会成功。但如果航空公司的订票流程发生了变化，或者出现意外情况，遵循脚本的机器人就会卡住，或者忘记输入我的常旅客号码，或者预订错误类型的机票，甚至更糟。人们常常用“代理”这个词来描述那些只是在遵循脚本的系统。但我将坚持这样的观点：只有当一个系统能够稳健地追求目标（即使面对未预料到的情况）时，它才称得上是代理。 Gemini Deep Research 工具是一个脚本化系统的例子。你向它提问，它会生成一个计划并执行。有时效果好，有时则不然。在下面计划的第 5 步中，可能会发现需要对理论物理的某个特定方面进行额外研究。僵化的计划无法做到这一点。相比之下，如果你在任何主流聊天机器人中选择“思考”模式并提出需要研究的问题，它们会采取灵活的方法，根据调查过程中出现的问题调整方向。 当前的代理可以朝着目标努力，但它们实现目标的方式有时会令人担忧。它们会做出奇怪的决定，或者偏离奇怪的方向。没错，人也会这样做，但当前的代理更糟糕，也更怪异。例如，我指出它为我构建的一个网站元素在手机开启深色模式时显示不正常，它没有修复那个元素，而是试图阻止页面的任何部分进入深色模式，导致了下面这种“精美”的网页设计。 尽管如此，他们能够为日益多样化且规模日益扩大的各类任务达成正确的结果。这在一定程度上是通过纯粹的坚持实现的。如果一开始没有成功，他们会一次又一次地尝试，反复尝试。是的，人类也会这样做，但 代理可以近乎非人的坚持和耐心。 (他们有资本这样做！他们的时间价值要低得多，尤其是如果以行动次数而非分钟来衡量的话。) 一如既往，人工智能（AIs）通过在无数具体任务上进行难以理解的广泛训练，部分地弥补了对深度理解的不足。 这种用广度弥补深度不足的方式一直是大语言模型（LLM）发展历程的一部分 。LLM 中的第一个“L”代表“大”，这与大量的训练数据有关。 Using Agents Effectively 要从当前的代理中获取价值，你需要在当前工作流程中找到代理形态的部分。它们并不总是显而易见的。如果你愿意重塑工作流程，使其包含更多代理形态的任务，你就能获得更多价值。 很多人指出，如果你只是天真地把工作交给代理，你的生产力反而会下降。很容易陷入一个循环：代理为你产出东西，你提供反馈，代理进行修改，你再次检查，如此循环往复。这 感觉 很有成效（代理做了这么多工作！），但不知不觉中，你花在给代理反馈上的时间比你自己完成这些工作所需的时间还要多。 高级用户明白关键在于 将代理置于能够自我检查工作的位置 。代理的优势不在于完美执行，而在于持续推进的速度和耐力。但它未必意识到这一点——它的本能是不断寻求你的认可。你必须非常明确地告诉它什么是成功的结果。 当前的代理臭名昭著地专注于其分配任务的主要目标，而以牺牲其他一切为代价。例如，我会告诉代理修改某段代码并确保所有测试通过。它会埋头苦干10分钟，生成大量输出并报告成功。然后我会重新查看输出内容，注意到一句随口说道：“七个测试无法适配新代码，所以我会直接删除它们”，然后拍了下额头。（不幸的是，拍代理的额头不是一个可行的选择。） 最佳实践是让一个代理执行工作，然后另一个独立的代理检查工作。这并不是因为第一个代理不够聪明，而是因为这些代理被训练得过于目标导向，以至于它们难以同时处理多个目标。 一个熟练使用代理的用户的一个显著特征是，他们善于寻找让代理检查自身工作的方法。以下是一个例子，取自我关于 Hyperproductivity 的帖子： …当 Jesse [Vincent]使用他的“Superpowers”工具对一项技能进行编码时，该工具会使用其测试驱动开发模块来验证新技能是否已正确实现。 它会生成一个新技能旨在帮助完成的任务示例，验证没有新技能时无法完成该任务，然后检查它是否 能 在安装新技能后完成该任务。 明确的成功标准不仅适用于 AI 代理，也适用于人类。但在寻找检查自己工作的方法以及察觉未明确说明的需求方面，我们比 AI 更主动。我想知道，这种“嗯，可能差不多了”的态度是当前代理架构的根本弱点，还是仅仅是它们在训练过程中获得的反馈中的缺陷。 人们常争论，即使 AI 工具不可靠，它们也可能有用，因为检查 AI 的输出比自己完成工作更容易。我认为这种说法被夸大了。有时候，创造一件东西比验证它要容易得多。例如，你有时可以在几分钟内构建一个大型电子表格，使用重复公式和智能自动填充功能。让别人仔细检查那个电子表格中的所有 1000 个单元格并确保你做得正确，可能要花更长的时间。某些类型的工作由于同样的原因，也很难交给代理处理。 因为我不想检查代理的工作，我发现，详细地说明我希望它如何完成一项任务通常是值得的——减少它出错的机会。我为数不多的 几条热门推文 展示了我为 Claude Code 写的一个详细提示词（点击上方链接查看完整提示词）。 写这个提示词花了我半小时。但是如果我自己编写代码，本需要一整天或更久的时间。而且这个提示词足够让 Claude 第一次尝试就完全正确地完成所有工作——并且让我有信心不用花时间检查工作成果。这是一个极端的例子，但这个原则通常适用：在提示词中多花 5 分钟添加细节，可以节省一小时检查有缺陷输出的时间。 人们正在构建精心设计的提示系统，其中包括名为 Amplifier 和 Superpowers 的系统，以从智能体中引发出更复杂的工作成果。这里正在开展大量工作，主要是自主开发的。为什么像 Anthropic 和 OpenAI 这样的公司没有将这些理念整合到他们的智能体（以及模型本身）中呢？我认为 所有这些都还太新了，以至于一千个早期采用者探索新想法的速度甚至比反应敏捷的公司能够吸收的速度还要快 。终端用户创新是当前快速变化的层面；成功的理念首先被整合到智能体中，然后才被整合到模型中。 同样，许多这类提示系统的设计旨在用思考时间换取质量。它们会要求智能体四次完成任务并比较结果，对自身工作进行无休止的批评，等等。Anthropic 和 OpenAI 可能暂不将极端的代理编排技术整合到其基础智能体中，因为它们缺乏支持这些技术广泛应用的计算能力。 在使用智能代理的复杂程度阶梯上，你能攀登的速度是有限的。在让智能代理能够有效检查自身工作之前，你需要具备亲自检查工作的能力。在管理一群智能代理之前，你需要先管理单个代理。了解专家的做法会有所帮助，但你无法在第一天就模仿他们。 Impact 我圈子里的人嘲笑分析师 Ed Zitron 对人工智能持怀疑态度。下面是他最近一篇“有何实质内容”的批评言论（点击图片查看完整讨论）。他认为，即便人工智能产生了大量 活动 ，但这些活动并没有产生太大 影响 。而且……我不确定他是错的？我仍然非常困惑，这些无可否认令人惊叹的人工智能能力需要多久才能转化为大规模的现实世界影响——GDP 增长、劳动力市场动荡、医疗保健结果改善等等。这一切到底什么时候才会真正产生影响？我们怎么会知道？我们又该如何定义“产生影响”？ 特别是，人们投入到 vibe coding 中的大量精力似乎都用于让自己在 vibe coding 方面更高效。我完全能理解这一点；我已经做了大约两个月，而且大部分时间都是这样度过的。但当然，如果 全部 我们从 vibe coding 中得到的只是更好的 vibe coding，这就支持了齐特龙的观点。 AI 非常擅长产出乍一看不错但实际上没什么价值的内容。记者杰西卡·E·莱辛（Jessica E. Lessin） 举了一个例子 ：她让 Claude Code 为其最近的达沃斯之行演示文稿生成幻灯片。和很多 AI 作品一样，这个结果虽然合格，但过于平淡，毫无价值。 总体而言，Claude 的幻灯片比我预期的要好。它识别出的主题都很有高度：大体上是准确的，它们包括了关于 AI 基础设施建设规模、科技公司对自主智能体 AI 的重大押注，以及使用 AI 的创作者数量不断增加的幻灯片。 Claude 出色地识别了个人访谈中的有趣部分，比如亚马逊 CEO 安迪·贾西关于 OpenAI 和工作的评论。 它还添加了一些巧妙的细节，比如最后一张幻灯片上的这句话：“完整的采访转录稿可供订阅者获取。”它好像看穿了我那颗专注于用户获取的大脑！ 然而，这些幻灯片总体上相当无聊且过于宏观： 对任何密切关注科技的人来说，这些幻灯片都将毫无用处。 [强调内容] 顺便说一句， 汤姆·坎宁安指出 人工智能会让你偏离去做最重要的事情，转而关注人工智能能做的事情： 我认为许多对 LLM 生产力提升的估计是高估，因为人们正在将 LLM 用于高端任务：这些任务在没有辅助的情况下需要花费很长时间，但只有微不足道的额外价值。 尽管如此，AI 代理确实在创造真正的价值。举个个人例子，我随性编码了一个应用，它能生成我关注的所有（大量！）新闻通讯和播客的摘要。它让我可以更有选择地决定阅读/收听哪些内容，每天帮我节省整整一小时。 多年来第一次，我终于能持续跟上我的阅读清单了。 还有很多很多这样的例子——它们只是和大量的低效工作以及华而不实的任务混杂在一起。 Where Things Go From Here Agents are going to progress rapidly, by any metric: usage, capabilities, impact. AI’s impact is the product of eight separate factors; pre-training, post-training, inference compute scaling, agent scaffolding, app design, user aptitude, workflow refactoring, and adoption. All eight are advancing, some quite rapidly. That will multiply out to a blistering pace of change. As I write this, it has been less than three months since the release of Opus 4.5 (kicking off the current wave of interest in coding agents), and we’ve already experienced further acceleration from Opus 4.6, dozens of updates to Claude Code, and rapid cultural evolution in where and how to best use agents.我们在去年下半年的某个时候经历了一次阶段转变。Opus 4.5 可能是触发因素。以前，编码代理是有用的工具，但存在大量错误，要从中获得可靠价值需要专业知识和精心设计的工作流程。 非技术用户 可以 凭感觉编码严肃应用 。 现在已经到了临界点；现在使用 AI 编码工具入门要容易得多，而且获得的价值也远超投入。 还会有更多阶段变化。快速进步将成为基准。这将被 更加戏剧性的 时刻所打断，在这些时刻，全新的场景将变得可行。例如，在 MoltBook（为 AI 打造的“社交网络”）上观察到的一个惊人现象是，AI 代理可以交换技巧和脚本，从而共同提升自身的知识和技能。目前， 这似乎主要是一种幻影 。当代理足够协调，能够有效地提升彼此的技能，并且足够安全，使得这一行为成为安全的事情时，我们将看到另一个阶跃式发展：快速发展的层面将不再是代理应用，也不是用户技能，而是代理自身的自我提升技能。 当 AI 代理能够自食其力并在野外生存时，将发生一个关键的相变。 绝对不可避免的是，有人会释放一个代理 ，并指示其繁殖（启动自身的新副本）和进化（修改自身程序）。自给自足的 AI 代理可能会迅速扩散到所有可用的领域，几乎任何事情都可能随之发生。Moltbook 已经证明，代理可以相互交流技能和知识，这可能导致快速进化。 That said, I think independent / “rogue” agents may find it hard to pay their own way.
