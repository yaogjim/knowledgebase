# 从0构建 agent

### 1. 项目介绍

视频开头通过 `README.md` 文件介绍了项目的核心功能和目标。这是一个基于 `ReAct` 架构的 Agent 智能体项目，提供了前后端分离的完整解决方案。

#### 1.1 本视频主要内容

以下是项目实现的主要功能点：

*   **后端服务**: 使用 `FastAPI` 框架实现对外提供 Agent 智能体的 API 后端接口服务。
*   **Agent 架构**: 使用 `LangGraph` 中预置的 `ReAct` 架构的 Agent。
*   **短期记忆与持久化**: 支持 `short-term`（短期记忆），并使用 `PostgreSQL` 数据库进行持久化存储，以实现断点续跑和故障恢复。
*   **工具调用 (Function Calling)**: 支持函数调用，包含了自定义工具和通过 MCP Server 协议提供的第三方工具（如高德地图）。
*   **人工审查 (Human in the loop)**: 对工具调用提供人工审查功能，支持四种审查类型 (`yes`, `no`, `edit`, `response`)。
*   **多模型支持**: 支持多家大语言模型（LLM）接口调用，包括 OpenAI、阿里通义千问以及本地部署的 Ollama 等。
*   **会话状态管理与故障恢复**: 使用 `Redis` 存用户会话状态，支持客户端和服务器端的故障恢复。
*   **前端 Demo**: 使用功能强大的 `rich` 库实现了一个命令行的前端 Demo 应用，与后端 API 接口服务进行联调。

### 2. 核心业务流程解读

视频中展示了 `doc` 文件夹下的三份核心业务流程图，用以帮助理解项目的整体架构和数据流动。

#### 2.1 后端业务核心流程

该流程图展示了后端服务的核心逻辑。



*   **核心组件**: 主要包括客户端（Client）、API接口、LangGraph 工作流（Workflow）、Redis（用于会话管理）和 PostgreSQL（用于状态持久化）。
*   **流程解析**:
    1.  **用户输入 (`Input`)**: 用户通过客户端 API 发起请求。
    2.  **调用 Agent (`invoke_agent`)**: 后端服务接收到请求后，开始调用 LangGraph 构建的 Agent。
    3.  **人工审查 (`Interrupt`)**: 当 Agent 运行到需要人工审查的节点（`human_node`）时，流程会中断（`Interrupt`），并将中断数据返回给客户端。
    4.  **用户反馈**: 用户根据提示输入反馈信息（如 `yes`, `no`, `edit` 等）。
    5.  **恢复 Agent (`resume_agent`)**: 后端服务接收到用户的反馈后，调用 `resume_agent` 接口，将用户的指令数据（`command_data`）传入，恢复 Agent 的运行。
    6.  **持久化**: 在整个过程中，`Checkpointer` 会将 Agent 的每一步状态都保存到 `PostgreSQL` 数据库中。
    7.  **会话管理**: `Redis` 用于存储用户会话（`session`）的映射关系（`user_id` -> `session_id`），实现会话的恢复和管理。
    8.  **完成 (`Completed`)**: 最终，Agent 完成任务，将结果通过 API 返回给客户端。

#### 2.2 API接口和数据模型描述

该文档详细定义了后端提供的 API 接口以及前后端交互时使用的数据模型。



*   **主要接口**:
    *   `agent/invoke`: 创建并调用智能体。
    *   `agent/resume`: 恢复被中断的智能体。
    *   `agent/status/{user_id}`: 获取指定用户的会话状态。
    *   `system/info`: 获取系统信息（如活跃会话数）。
    *   `agent/session/{user_id}`: 删除指定用户的会话。
*   **数据模型**: 定义了如 `AgentRequest`（请求）、`AgentResponse`（响应）、`InterruptResponse`（中断响应）等 Pydantic 模型，确保了前后端数据交换的规范性和类型安全。

#### 2.3 前端业务核心流程

该流程图展示了客户端（即 `02_frontendServer.py`）的工作逻辑。



*   **流程解析**:
    1.  **启动**: 程序开始，首先调用 `get_system_info()` 接口获取系统当前活跃的会话和用户数。
    2.  **用户输入ID**: 等待用户输入 `user_id`。
    3.  **检查/恢复会话**: 调用 `check_and_restore_session()`，检查该用户是否存在活跃会话。如果存在，则自动恢复。
    4.  **主循环 (while True)**:
        *   **判断会话状态**: 如果会话被中断 (`interrupted`)，则进入中段处理逻辑，等待用户输入 `yes`, `no`, `edit` 或 `response`，然后调用 `resume_agent` 接口。
        *   **处理新请求**: 如果没有中断，则等待用户输入新的问题 (`query`)，然后调用 `invoke_agent` 接口发起新的智能体任务。
        *   **处理特殊指令**: 支持 `exit`（退出）、`status`（查询状态）、`new`（开启新会话）等特殊指令。

### 4. 功能测试

视频中详细演示了项目的各项功能。

#### 4.1 启动数据库服务

使用 Docker Compose 启动 `PostgreSQL` 和 `Redis` 服务。

进入 `docker/postgresql` 目录，执行：
```bash
docker-compose up -d
```
进入 `docker/redis` 目录，执行：
```bash
docker-compose up -d
```
启动后，可以通过 Docker Desktop 界面查看到 `postgres` 和 `redis` 容器正在运行。

#### 4.2 启动前后端服务

分别在两个终端中启动后端和前端服务。

**启动后端服务：**
```bash
python 01_backendServer.py
```

**启动前端服务：**
```bash
python 02_frontendServer.py
```

#### 4.3 功能演示

1.  **人工审查 (HIL) 测试**
    *   **同意工具调用**: 输入 "调用工具预定如家酒店"，在提示是否允许时输入 `yes`，Agent 成功调用工具并返回结果。
    *   **拒绝工具调用**: 输入 "调用工具预定桔子酒店"，在提示时输入 `no`，Agent 放弃调用工具并给出相应回复。
    *   **修改工具参数**: 输入 "调用工具修改工具参数后调用工具"，在提示时输入 `edit`，然后根据提示输入新的 JSON 格式参数 `{"hotel_name": "全季酒店(软件园店)"}`，Agent 使用修改后的参数成功调用工具。
    *   **直接提供反馈**: 输入一个需要调用工具的问题，在提示时输入 `response`，然后直接输入反馈信息，Agent 将不会调用工具，而是基于你提供的信息继续思考。

2.  **客户端故障恢复测试**
    *   在一个进行中的会话（例如，处于人工审查中断状态）中，强制关闭前端客户端（模拟故障）。
    *   重新启动一个新的前端客户端。
    *   输入与之前相同的 `user_id`（例如 `test02`）。
    *   系统会自动检测到该用户有未完成的会话，并恢复到中断前的状态，用户可以继续之前的操作。

3.  **多用户与会话管理**
    *   视频中通过开启多个前端客户端，并使用不同的 `user_id`（`test01`, `test02`）来模拟多用户场景。
    *   每个用户的会话状态都独立存储在 Redis 中，互不干扰。
    *   使用 `status` 指令可以查看当前会话的状态信息。
    *   使用 `new` 指令可以清除当前用户的旧会话，开启一个全新的会话。

### 5. 核心代码解读

视频最后对关键的代码文件进行了简要的梳理。

*   **`utils/config.py`**: 全局配置文件，定义了日志、数据库连接、Redis连接、API服务地址以及默认使用的大模型类型。
*   **`utils/llms.py`**: 统一管理大模型实例。根据 `config.py` 中的 `LLM_TYPE` 配置，初始化不同的大模型客户端（OpenAI、通义千问、Ollama等）。
*   **`utils/tools.py`**: 工具定义文件。
    *   实现了 `book_hotel`（预定酒店）和 `multiply`（乘法计算）两个自定义工具。
    *   通过 `add_human_in_the_loop` 函数为工具包装了一层人工审查的逻辑。
    *   集成了 `MCP Server` 的工具（高德地图API），演示了如何调用外部工具服务。
*   **`01_backendServer.py`**: 后端服务主文件。
    *   使用 `FastAPI` 创建 Web 应用。
    *   定义 `lifespan` 生命周期函数，在服务启动时初始化数据库连接池和 Redis 连接。
    *   定义了 `/agent/invoke`, `/agent/resume` 等核心 API 接口，处理客户端请求并与 LangGraph 工作流交互。
*   **`02_frontendServer.py`**: 前端命令行客户端主文件。
    *   使用 `rich` 库构建美观的命令行界面。
    *   `main()` 函数是主逻辑入口，包含一个 `while` 循环，负责接收用户输入、调用后端API、处理返回结果和展示信息。
    *   实现了 `check_and_restore_session` 函数，用于实现客户端的故障恢复。

总的来说，这个视频详细地介绍并演示了一个功能完备、架构清晰的 Agent 智能体服务，涵盖了从后端架构、API设计、状态管理到前端交互的完整流程，对学习和实践 Agent 开发非常有帮助。
