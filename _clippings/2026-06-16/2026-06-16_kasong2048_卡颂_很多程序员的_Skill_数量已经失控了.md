# 卡颂: 很多程序员的 Skill 数量已经失控了

**卡颂**

很多程序员的 Skill 数量已经失控了。

今天试了 superpowers，明天又被安利 compound-engineering，后天跟风又装了 gstack，Skill 数量瞬间膨胀到几十个，Skill 之间的跳转、召回逻辑变得无比不稳定。

这是很多人都会经历的，本质原因是：这些框架都是对 Harness Engineering 最佳实践的探索，自身都有亮点（比如 superpowers 的 Skill 编排，compound 的持续学习），但能力又有交集。

当前 Skill 管理工具的思路都是“屏蔽复杂度”（比如启用/停用 某个 Skill），而不是“降低复杂度”。

我当前在实践的方式是：以 superpowers 为基础框架，把其他框架的亮点（比如 compound）合并在基础框架上。当然，合并、测试 Skill 都是通过 Skill 完成的。

这样能控制 Skill 数量的膨胀速度～
