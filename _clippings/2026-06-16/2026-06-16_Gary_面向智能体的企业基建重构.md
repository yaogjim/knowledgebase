# 面向智能体的企业基建重构

# John Suh: Increasingly, I believe companies may need to be rebuilt from the ground up, whe…

https://x.com/john\_ssuh/status/2065184662344048789

**John Suh**

我日益认为，企业可能需要从头重建。需要建立一个统一的可检索系统，其中包含所有可观测性、产品指标和文件变更的单一时间线，例如整合 Datadog、Posthog、Google Drive 和 Slack（实际上是 Claude Code 聊天与 Codex 聊天的统一文件系统）。这或许会成为所有企业最大化人工智能应用的新数据基础。之所以需要重建，是因为在现有系统中追踪差异基本上无法生成关于决策和回滚的纵向信息——这是编码代理存储公司正在积极探索的问题，但这一需求应该扩展到整个企业层面。

不过，现有企业可能会对采用这一方案持高度怀疑态度，因为这意味着需要彻底改造其所有的工具和业务数据；但我认为，以此为基础构建的企业可能能够执行得更好、更快，效率提升100倍

# Jerry Liu: There's got to be some major advances in the data ingestion, indexing, and retri…

https://x.com/jerryjliu0/status/2065264788268319221

**Jerry Liu**

要实现这一点，数据摄取、索引和检索层必须有一些重大进展。

智能代理在通过简单工具接口（例如：命令行界面(CLI) + 文件系统）获取多样化上下文来源方面变得越来越先进。但是：

这是一个已知问题，即通过 MCP 进行的代理式联邦搜索在检索相关性方面并非最优

代理式搜索通常在没有预索引的情况下真的很慢

当你交错不同的数据来源时，你需要对每个项目进行适当的加权

不同类型的数据需要不同的查询接口 - 从 SQL 到嵌入搜索

期待看到这如何实现。我们今天的主要重点是解锁基于文档的上下文，并且我们很想看看这如何与 SaaS/结构化数据集成。
