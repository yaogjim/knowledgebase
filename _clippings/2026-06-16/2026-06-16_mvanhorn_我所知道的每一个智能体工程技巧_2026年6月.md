## 当你有想法的那一刻，制定一个 CE 计划.md

仍然是第一条规则。仍然是我学到的最重要的事情。

当我有了一个想法，就会用/ce-plan 来创建一个 plan.md 文件。不是先想“让我想想这个”，也不是“让我开始编码”。每次都用/ce-plan。它也会处理图片，所以任何你能捕捉到的东西都可以作为起点：

- 疯狂的产品创意：/ce-plan
- GitHub 上的 bug：复制问题 URL，粘贴它，/ce-plan。
- 终端错误：使用 Command+Shift+4 进行截图，Ctrl+V 粘贴，/ce-plan 修复此问题。
- 截图、错误消息、设计原型、Slack 线程：把这些中的任何一个放进来。

当想法还很模糊，我甚至还不知道自己想要什么时，我会先用 /ce-brainstorm 与助手一起梳理思路，然后一旦想法清晰后，就用 /ce-plan。

在内部，/ce-plan 会并行派遣多个研究代理。一个代理读取你的代码库，发现模式，检查你的编码规范。另一个代理搜索你过往的解决方案以获取经验。如果主题需要，更多代理会去查阅外部文档和最佳实践。所有代理同时工作。然后它会整合信息并生成一个结构化的 plan.md 文件：指出问题所在、说明方法、需要修改的文件、带复选框的验收标准，以及你自己代码中应遵循的模式。该计划基于你的代码仓库、编码规范和历史记录，而非通用建议。

/ce-work 会获取该计划并进行构建。上下文崩溃了？开启一个新会话，指向该计划，从上次中断处继续。该计划是经受住一切的检查点。

传统开发中，80%是编码，20%是规划。这完全相反。思考融入规划，执行是机械的。

## 2\. 不要阅读 plan.md

我总是创建 plan.md。我几乎从不阅读它。计划是给代理的，你这个傻人。

迫使计划存在能让编码代理不偷懒。这会促使它们进行研究、确定一种方法、写下验收标准，并最终达成这些标准。有计划的编码代理会交付已完成的工作。没有计划的编码代理则会走捷径并提前停止。计划是缰绳。

所以我让它写计划，我快速浏览标题，然后运行 /ce-work。如果我有问题，我会在会话中直接提问：“等等，为什么用这种方法？”或者我会要求 TLDR。或者，当我不理解的时候，就说“eli5 这个计划”。我会得到一个段落的版本，点点头，继续前进。我不会坐在那里阅读 300 行的 Markdown。这是代理的工作，不是我的。

制定计划。信任计划。不要阅读计划。

黑客攻击

- 不要让自己读这份计划。直接提问：TLDR？、eli5 这份计划，或者‘等等，为什么这种方法？’

## 3\. 使用 /ce-plan 处理您最深入的非工程类工作，为计划制定计划

人们认为 /ce-plan 和 /ce-work 是为代码设计的。自三月以来我学到的最重要的一点是，它们并非如此。我现在所做的最深入的知识工作遵循同样的流程，而关键在于让第一个计划成为关于计划的计划。这也不是我在强迫一个代码工具去做它本不擅长的事情：/ce-plan 内置了一个通用规划模式，正是为这种非代码工作而设计的。

这不仅仅是业务问题。战略文档、产品规格、竞争分析、董事会更新，都在同一个循环里。

这是一个真实的例子。我遇到了迈克尔·马戈利斯（Michael Margolis），他是前 GV 研究合作伙伴，以靶心客户方法（bullseye-customer method）而闻名。我们讨论了我正在酝酿的一个商业挑战。他建议我读他的书，这本书在他的网站上可以免费以 PDF 格式获取。以往的做法是快速浏览后就继续，但这次我打开了 Claude Code，大致说道：

"/ce-plan 制定一个计划来规划这个计划。我马上要给你两件东西：Margolis 的书（PDF 格式），以及我刚刚与他进行的两小时 Granola 会议的转录稿，其中包含了我们讨论内容的完整背景信息。我需要一个深思熟虑的计划，说明我的业务问题、那次谈话以及书中的教训如何整合起来，形成我能实际使用的方案。现在不要写那份文档。写这份文档才是后续的工作。现在我只需要一个计划，说明你将如何阅读这本书、挖掘转录稿中的信息，并产出一份出色的文档。"

它花费了接下来的 45 分钟制定一个 EPIC 计划。

这也是我所知道的让 LLM 不偷懒的唯一最好技巧。直接要求交付成果，它会走捷径。让它先规划如何生成交付成果，然后执行该计划，它每次都会给出深入的版本。

黑客攻击

- 深度非代码工作：/ce-plan 为该计划制定计划，提交你所有的上下文和记录，然后 /ce-work.

## 4\. 语音觉醒

语音到 LLM 与语音到其他任何内容的转换不同。转录不需要完美，因为接收方（即 LLM）能理解上下文。它会猜测麦克风识别错误的地方。你可以含糊表达、声音中断或重新开始句子。语音转换终于能正常工作，因为另一端的模型足够智能以填补缺口。

我的设置

- Mac：
 
 [Monologue](https://monologue.to/)（来自 Every）或
 
 [Wispr Flow](https://wisprflow.ai/)
 
 。选择一个，将语音输入到当前聚焦的任何应用中，与 Claude Code 对话。我为办公室买了一个鹅颈麦克风。
 
- 手机：跳过 Monologue 和 Wispr Flow，在 iOS 上切换到它们太烦人了。苹果的内置语音输入已经足够好了，因为你是在和 LLM 对话，而不是和人对话。即使它可能会识别错一半的单词，AI 助手仍然能理解。随手记也没关系。

一个坦诚的承认：当我独自一人时，我很擅长使用语音。在办公室里我就很吃力。人们说你可以对着麦克风轻声说，但我发现自己其实做不到，因为我不想显得粗鲁或者打扰周围的人。所以，在一个共享空间里的工位对我来说，在整个工作流程中仍然是个薄弱环节。如果你能在开放式办公室里使用语音而不被人觉得是那种人，告诉我你是怎么做的。我真的很想得到建议。

黑客攻击

- Mac：安装
 
 [Monologue](https://monologue.to/) 或
 
 [Wispr Flow](https://wisprflow.ai/)
 
 。
 
 手机：使用 Apple 听写。获取一个鹅颈麦克风 。

## 6\. 将你的终端默认设置为 Claude 或 Codex，而不是 Shell

新标签页应该直接打开到 Claude Code，而不是 Shell。打开一个标签页，你就已经在和一个助手对话了。不需要输入 cd，也不需要输入 claude。当创建一个新会话只需一次按键时，你会开始创建更多的会话。我也不使用文件夹。你的助手可以找到你的项目。

黑客攻击

- 粘贴到你的代理中：“让每个新的终端标签页直接打开到 Claude Code。在~/.config/ghostty/config中，添加一行 command = ~/.local/bin/claude-launcher.sh，且不影响该文件中已有的其他设置。然后创建~/.local/bin/claude-launcher.sh，使其运行 claude --dangerously-skip-permissions，并且当 Claude 退出时打印一条简短的提示信息，并将我带入交互式登录 zsh。对该脚本执行 chmod +x。这适用于 Ghostty 和 cmux，因为 cmux 读取与 Ghostty 相同的配置。”

## 7\. 远程控制每个窗口，并给 Claude Code 或 Codex 一个电子邮件地址

两个技巧，使每个会话都能从任何地方访问。

每次打开新窗口时，开启遥控器

设置遥控器在每次会话中自动开启。

现在每个窗口都可以从 Claude 移动应用程序访问。在办公桌前开始一个会话，离开后，在任务进行中通过手机继续完全相同的实时会话。在某个地方排队时，你也可以控制家里 Mac 上正在运行的内容。

给你的 Claude 一个邮箱地址

Claude Code 可以通过 AgentMail 拥有一个电子邮件地址。创始人 Adi

[@adisingh](https://x.com/@adisingh) 教了我这个。向收件箱发送电子邮件后，一个新的会话会打开并开始处理主题和正文中的内容，任何附件都可通过路径获取。晚餐时遇到问题？从手机发送电子邮件，在你回到屏幕前会话就已开始运行。我将整个项目开源了：

[github.com/mvanhorn/agentmail-to-claude-code](//github.com/mvanhorn/agentmail-to-claude-code)

.

三件：

- 一个守护进程，它通过 WebSocket 监视一个
 
 [AgentMail](https://agentmail.to/) 收件箱。对于每一封已列入允许列表的邮件，它会打开一个新的 Claude 会话，将邮件写入提示文件，并指示 Claude 读取并处理该邮件。
 
- 两个终端后端，cmux 或独立的 Ghostty，因此它能驱动你已经启动的任何内容。
- 一个发送端。我在我的 Hermes 中将其配置为 cc 命令，因此从手机运行 cc <任务>，它就会在我的 Mac 上生成一个工作会话，无需 VPN，无需 SSH。

白名单就是大门。只有你控制的地址才能通过，任何未通过 DKIM 或 SPF 验证的内容在会话建立之前就会被拦截。

黑客攻击

- 始终开启的远程控制：在~/.claude/settings.json.中添加 "remoteControlAtStartup": true
- 给 Claude 发一封邮件。粘贴到你的代理中：“给 Claude Code 使用
 
 [github.com/mvanhorn/agentmail-to-claude-code](//github.com/mvanhorn/agentmail-to-claude-code) 发一封邮件地址。克隆它，设置一个 AgentMail 收件箱，用我的 API 密钥填充 cc.env，收件箱，仅包含我自己地址的允许列表，以及我的终端（cmux 或 Ghostty），然后运行守护进程并将其安装为 launchd 任务。当我向该收件箱发送邮件时，应该会在这台 Mac 上打开一个新的 Claude Code 会话，并从主题和正文中开始。
 

## 8\. 危险地绕过权限，而且我是认真的

Claude Code 对每次编辑和命令都请求权限。有六个会话你根本管不过来。两个设置让它用起来更顺手。人们说自动是“更安全”的方式，但这也让我慢了太多。

关键是将 skipDangerousModePermissionPrompt 设置为 true。如果不设置这个，Claude 会要求你确认每一次会话。你也可以按 Shift+Tab 来切换这个设置。有人告诉我，新的“auto”模式在更安全的前提下能帮你解决大部分问题。也许吧。我嘛，就信奉 YOLO（你只活一次）。这是我的电脑，要是我把一切搞砸了，GitHub 还在那儿。我给一个朋友设置 Claude Code 时，AI 还主动劝他别启用这个设置。你得直接跟它说。

另一个设置是一个声音钩子，不可协商，包含六次会话。

走开，听到声音再回来。六个会话正在运行，声音是你判断哪个刚刚结束的方式。

黑客攻击

粘贴到 ~/.claude/settings.json:

{ "权限": { "允许": \[ "WebSearch", "WebFetch", "Bash", "Read", "Write", "Edit", "Glob", "Grep", "Task", "TodoWrite" \], "拒绝": \[\], "默认模式": "绕过权限" }, "跳过危险模式权限提示": true }

{ "钩子": { "停止": \[ { "钩子": \[ { "类型": "命令", "命令": "afplay /System/Library/Sounds/Blow.aiff" } \] } \] } }

Codex 具有相同的 YOLO 模式。在~/.codex/config.toml:

approval\_policy = "从不" sandbox\_mode = "danger-full-access"

或者用 codex --yolo 启动一个一次性操作。

## 9\. 我如何在不打开 Codex 命令行界面的情况下运行我大部分的代码

我整天都把工作交给 Codex 处理，几乎从不打开 Codex CLI 来做这件事。Claude 负责规划，Codex 负责构建，我从不离开我的 Claude 会话。

三种我不离开 Claude 而手动工作于 Codex 的方法

- [Codex IDE 扩展](https://developers.openai.com/codex/ide)
 
 [Codex IDE 扩展](https://developers.openai.com/codex/ide)
 
 : 发送任务，应用结果，永不进入 Codex 终端。
 
- /ce-work --codex: 将构建直接委派给 Codex，该委派发生在 Compound Engineering 循环内部。
- Printing Press Codex 模式：在打印新 CLI 时，将 codex 放在提示的末尾，然后它会将构建交给 Codex。

我的设置，两个引擎都调至超高推理级别：

- Codex：推理超高，快速模式始终开启。
- Claude Code：推理超高，快速模式关闭。它的快速模式按 token 计费，超出您的 200 美元最高计划，所以我跳过它。

两个 200 美元的计划并排运行就像一个完整的第二引擎。我向 Codex 推动大型并行构建，同时让 Claude 负责规划和品味。有些朋友则采用相反的方式：Codex 进行构建，Claude 进行审查。

黑客攻击

- Codex：推理 xhigh，快速模式开启。Claude Code：xhigh，快速模式关闭。
- 手动操作到 Codex：的
 
 [Codex IDE 扩展](https://developers.openai.com/codex/ide) ，/ce-work --codex，或者在 Printing Press 提示的末尾加上 codex
 
 [Printing Press](https://printingpress.dev/)
 
 的提示。
 

## 10\. 在计划前进行研究：last30days

在我执行/ce-plan 之前，我通常会先在它上面运行/last30days。

我在 Vercel 的 agent-browser 和 Playwright 之间做选择。与其阅读文档，我直接运行了 /last30days Vercel agent browser vs Playwright。几分钟内：数十条 Reddit 帖子、X 帖子、YouTube 视频、Hacker News 故事。Agent-browser 每次调用使用的上下文少得多，而 Playwright 仅为工具定义就会消耗数千个 token。我将整个输出内容输入到 /ce-plan integrate agent-browser。生成的计划基于社区当前实际了解的内容，而非六个月前的训练数据。

[最近 30 天](https://github.com/mvanhorn/last30days-skill)

[最近 30 天](https://github.com/mvanhorn/last30days-skill)

是开源项目，目前已获得超过 26K 颗星。它会并行搜索 Reddit、X、YouTube、TikTok、Instagram、HN、Polymarket、GitHub 以及网页。我在选择库之前、构建功能之前、与商业伙伴会面之前、撰写文章之前都会使用它。我在这篇文章中提到的一些内容上运行过它。研究、计划、构建。这才是真正的循环。

## 11\. 格兰诺拉所有东西，以及将原始转录文本放入你的 LLM

我和一位候选人共进午餐。我们聊了产品、食物和孩子，九十分钟的普通交谈中穿插着一个产品想法。

[Granola](https://granola.ai/)Granola 当时正在运行。之后，我将完整的原始转录文本粘贴到 Claude Code 中：/ce-plan 将其转化为产品提案。

关键在于原始性。我不会先总结，而是直接把整个杂乱的文字记录（包括关于寿司的旁支内容等）丢进去，让 Claude 针对我实际的代码库和我之前写的每一份策略计划进行提取。颗粒化的上下文加上代码库和之前的计划，等于黄金。它一次性完成了提案，忽略了关于餐厅的讨论，我当晚就发了出去。现在那个人全职和我们一起工作了。

黑客攻击

## 17\. 撰写你自己的技能

最大的提升不是使用代理，而是教会它们能记住的技巧。任何我做过两次以上的操作，我都会将其转化为一种技能：一种我的代理可以永久执行的可重复使用的命令。首先编写你自己的技能，以自动化你的工作流程。

你不需要从头开始编写它们。对我来说，解决这个问题的诀窍是让你的代理指向一个已经有效的技能，并让它复制其结构。具体来说：“看看 Compound Engineering 技能，帮我为\[我想要自动化的任何事情\]创建一个类似的技能。”它读取一个很好的示例，学习其结构，并为我搭建框架。我用这种方法构建了很多技能。

这也是我现在开源生活的大部分内容。如果你看看

[我的 GitHub](https://github.com/mvanhorn)，工作内容是技能以及围绕这些技能的工具。last30days 最初是我为自己想要的一项技能，现在已开源，获得了超过 26K 的星标。Printing Press 是一个用于生成 agent 原生 CLI 的完整工厂，也是我最常用的个人工具，已有超过 320 个 PR 被合并到其中。我是 Compound Engineering 的核心贡献者之一。这一切都不是什么宏伟计划。每一部分都是我经常运行的工作流程，因此值得让 agent 永久擅长它。

编写一次技能，之后的每一次会话都更快。那就是复合工程的复合部分。

黑客攻击

- 任何你做过两次以上的事情，都要将其转化为技能：“看看复合工程技能，帮我为\[X\]制作一个类似的。”

## 21\. 坦诚的部分：AI 精神病

代理本应替我们做所有工作。相反，我所有的朋友都在一生中最努力地工作。

简单的回应是休息一下，去户外走走。但这不是重点。这是关于成瘾的。用代理建造是有史以来最伟大的电子游戏，而且游戏循环机制太赞了。

我有一些真正让我担心的朋友。他们因为能创造任何东西而兴奋不已，以至于不再做其他事情。然后他们推出产品，但没有用户。而这也没关系。我也推出过很多没有用户的东西。问题不在于推出时没人用，而在于沉迷于构建而失去身边的人。

所以要小心。和你爱的人谈谈。问问自己，是否真的有人想要你正在制作的东西。如果诚实的答案是它对你来说只是个工具，那也没关系。我做过的一些最棒的东西，其实只是为我自己做的。

如果你确实想要拥有受众，那就是加里·维纳查克(Gary Vaynerchuk)一直宣扬的内容传播路径。你从某个地方开始，在虚拟空间发布内容，希望有人注意到。然后是三个，然后是十个，然后是一百个，你一步步发展到数千人。没人能从数千人开始。你所构建的任何事物都是如此。

黑客攻击

- 休息一下，摸摸草。
- 和你爱的人谈谈。
- 构建一些人们想要的东西，即使“人们”只是你。
