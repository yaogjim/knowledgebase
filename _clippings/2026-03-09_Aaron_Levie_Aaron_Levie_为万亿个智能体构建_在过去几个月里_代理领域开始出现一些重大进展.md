# Aaron Levie # 为万亿个智能体构建 在过去几个月里，代理领域开始出现一些重大进展

**Aaron Levie**

# 为万亿个智能体构建

在过去几个月里，代理领域开始出现一些重大进展。去年年底前后，我们开始发现编码代理能够完成运行时间长得多的任务，并且在开发过程中不再需要那么多的人工指导。

这些代理不再是具备基础工具的聊天机器人。相反，这些代理通常拥有自己的沙箱化计算环境，能够为遇到的任何问题编写和运行代码，直接与 API 和 CLI 交互，拥有自己的文件系统和长期记忆等。这一系列核心基本原语、代理框架最佳实践方面的普遍进展，以及代理在工具使用和软件开发方面的惊人模型进展，让我们得以窥见这些代理能够处理任何可能被赋予的任务。

而这种架构最初由 Claude Code、Devin、Codex、Factory、Cursor 或 Replit 等编码代理定义，我们最近已跨越鸿沟，进入个人体验和知识工作的各个领域，如今借助 Claude Cowork、Perplexity Computer、Manus 以及当然还有 OpenClaw 等代理。OpenClaw 将发展推向了更远的未来，其代理全天候在自身的持久环境中运行。

由于能力的快速提升，智能代理将被应用到几乎所有工作领域。智能代理将被部署来审核所有起草的合同，处理大多数客户支持案例的一线工作，审计每家公司的财务状况，梳理所有用于药物研发的医学研究资料，生成几乎所有已编写的代码，制作大多数销售和咨询演示文稿，为消费者在网络上进行交易，总体而言，参与社会中几乎所有其他具有经济价值的任务。

这不仅仅是执行我们今天已在做的任务。我们将使用智能代理完成远比以往多得多的工作——我们将用它们运行以前负担不起的模拟，用它们为每个想法构建包含多种不同选项的原型，开展远比以往多得多的项目（因为启动成本低且易于终止），并且我们将审查每一条数据而非抽样信息。

综合来看，我们可以预期，几乎每个组织中的员工都会有许多代理代表他们行事，不难想象一家企业中代理的数量会比员工多100倍甚至1000倍。由于数万亿的代理四处活动，代理将在未来成为所有软件的主要用户。

由于大多数软件是为人们使用而构建的，这意味着我们将看到软件未来形态的重大转变。那么下一步是什么？

让代理想要的东西

保罗·格雷厄姆（Paul Graham）以最简洁的方式著名地阐述了如何构建软件：制造人们想要的东西。

这一建议催生了21世纪一些最大的软件成功案例，并推动了一场开发工具的运动，这些工具易于使用、易于上手、解决明确问题、不使用术语、定价直接明了，以及其他类似的特点。

现在，前进的方向是开发代理想要的软件。虽然代理的最大用户群体往往是开发者，或者至少是技术能力很强的用户，他们通常会有自己对工具的偏好，但在代理为知识工作者完成各类任务的世界里，这种偏好将会慢慢消失。除非企业已经有了标准，否则在任何特定工作流程中，哪些内容会被采用将由代理来主导。

这可能意味着他们注册使用的工具、编写的代码、使用的库、运用的技能等等。对代理更容易上手，并且能最好地解决代理（和用户）问题的平台，将会比那些做不到的平台领先快得多。代理不会去参加你的网络研讨会或看到你的广告；他们只会选择最适合该工作的工具，而你会希望这个工具是你的。

这条建议的最大含义是，你所构建的一切都必须采用 API 优先的策略。如果某个功能没有对应的 API，那它就形同虚设。如果某个功能无法通过 CLI 或 MCP 服务器暴露，你就会处于劣势。如果你的 API 混乱且代理在执行时有相互冲突的路径，那你就是在降低该功能对代理的有用性。在 Box 公司，当我们专注于为代理构建文件系统时，我们一直在仔细梳理 API 的各个方面，以确定在代理环境中哪些地方会影响可用性——而这种可用性水平通常只有在用户体验（UX）设计中才会被关注。

就像为用户设计软件时需要设身处地为他们着想一样，当考虑到智能体将会遇到什么情况时也是如此。例如，YCombinator 的 Jared Friedman 提醒所有人：“即使是最好的开发者工具，大多时候仍然不允许你通过 API 注册账户。在 Claude 代码时代，这是一个很大的缺失，因为这意味着 Claude 无法自行注册。现在，将所有账户管理功能都放到你的 API 中应该是基本要求了。” 如果一个智能体无法轻松注册你的服务并开始使用，那么对这些智能体来说，你基本上就没用了。

对于未来代理将成为最大软件用户的世界，这也会带来重大的商业模式影响。在某些情况下，由用户席位触发的代理可能会比较自然地适配软件的基于席位的商业模式，但代理有大量用例无法简单地与现有用户关联，或者因为其工作量规模现在完全不同。例如，只需输入几个单词或几行文本，代理就能在软件中完成数小时的等效人类工作，并将最终结果呈现给最终用户。

这最终将意味着软件某些部分的商业模式将发生演变，因为任何想要在智能化代理时代生存的工具，都需要将某种形式的按使用量或按规模计费的商业模式融入到自身系统中，甚至支持代理能够为这些服务自行支付费用。

为智能体服务的基础设施与工具的下一个时代

"给人类配备电脑是个好主意。让电脑配备电脑则是一个更好的主意，以便它们能够生成我们在电脑上为工作所做的相同输出。"——Aravind Srinivas，Perplexity

由于智能代理拥有自己使用的电脑，能够编写和执行自己的代码，调用常用技能来执行重复操作，以及利用外部工具和服务，这为智能代理使用一整套全新的技术创造了机会。试想一下用户在电脑上做什么，而智能代理将需要一套类似的、专门为其设计的能力。

这些核心服务中，有些将自然来自现有参与者，因为智能化代理正在利用现有数据，或者现有人类用户与系统中的智能化用户之间的协作或连接具有价值。同样，由于问题空间与人类用户以往的需求或能力相比差异巨大，因此会出现全新的类别，这使得从头开始设计服务变得合理。

例如，很明显，代理将需要拥有自己的基础设施来运行，并且规模将达到我们前所未见的程度。下一个超大规模云服务商（或现有的一个）将基于这样一种理念构建：未来的服务器场将不再用于我们的应用，而是用于我们的代理。E2B、Daytona、Modal 和 Cloudflare 都在朝这个方向推进，而这些沙箱环境将与我们前所未见的任何计算规模相媲美。

代理还需要访问企业中的核心文件，同时能够管理自己的数据以处理内存和长时间运行的工作，这正是我们在 Box 专注构建的内容。同样，主要的企业系统需要优先采用 API，以便代理能够与组织的关键服务和数据进行交互，例如人力资源信息系统（HRIS）、客户关系管理系统（CRM）、工作流、数据湖以及其他主要系统。能够为代理提供最无缝工具以使其随时随地操作这些数据的产品，将在赢得这些未来工作负载方面占据最佳位置。

代理可能还需要身份，并具备与他人沟通的能力；例如，Agentmail 正在为代理提供邮箱，让它们拥有自己的持久邮箱以开展工作。Parallel、Exa 等公司正在为一个代理成为最大用户、抓取网络信息的世界重建网络搜索。许多类型的代理将需要使用 Stripe 或 Coinbase 的钱包来管理自己的支出预算，而我们可能终于会迎来小额交易的真正应用场景，在其中代理可以接入付费工具和信息。

安全、合规和治理将成为这些代理的主要问题。在代理访问和处理工作流中的敏感信息，或执行受监管工作流（如制药或银行业）的环境中，企业需要管理和留存这些代理所做的所有工作。长期运行的代理可能需要自己的身份，以允许它们对服务进行身份验证，从而严格控制它们可以执行的操作类型以及在企业中可以访问的数据。我们需要所有新的软件和平台来应对这些挑战，就像我们随着时间的推移为人员和应用程序构建的那样。

总体而言，我们显然正进入一个新的软件时代，在这个时代，我们需要专门为代理的规模化使用设计和构建工具。在一个有数万亿代理执行工作的世界中，这将开启一种全新的软件使用方式。
