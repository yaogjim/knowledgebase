# 研究 Codex 上下文压缩是如何工作的

对于非 Codex 模型，开源的 Codex CLI 会在本地压缩上下文：LLM 使用一个压缩提示词当压缩后的上下文被再次使用时，responses.create()会接收它并附带一个交接提示词 ，该提示词用于构建总结。两个提示词都可在源代码中查看。

对于 Codex 模型，CLI 转而调用 compact() API，该 API 返回一个 加密的二进制数据块 。我们不知道它是否在内部使用了 LLM，使用了什么提示词，或者是否存在交接提示词。

下面，我展示了一个简单的提示注入（2 次 API 调用，35 行 Python 代码）如何揭示 API 压缩路径确实使用 LLM 来总结上下文，其中包含其自身的压缩提示和一个交接提示被添加到总结的开头。这些提示与开源版本几乎相同。
