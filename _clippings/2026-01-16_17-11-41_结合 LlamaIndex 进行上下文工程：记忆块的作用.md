# 使用 LlamaIndex 进行上下文工程

**Tuana Celik (LlamaIndex):**
大家好，我是来自 LlamaIndex 的 Tuana。今天我要讲的是上下文工程（Context Engineering），具体来说，我将探讨在上下文工程中“记忆（Memory）”所扮演的角色。

当我们谈论上下文或上下文工程时，我们实际上是在谈论多种事物的协同工作，旨在为大语言模型（LLM）或智能体（Agent）形成最相关、最准确或最有效的上下文，从而为我们提供最有价值、最合理的答案。

这可能涉及提示词（Prompts）、工具（Tools）、记忆（Memory）等许多方面。在本次演示中，我将重点讨论记忆。

## 记忆块的类型

即便是在记忆这个范畴内，我们也有多种类型。过去几个月在 LlamaIndex，我们一直在引入不同类型的长期和短期记忆块。

我们今天主要讨论一种特定的记忆块，称为**工件记忆块（Artifact Memory Block）**。除此之外，你也可以使用其他类型的记忆块：

1.  **静态记忆块（Static Memory Block）：** 仅保存静态的、基本不变或极少变化的信息。
2.  **事实提取记忆块（Fact Extraction Memory Block）：** 适用于那些需要依赖最新事实来给出最相关答案的应用程序。
3.  **向量记忆块（Vector Memory Block）：** 这是一种提取过去对话或聊天消息的好方法，它能找出与当前对话最相关的内容。
4.  **工件记忆块（Artifact Memory Block）：** 这是我们要重点讨论的。它与事实提取记忆块有些相似，但它允许我们整合一个短期记忆组件，用于跟踪某种结构化的信息。

## 演示案例：披萨店订单助手

为了演示，我们将想象自己是一家餐厅或披萨店，我们要为顾客提供一个订单追踪机器人。顾客可以与这个机器人对话，但我们的主要目标是获取顾客想要下的最终订单。

你可以想象，虽然大部分对话内容可能仍然相关，但把**整个**聊天记录作为上下文保留下来其实并不是那么重要。真正关键的是提炼出几个核心信息点，例如：
*   披萨的种类
*   顾客想要添加或移除的配料
*   地址
*   等等

所以，话不多说，让我们开始构建一个使用工件记忆块（Artifact Memory Block）的智能体。我们还将定义保留多少比例的聊天记录，以及多少比例留给系统提示词和我们的工件记忆块。

我已经准备好了所有的导入和安装，并提供了我的 OpenAI API 密钥（这里我使用的是 OpenAI 模型，但你可以使用任何你选择的模型）。

我们要做的第一件事是定义想要用作短期记忆块的“工件”。

1.  **定义 Pizza 类：** 我们定义一个 `Pizza` 类。
2.  **定义 Address 类：** 接着定义一个 `Address` 类。
3.  **定义 Order 类：** 最后，定义我们要追踪的最终工件结果，即 `Order`（订单）。一个订单可以包含多个披萨，但只有一个地址。

对于我们要定义的每个类，我们都会为每个字段提供**描述（Description）**。这是额外的上下文，对大语言模型来说非常重要。当它浏览对话时，它将使用这些描述来决定对话中的哪些内容与该字段相关。例如，对话中的什么内容可以被分配给“披萨名称”这一字段。

## 设置工具与记忆块

定义好数据结构后，我们开始定义**工件编辑器工具（Artifact Editor Tool）**。这是我们的智能体在过程中用来编辑工件的工具。

然后，我们要定义记忆块：
*   我们将工具规范转换为智能体可用的工具列表。
*   我们定义一个记忆块，这里使用的是 `ArtifactMemoryBlock`，并传入我们上面定义的工具规范。
*   我们还可以定义上下文的比例。在这里，我设置了 **70%** 的上下文用于聊天记录（Chat History），而剩余的部分则专门留给系统提示词（让 LLM 理解其角色）和我们的工件记忆块。

然后我们定义订单追踪智能体。这里我使用的是 LlamaIndex 中的一个特殊类，叫做 **AgentWorkflow**。这个工作流能够处理多个功能智能体。

现在我们有了这个 Agent Workflow，我们可以创建一个非常简单的聊天循环。

逻辑很简单：除非用户输入 "exit" 或 "quit"，否则我们会持续运行智能体，并带上我们要追踪的工件和聊天记录。

# 演示互动

现在我们可以开始与订单追踪智能体聊天了。

**用户：** “我想要一个意大利辣香肠披萨（pepperoni）。”

**系统反应：**
你可以看到，它已经决定了工件的当前状态：
*   我们有一个意大利辣香肠披萨。
*   没有移除或添加任何配料。
*   目前还没有地址。

智能体的反应非常相关，它问道：“这是自取还是外送？”

**用户：** “外送。地址是纽约州纽约市 Elm 街 1 号，邮编 11111。另外我想加点橄榄。”（注：这里我有意在地址上胡编乱造，并测试它处理修改订单的能力）。

**系统反应：**
我们现在退出了与智能体的对话。因为我们从未定义何时“结束”订单，只定义了退出语句。但我们可以看到，它成功追踪到了它所需要的信息：
*   披萨名称：意大利辣香肠
*   添加配料：橄榄
*   地址：Elm 街 1 号等详细信息

我们成功做到了这一点，而且**没有**把整个冗长的聊天记录作为上下文让智能体去筛选，而是提供了一个工件记忆块来追踪具体的结构化对象。

# 总结：Agent Workflows

最后，关于上下文工程和 LlamaIndex，我想再提一点，那就是 **Agent Workflows（智能体工作流）**。

这实际上是一种让你在过程中构建上下文的方法。工作流允许你定义智能体采取的每一个步骤，无论是决策步骤、结果步骤还是中间的任何步骤。它让你能够完全控制智能体的行为。

这其实非常简单，你可以扩展一个类，定义你自己的“步骤（Steps）”和“事件（Events）”。一个步骤可以触发一个事件，也可以订阅一个事件。你可以可视化你的智能体编排。

屏幕上展示的是一个简单的工作流，但你可以拥有分支、循环等复杂的工作流。你可以想象，每一个步骤都在为上下文提供额外的信息，或者在优化上下文。
