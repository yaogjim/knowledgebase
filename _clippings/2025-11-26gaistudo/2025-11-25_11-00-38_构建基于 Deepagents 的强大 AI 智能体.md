我是来自 LangChain 的 Lance。今天我们来聊聊 **Deepagents**。

## 什么是 Deepagents？

Deepagents 是一个简单的开源 Agent 基础框架（Harness）。它实现了一些我们在许多流行 Agent（如 Manis 和 Claude Code）中看到的共同理念，主要包括：

*   **规划 (Planning)**
*   **计算机访问权限 (Computer Access)**
*   **子 Agent 委派 (Sub-agent Delegation)**

这个开源框架为你内置了这些工具，但同时也非常易于扩展。你可以提供自定义的提示词（Prompts）、自定义工具，而且它是完全开源的，你可以按需随意修改。

为了帮助大家开始使用 Deepagents 构建不同的应用程序，我们创建了 `deepagents-quickstarts` 代码仓库。其中包含针对不同用例的多个文件夹，首先从“研究 (Research)”开始，因为我们在研究领域已经做了很多工作，且这是一个非常流行的用例。

接下来，我会先展示它的运行效果，然后深入讲解其底层原理。

## 核心原理：内置工具 (Built-in Tools)

让我们深入了解一下。在仓库中，你可以看到针对研究用例的 `quickstart`。这是构建在 `deepagents` 包之上的。

如果你查看 `deepagents` 包的 README，有一点非常简单但也非常重要：**每一个 Deep Agent 都有几个内置工具可供使用：**

1.  **规划工具 (Planning Tool)**
2.  **子 Agent 委派工具 (Sub-agent Delegation Tool)**
3.  **各种文件系统工具 (Filesystem Tools)**
4.  **用户提供的工具和指令**

在 README 的表格中列出了所有开箱即用的内置工具，这些名称与我们在 Agent 轨迹中看到的完全一致：
*   `write_todos` / `read_todos`：用于规划。
*   `ls` / `read_file` / `write_file` / `edit_file`：文件系统操作。
*   `glob` / `grep`：文件搜索。
*   `execute`：执行 Shell 命令。
*   `task`：用于将工作委派给子 Agent。

这一组简单的原子工具让你可以做很多事情：与文件系统交互、调用 Shell 命令、通过待办事项（Todos）进行规划、以及通过 Task 工具委派任务。

你会发现这些工具与 Manis 或 Claude Code 中看到的非常相似。它们同样可以访问文件系统（Claude Code 通常是本地文件系统，Manis 是沙箱），拥有子 Agent 委派工具，并具备规划能力。这些是构建能够处理复杂任务的长运行 Agent 的基础要素。

## 快速入门：Deep Research 案例详解

理解了 Deepagents 包中内置的基础工具后，Quickstart 就很容易理解了。我们打开 `deep_research` 目录。

我们可以通过几种方式与这个 Quickstart 交互：
1.  运行 Jupyter Notebook（稍后展示）。
2.  在本地运行 LangGraph Server 并连接到 UI（如之前演示的那样）。

现在，让我们启动 Jupyter Notebook 来详细看看。

对于任何 Quickstart，我们都可以从四个方面来理解：

### 1. 理解原生工具 (Native Tools)
即我们刚才讨论的 Deepagents 内置工具（如规划、文件系统等）。

### 2. 提供特定任务工具 (Task-Specific Tools)
对于“研究”这个用例，我提供了两个特定的工具：
*   **Search Tool (搜索工具)**：使用 Tavily 搜索相关 URL 并获取网页内容。
*   **Think Tool (思考工具)**：这是一个完全可选的工具。我喜欢用它来进行审计。它只是一个让 Agent 调用的工具，用于强制进行“交替思考 (Interleaved Thinking)”。有些 SDK（如 Claude）内置了这个功能，但并非总是如此。这是一个显式告诉 Agent 在步骤之间进行思考的好方法。

注意：Think Tool 实际上并不执行任何操作，它只是强制 Agent 暂停并产生一个反思（Reflection）。

### 3. 提供特定任务指令 (Task-Specific Instructions)
提示工程（Prompting）并没有消亡，它在 Agent 中仍然非常重要且充满技巧。我在代码中添加了一些我常用的提示技巧：

*   **像 Agent 一样思考 (Think Like The Agent)**：你会给新同事什么指令？例如：仔细阅读问题，从广泛搜索开始，暂停并评估是否获得足够信息，然后执行更窄的搜索来填补空白。
*   **具体的启发式方法 (Concrete Heuristics) - 防止“空转” (Spin-out)**：
    *   使用硬性限制 (Hard Limits) 防止 Agent 过度调用工具。
    *   例如：当你可以自信地回答时就停止；不要追求完美；给它预算（Budget），比如“简单查询使用 2-3 次搜索调用，复杂查询最多 5 次”；如果在 5 次搜索后仍未找到正确来源，必须停止。
    *   我曾见过 Agent 即使已经收集了足够的信息，仍不停地进行搜索以优化结果，因此这些防止“空转”的启发式方法非常有用。
*   **展示你的思考 (Show your thinking)**：要求 Agent 在每次搜索工具调用后使用 `think_tool` 来分析结果。

### 4. 提供特定任务子 Agent (Task-Specific Sub-Agents)
Deepagents 的 `task` 工具可以将任务委派给子 Agent。为什么要这样做？主要是为了**上下文隔离 (Context Isolation)**。

研究任务通常非常消耗 Token。如果你想研究一个特定的问题，将其委派给一个子 Agent，让它去进行大量搜索、学习大量信息，然后只把**结果**传回给主 Agent。这是一种很好的方式，可以将研究任务中收集的所有上下文隔离在子 Agent 的上下文窗口中。

在代码中，我们可以定义一个名为 "research-agent" 的子 Agent，给它描述和指令（复用之前的研究者指令），并赋予它工具。

## 整合与中间件 (Middleware)

最后，我们将所有内容整合到一起：工作流指令（Workflow Instructions）、子 Agent 委派指令和研究者指令。

这里有一个有趣的概念：**中间件 (Middleware)**。

初始化 Deep Agent 非常简单：
```python
agent = create_deep_agent(model=..., tools=..., checkpointers=..., middleware=...)
```

Deepagents 抽象了一套内置的默认原子工具，但你也需要考虑你的提示词和中间件。中间件实际上是 LangGraph 中的一些组件，用于编排 Agent 循环。

Agent 循环很简单：LLM -> 调用工具 -> 循环。但你通常希望在这个循环的特定点停下来做些事情。中间件就像是“钩子 (Hooks)”。

在 Deepagents 的 README 中，我列出了使用的中间件及其作用：
*   **TodoListMiddleware / FilesystemMiddleware / SubAgentMiddleware**：这些中间件实际上是向 Agent **提供工具**。例如，文件系统中间件提供了 `ls`, `read_file` 等工具。
*   **SummarizationMiddleware (摘要中间件)**：这就更像是一个钩子。它会在模型调用之前运行。如果上下文超过了 170,000 个 Token（针对 Anthropic 模型配置），它会自动对消息历史进行摘要，类似于 Claude Code 中的压缩机制。
*   **PatchToolCallsMiddleware**：修复悬空的工具调用。
*   **HumanInTheLoopMiddleware**：可以在不同步骤暂停执行以等待人工批准。

## 执行流程与状态管理

现在我们在 Notebook 中运行它。

你可以看到 Agent 根据指令：
1.  使用 `write_file` 将用户的研究请求保存到文件（`research_request.md`）。
2.  使用 `write_todos` 创建研究计划。
3.  使用 `task` 工具委派任务给子 Agent。

**关键点：文件系统与内存状态**
当看到 `write_file` 时，你可能会问：这是写到我的本地文件系统了吗？
默认情况下，Deepagents 只会写入**内部的内存状态对象 (Internal In-memory State Object)**。

Deepagents 基于 LangGraph 构建，LangGraph 有状态对象的概念。它可以将文件写入状态，并从状态中读回。这在 Agent 执行期间保存在内存中。这实际上是一种**复述 (Recitation)** 模式：将请求写入状态，做一系列操作，然后再读回来确认是否解决了请求。这是一种引导 Agent 并确保其保持正轨的好技巧（Manis 也常提到这点）。

当然，Deepagents 支持不同的后端。如果你想让它真正访问文件系统或沙箱，你可以通过配置来实现（视频描述中会提供文档）。

在演示中，子 Agent 完成任务后，将整个研究产出返回给了父 Agent。父 Agent 更新了 Todo 列表，最后基于子 Agent 的研究结果编写了 `final_report.md`，并进行了验证。

因为底层使用的是 LangGraph，所有的过程都被 **LangSmith** 记录了下来。你可以打开 Trace，查看每一个工具调用、每一个模型调用（例如我们使用的是 Claude Sonnet 3.5），这提供了完整的可视化轨迹。

## 部署应用程序

除了在 Notebook 中运行，你还可以作为一个可部署的应用程序来运行。

只需在目录下运行：
```bash
uv run langgraph dev
```
这将启动一个本地 LangGraph 服务器。你可以使用内置的 Studio 界面，也可以将其连接到我在开头展示的 Deep Agent UI。README 中包含了连接所需的所有代码。

## 总结

Deepagents 是一个开源的 Agent 基础框架，它集成了规划、计算机访问、子 Agent 委派等强大的通用工具。它不仅为你实现了这些底层能力（如中间件处理摘要、工具集），还允许你通过自定义提示词、工具和子 Agent 轻松地适配你的特定用例。

希望这个概述对你有帮助。所有代码都是开源的，欢迎大家尝试、修改并贡献代码。谢谢！
