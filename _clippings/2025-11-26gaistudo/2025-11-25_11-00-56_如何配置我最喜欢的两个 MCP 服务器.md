# 如何配置我最喜欢的两个 MCP 服务器：Ref.tools 与 Exa.ai 打造高效 AI 编程工作流

**YouTube 视频地址:** https://www.youtube.com/watch?v=FqY9d14_bng

我要向大家展示如何设置我最喜欢的两个 MCP（Model Context Protocol，模型上下文协议）工具：**Ref.tools** 和 **Exa.ai**。

我之所以选择 Ref.tools 而不是其他用于搜索文档的 MCP，原因在于解决“**上下文腐烂**”（Context Rot）的问题。

### 什么是上下文腐烂？

当大语言模型（LLM）在试图帮助你处理信息时突然变得“很蠢”，这就是上下文腐烂。如果你不知道的话，当你使用语言模型时，它们的所有训练数据都有一个截止日期。这就是为什么我选择这两个特定的 MCP 服务器，因为它们最高效。

如果你以前使用过其他 MCP 服务器，你会发现文档会突然塞满你的上下文窗口，消耗大量的 Token。我以前就是这样，仅仅为了喂给 AI 新的 SDK 文档、认证方式、数据库提供商等规则，就要消耗近 10 万个 Token。

但实际上，当 LLM 拥有**恰到好处的信息**来完成**恰到好处的特定任务**时，它们的表现才是最好的。

### Ref.tools 介绍

Ref.tools 此时就派上用场了。它为这些 AI 代理提供了实际所需的上下文。

它的工作原理是抓取公共文档以及你提供的任何私有文档（如 PDF、GitHub 仓库等），建立索引，并在 Claude Code、Droid、Codex 和 Cursor 中提供这些信息。我们今天将涵盖这四个工具的安装。

很多时候，当进行工具调用（Tool Calling）时，会产生多个请求和步骤。Ref.tools 专为这种代理式搜索而设计，这样它就不会因为大量的文档内容而“杀死”你的上下文窗口。

### Exa.ai 介绍

结合 Exa.ai，它为特定的编程任务提供了极其高质量且快速的搜索功能。如果你将这两个工具结合起来，你的效率将大幅提升。

我已经使用这两个 MCP 服务器在“计划模式”（Plan Mode）下发布了许多功能。它们帮助收集正确的上下文，等到 AI 编写代码时，就好像雇佣了几位开发者先阅读文档，然后为你实现代码一样。

### 第一步：在 Claude Code 中配置 Ref.tools

Ref.tools 让配置变得非常简单。

1.  注册账号后，进入 MCP 页面。
2.  在 **Claude Code** 部分，你会看到通过命令行安装的指令。
3.  复制包含 API Key 的命令。
4.  打开终端，粘贴并运行该命令。

终端会显示“Added MCP MCP server with Ref...”，这意味着 API Key 已经添加到了本地配置中。

**验证安装：**
在终端运行 `claude` 进入 Claude Code，然后输入 `/mcp`。你会看到 Ref.tools 已经连接成功。或者你可以运行 `claude mcp list` 来查看当前活跃的 MCP 服务器列表。

*注意：由于这是在你的根用户下配置的，它将适用于你启动的任何新项目，不需要为每个项目单独添加。另外，切记不要将含有 API Key 的配置文件作为代码提交到公共仓库。*

### 第二步：在 Claude Code 中配置 Exa.ai

接下来配置 Exa。

1.  Claude Code 的安装命令是 `claude mcp add exa ...` 加上你的 API Key。
2.  你需要去 Exa 的 API 仪表盘生成一个新的 API Key。
3.  复制 Key，在终端命令中替换掉占位符，然后运行命令。
4.  同样，它会提示已添加到本地配置。

现在，如果运行 `claude mcp list`，你应该能看到 Ref 和 Exa 都已连接。

### 实战演示：使用 Claude Code 升级 Tailwind v4

我们可以使用 Claude 4.5 甚至是速度更快的 Haiku 模型来测试。

**任务：** 我想让 AI 检查我的代码库（一个名为 Anime Leak 的应用），看看是否可以利用最新的 Tailwind v4，并查找所有硬编码的地方，以便统一设计系统。

**Prompt（提示词）：**
> "我希望你先使用 Ref 和 Exa MCPs 阅读文档，了解这种类型的系统是如何工作的，并通读我代码库的所有不同部分，以了解当前的设计系统。我们应该将 Tailwind v4 与 shadcn 以及整个系统的目的结合使用……"

Claude Code 会开始执行：
1.  它会搜索并研究 Tailwind v4 的设计令牌（Design Tokens）和系统。
2.  它会利用 Ref 文档搜索来获取关于 CSS 变量和自定义令牌的具体信息。
3.  它会在不消耗大量 Token 的情况下，只抓取所需的信息进行模式匹配。

这比单纯的网页搜索要高效得多，因为它不会用无关信息淹没上下文窗口。

### 第三步：在 Cursor 中配置

接下来，我们在 Cursor 编辑器中配置这些。

1.  点击 Cursor 的设置齿轮图标。
2.  找到 **Tools & MCP** 部分。
3.  点击 **Add Custom MCP Server**（添加自定义 MCP 服务器）。

**添加 Ref.tools：**
*   回到 Ref.tools 网站，找到 Cursor 的部分，它会提供一个 JSON 配置文件链接或内容。
*   在 Cursor 中，你可以直接点击“Install”（如果通过链接）或者手动填入名称、类型（SSE 或 Stdio）和 URL（包含 API Key）。

**添加 Exa.ai：**
*   这步稍微复杂一点。回到 Exa 仪表盘，找到 Exa MCP 的配置 JSON。
*   你需要复制 `mcpServers` 下面的 `exa` 部分。
*   **注意：** 这里的配置通常包含 `env` 环境变量部分来存放 API Key。你需要将你的 Exa API Key 填入其中。
*   在 Cursor 中添加时，确保格式正确。

配置完成后，确保两个 MCP 服务器旁边的开关是绿色的（已启用）。

### 实战演示：Cursor 的“计划模式” (Plan Mode)

这是 Cursor 的一个杀手级功能。按下 `Command + E`（或者在设置中启用），你会进入一个专门的代理窗口——**Plan Mode**。

在这个模式下：
1.  输入同样的提示词（升级 Tailwind v4）。
2.  Cursor 会开始分析，并在侧边栏的专用窗口中展示它的思考过程。
3.  你会看到它正在执行工具调用：`mcp_exa_web_search`，`mcp_ref_search_documentation` 等。
4.  它会先进行研究，然后制定一个详细的实施计划（例如：第一阶段统一设计令牌，第二阶段提取组件令牌等）。

**Token 效率惊人：**
在这个演示中，为了完成这个庞大的重构任务分析，它只消耗了不到 3000 个 Token（仅占上下文窗口的 1.4%）。这就是高效 MCP 的威力。

### 第四步：在 Codex (和 Droid) 中配置

如果你使用 Codex 或 Droid Factory，配置方式类似，通常是通过编辑配置文件。

1.  在 Codex CLI 文档中找到安装指南。
2.  它通常是在 `config.toml` 文件中配置。
3.  你需要将 JSON 格式的配置转换为 TOML 格式。
4.  对于 Ref.tools，复制提供的 TOML 配置并将 API Key 填入。
5.  对于 Exa，你需要手动构建 TOML 条目，确保包含 URL 和 API Key。

**示例 TOML 配置结构：**
```toml
[mcp_servers.ref]
command = "..."
# 或者如果是 HTTP/SSE 类型
url = "https://api.ref.tools/..."
headers = { "x-ref-api-key" = "你的KEY" }

[mcp_servers.exa]
url = "https://..."
headers = { "Authorization" = "Bearer 你的KEY" } # 具体看文档要求
```

保存 `config.toml` 后，在终端运行 `codex mcp list` 确认加载成功。

### 总结

当你必须在代码中明确调用这些工具时（例如在 Prompt 中说“使用 Ref MCP 查找...”），效果会显著提升。

在计划模式下工作时，记得使用 `Shift + Tab` 切换到正确的模式，并明确指示代理使用这些工具来收集上下文。

这就是 AI 编程的新时代。我们才刚刚开始。通过使用 Exa 和 Ref 这样的工具，你可以保持 LLM 的高智商，同时用最新的外部数据填补它们的知识空白，而不需要手动去查阅每一页文档。这不仅节省了时间，还让你的 AI 助手变得更加强大。
