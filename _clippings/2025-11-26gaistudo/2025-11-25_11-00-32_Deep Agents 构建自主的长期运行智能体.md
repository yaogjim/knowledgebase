## 什么是深度智能体 (Deep Agents)？

大家好，我是 Lance。我想和大家聊聊我们最近发布的 **Deep Agents**（深度智能体）开发包。

现在的智能体能够承担的任务时长大约每 7 个月就会翻一番。我们已经看到了许多流行的、能够长期运行的智能体案例，比如 Claude Code、Deep Research 和 Manus。以 Manus 为例，它执行一项任务平均可能包含多达 50 次不同的工具调用。

情况已经越来越清楚，智能体需要从事我们可以称之为“深度工作（Deep Work）”的任务，也就是那些耗时更长、更具挑战性的任务。因此，我们提出了“Deep Agents”这个术语。

## Deep Agents 包的核心内容

当我们观察像 Manus 或 Claude Code 这样的智能体时，会发现一个有趣的现象：它们实际上并没有使用那么多五花八门的工具。相反，它们专注于使用少量**原子工具（Atomic Tools）**，这些工具虽然基础，但能执行非常强大的操作。

Deep Agents 包主要包含以下 4 个关键要素：

1.  **文件系统与计算机访问权限**：最显著的特点是能够访问文件系统和计算机。这通常通过文件操作工具以及用于执行脚本的 **Bash** 或 **Shell** 工具来实现。这对于在长期的智能体运行轨迹中“卸载（offloading）”上下文，以及通过脚本执行来完成各种动作都极其有用。
2.  **规划能力 (Planning)**：长期运行的智能体通常都需要某种形式的规划。Claude Code 和 Manus 都有各自的规划工具。
3.  **子智能体 (Sub-agents)**：它们都使用子智能体来进行**上下文隔离（Context Isolation）**。如果有特定的任务，父智能体可以生成一个拥有独立上下文窗口的子智能体来执行该任务，并将结果返回给父智能体。这是一种保护父智能体上下文窗口的极佳方式。
4.  **提示工程 (Prompts)**：在所有这些案例中，提示工程仍然至关重要。例如，Claude Code 的系统提示词是公开的，且非常长和详尽。

总结来说，这套方案利用少量原子工具（子智能体委托、规划、文件系统/Shell 访问）来覆盖广泛的操作，并由详细的提示词进行引导。

## Deep Agents 与 LangChain 和 LangGraph 的区别

由于这些工具非常通用，我们将它们整合进了 **deepagents** 包中，它是完全开源的。那么它与 LangChain 和 LangGraph 有什么不同呢？

*   **LangGraph (智能体运行时)**：提供底层的智能体运行时（Runtime）基础设施。它处理检查点（Checkpointing）、记忆（Memory）、人机交互（Human-in-the-loop）、持久化、流式传输等功能。
*   **LangChain (框架)**：提供通用的抽象层，例如用于访问聊天模型、定义工具的接口。
*   **Deep Agents (智能体框架套件)**：这是一个构建在上述两者之上的、**观点鲜明的智能体框架套件（Opinionated Agent Harness）**。它实现了一组特定的预定义工具（如前所述的规划、子智能体委托、文件系统操作、代码执行），并通过特定的提示词策略来管理这些工具的使用。

| 特性 | LangChain | LangGraph | Deep Agents |
| :--- | :--- | :--- | :--- |
| **定义** | 框架 (Framework) | 运行时 (Runtime) | 框架套件 (Harness) |
| **价值** | 抽象 (Abstractions) | 持久执行、流式、人机交互、持久化 | 预定义工具、提示词、子智能体 |
| **适用场景** | 快速上手，标准化团队构建方式 | 需要底层控制、长期运行、有状态 | 构建更自主的、长期运行的工具循环智能体 |

## 为什么现在关注 Deep Agents？

智能体正迅速变得更加自主。Deep Agents 旨在帮助我们为这种未来做好准备。在使用 Deep Agents 时，有几个最佳实践原则：

1.  **将复杂性放入提示词中**：模型的能力越来越强。鉴于这套原子工具非常通用（Shell、文件操作、规划），通常将应用程序的复杂性转移到提示词（Prompting）本身会更有益。我们看到越来越多的趋势是使用一组精简的工具，配合高度复杂的指令。
2.  **充分利用文件系统**：
    *   **上下文卸载**：文件系统不仅可以用来从 LLM 的上下文窗口中卸载信息（例如写入一个计划，稍后再读取）。
    *   **脚本存储 (Skills)**：文件系统还可以用来存储智能体可以使用的脚本。这类似于 "Claude Skills" 的概念。你可以给智能体一个包含不同技能脚本的目录，它可以通过 Bash 工具随时调用这些脚本。

通过访问计算机（文件系统 + Bash 工具），智能体可以执行极其广泛的动作。同时，子智能体委托对于处理那些 Token 消耗量大、最好在独立上下文中隔离的任务也非常有用。

## 最新发布：Deep Agents CLI 与 0.2 版本

我们刚刚发布了 **Deep Agents CLI**（命令行界面）和 **Deep Agents 0.2** 版本。

*   **Deep Agents CLI**：允许你直接在终端中运行自定义的 Deep Agent。这就像在本地运行 Claude Code 一样，智能体可以直接访问你的本地文件系统。
*   **Deep Agents 0.2 (可插拔后端)**：这个版本引入了可插拔后端。你不再局限于使用虚拟文件系统（即 LangGraph State 对象），而是可以直接使用你的**本地文件系统**。
*   **中间件 (Middleware)**：Deep Agents 内置了有用的中间件（可以理解为钩子 Hooks），用于在智能体生命周期的特定点运行代码：
    *   **上下文压缩**：当消息列表过长时，自动进行摘要压缩。
    *   **工具处理程序**：用于处理文件系统工具和子智能体工具的逻辑。
    *   **提示词缓存 (Prompt Caching)**：支持缓存输入 Token，这是降低延迟和成本的有效手段。

**Deep Agents CLI** 的核心功能包括：
*   读取、写入和编辑项目中的文件。
*   在获得批准后执行 Shell 命令。
*   搜索网络获取最新信息。
*   跨会话的持久记忆。

总而言之，Deep Agents 是一个构建在 LangChain 和 LangGraph 之上的、观点鲜明的智能体框架套件。它内置了长期运行智能体所需的关键工具（规划、子智能体、文件系统、Shell），并支持通过 MCP（模型上下文协议）添加自定义工具。该项目完全开源，欢迎大家通过 CLI 试用并提供反馈。
