# 什么是 Claude Skills？

官方的定义是：Skills 是指令、脚本和资源的文件夹。Claude 会动态加载这些文件夹，以提高其在专业任务上的性能。

这里面其实有一个比较重要的特点，就是 Skills 会教会 Claude 如何以**可重复的方式**来完成特定的任务。所以我们可以把 Skills 的定义简化为一个**“可复用的指令包”**。

因此，很多人听到 Skills 的第一反应就是：“这不就是一个保存 Prompt 的地方吗？”

这句话没错，但是完全没有体现出 Skills 厉害的地方。对我来说，更准确的一个理解应该是：**Skills 可以让你把你自己的判断逻辑和处理流程，写成一个 Claude 能反复执行的模块。**

## Skills 的结构

我们来看一个具体的 Skill 的结构。

这个 Skill 就是一个文件夹，里面有一个核心的 `SKILL.md` 的 Markdown 文件。它会用 Markdown 的格式写清楚这个 Skill 要解决什么问题。

所以从本质上来说，`SKILL.md` 这个 Markdown 文件，它实际上就是我们的**系统提示词（System Prompt）**。

比如，我们完全可以用一个最简单的 Prompt 来创建一个 Skill，例如“把英文翻译成中文”。只要这一个 `SKILL.md` 文件，一句话，它就可以当做一个 Skill 来使用。所以 Skills 本身来说，入门是非常之简单。

Skill 这个文件的重点，是它的**名称**和它的**描述**。因为 Claude 是根据名称和描述来判断什么时候来调用这个 Skill 的，所以描述一定要写清楚。

除了它的主文件 `SKILL.md`，它还有一些可选的资源文件，比如固定的模板、参考文档、示例，甚至会有一些脚本代码。

# Skills 与 Prompt 的本质区别

你可能会想：“我可以写一个很长的 Prompt，把判断标准、流程步骤、注意事项全部都写进去，让 AI 每次来照着做。那这和写 Skill 有什么区别呢？”

这个问题非常好。确实，从内容的复杂度来说，Prompt 和 Skill 没有本质的区别。你完全可以写一个两三千字的 Prompt，把它当成一份迷你的工作说明书来使用。

但是，真正的差别在于它们的**形态**和**生命周期**。

*   **Prompt（一次性）：** Prompt 是一次性的对话内容。你需要自己保存，自己复制粘贴。模型不会知道什么时候该用哪一个长的 Prompt。而且，你一次要把 Prompt 全部塞到上下文里边，这会大量的占用你的模型的上下文空间。
*   **Skills（工程化）：** Skills 是把同样的东西换了一种更工程化的包装方式。它是一个文件夹，在 Claude 启动的时候，它**只会加载名字和简介**。只有觉得相关，才会把完整的内容给读进来。这就是 Skills 的一个很重要特性，叫做**渐进式披露（Progressive Disclosure）** / 渐进式加载。

同一个 Skill 本身就是一个纯文本的文件夹，你可以在不同的对话、不同的产品当中复用，也可以把它进行版本管理，跟团队的同事一起来进行共享和协作。

所以你也可以理解为，Skill 不是写出了更复杂的 Prompt，而是把复杂的 Prompt 变成了一个**有结构、可复用、可以自动调用的模块**。

这就是为什么我很看重 Skills。它把我们过去靠“人肉维护”的 Prompt 库，升级成了一套可以被 Claude 主动使用的判断和流程的资产。这也是我在 MAPS 思维框架当中，在架构设计部分强调的一个核心原则——**资产化**。

**什么是资产化？** 就是把你的个人技巧、隐形的知识，转换成一个可以规模化的数字资产。这里的重点是：**你的知识 + 规模化**。

# 两种核心使用模式

Skills 有很多种用法，今天我会重点展示两种：
1.  **能力包型**：用来封装判断逻辑和处理规则。
2.  **软编排型**：用来协调多个子智能体（sub-agents）协作。

## 案例 1：能力包型（discussion-organizer）

这种 Skill 的特点是它会封装一整套的判断逻辑和处理规则。Claude 读取后，就会按照你定义好的这些规则来执行，它不会去调用其他的 Agent。

**场景：** 整理我的学习笔记和讨论记录。这些记录里有一些非常有价值的信息，如果人工整理非常耗时。

**Skill 逻辑（四层判断）：**
1.  **价值判断**：评估每一条讨论是核心洞察、有用的补充，还是无价值的信息。
2.  **可信度判断**：对于提到的论点和观点进行验证，看是否有官方文档或数据支持。
3.  **提取粒度**：决定是直接引用原话，还是只需要记录主题。
4.  **措辞风格**：根据需求把口语化转换为书面语等。

**执行过程：**
我在 Claude 中直接上传笔记文件，并要求它整理。Claude 根据我的要求识别出需要调用 `discussion-organizer` 这个 Skill。在整理之前，它会先进行需求确认（这是我们在 Skill 里定义的）。确认后，它会按照我们在 `SKILL.md` 里定义的逻辑和提供的参考模板（按需加载），生成符合 TBRC 框架（Topic, Boundary, Runner, Closure）的知识库文档。

这就是典型的能力包型 Skill。它封装了复杂的判断逻辑，而这些逻辑来自于你的知识和经验。

## 案例 2：软编排型（SRT Workflow）

**注意：** 这种模式主要推荐在 **Claude Code**（命令行环境）里使用，因为 Web 版不支持 Task 工具编排。

**场景：** 将视频的 SRT 字幕文件转换为一篇结构化的文章。

**Skill 逻辑（四阶段 SOP）：**
这个任务不是由一个 Skill 自己干活，而是定义了一个四阶段的标准操作流程（SOP），每个阶段由一个独立的 **sub-agent（子智能体）** 完成。
1.  **字幕分段 (Segmenter)**：将一行行的字幕转换为段落格式。
2.  **分段审查 (Reviewer)**：针对语音识别错误进行校对，AI 提供修改建议（可能会调用 Web Search 进行验证）。
3.  **内容定稿 (Finalizer)**：根据修改建议生成最终文章。
4.  **翻译 (Translator)**：如果是英文内容，则翻译成中文。

**执行过程：**
主 Claude (Claude Code) 就像一个项目经理。它读取 Skill 中定义的流程，然后使用 **Task 工具** 按顺序调度 sub-agents。每个 sub-agent 都有自己的上下文窗口、工具白名单和判断标准。sub-agents 之间通过文件来传递上下文，不走主 Claude 的上下文。

最终，它将 SRT 字幕转换成了一篇带段落的文章。

# 使用限制与边界

1.  **付费门槛**：使用 Skills 的前置条件是你必须是付费用户。
2.  **权限要求**：必须打开代码执行（Code Execution）权限。因为 Skills 依赖文件系统工具和代码执行能力。这也意味着有一定的风险，所以应尽量只使用可信来源的 Skills。
3.  **跨平台不同步**：你在 Web 端上传的 Skills 不会自动同步到 Claude Code (CLI) 或 API，需要自己管理（建议本地文件管理）。
4.  **触发机制**：Claude 是根据 Skills 的描述（Description）来决定是否调用的。描述不清晰或多个 Skills 描述过于接近，可能导致调用错误。必要时可以手动指定 Skill 名称。
5.  **并发限制**：软编排中并行的 sub-agents 最多 10 个。
6.  **不适用场景**：
    *   一次性任务。
    *   非常简单的指令。
    *   需要精确控制后端服务的硬流程（这种情况更适合用 Make 等自动化平台）。

# 从 MAPS 框架看 Skills 的价值

我们可以用我的 MAPS 框架（Mindset, Architecture, Prompt, Systems）来审视 Skills：

*   **Mindset（心智）**：这是从写 Prompt 到“资产化”的过程。把隐性知识显性化、模块化。
*   **Architecture（架构）**：Skills 是连接 Prompt 和 Agent 的中间层。通过软编排，把任务的说明过程（流程）和执行过程分离。
*   **Prompt（提示工程）**：Prompt 不再是临时的指令，而是封装在 Skills 里的规范。利用“渐进式披露”节省 Token。
*   **Systems（系统）**：Skills 不是孤立的，具有可组合性。它可以和 MCP 工具结合，Skills 之间也可以互相调用。

这就是为什么我说 Skills 有机会改变 Agent 的格局。它提供了一套从 Prompt 到 Agent 的中间层抽象。

# 如何快速上手？（5A 框架）

我们可以跟着 5A 框架（Aim, Acquire, Attempt, Adjust, Apply）来行动。

1.  **Aim（瞄准需求）**：明确你有哪任务是重复的？哪些任务包含复杂的判断逻辑？把这些任务作为起点。
2.  **Acquire（获取/安装）**：
    *   **桌面端/Web端**：Settings -> Capabilities -> Skills -> Upload Skill (上传 ZIP 压缩包，扩展名改为 `.skill` 或保持 `.zip`)。
    *   **Claude Code**：将 Skill 文件夹复制到用户根目录下的 `.claude/skills` 文件夹中。
3.  **Attempt（尝试创建）**：
    *   **方法一（推荐）**：使用 **`skill-creator`**。这是官方提供的一个 Skill，专门用来创建 Skill。你只需要用自然语言描述需求（比如“帮我做一个把英文翻译成中文的 Skill”），它会自动生成规范的文件结构、YAML 配置和 Markdown 内容。零学习成本。
    *   **方法二**：使用官方或社区现成的 Skills（链接见视频描述）。
    *   **方法三**：手写 Markdown 和 YAML（适合复杂场景）。
