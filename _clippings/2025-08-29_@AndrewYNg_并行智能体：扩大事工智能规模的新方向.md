**Andrew Ng** @AndrewYNg [2025-08-28](https://x.com/AndrewYNg/status/1961118026398617648)

  
并行智能体正在成为扩大人工智能规模的一个重要新方向。人工智能的能力随着更多的训练数据、训练时的计算资源以及测试时的计算资源而得到提升。让多个智能体并行运行正日益成为一种进一步扩大规模并提高性能的技术。

我之前的团队在百度的工作，以及后来 OpenAI 的工作让我们了解到，人工智能模型的性能会随着数据量和训练计算量的增加而可预测地提升。在诸如智能体工作流程以及能够思考、反思并对答案进行迭代的推理模型等测试时计算中，性能会进一步提高。但这些方法生成输出的时间更长。并行工作的智能体提供了另一条改善结果的途径，而无需让用户等待。

推理模型按顺序生成令牌，运行时间可能很长。同样，大多数智能体工作流程最初都是以顺序方式实现的。但是随着 LLM 每令牌价格持续下降——从而使这些技术变得可行——并且产品团队希望更快地向用户交付结果，越来越多的智能体工作流程正在被并行化。

一些示例：

\- 现在，许多研究智能体并行获取多个网页并检查其文本，试图更快地合成深度思考的研究报告。

\- 一些代理编码框架允许用户编排多个代理，使其同时处理代码库的不同部分。我们关于 Claude Code 的短期课程展示了如何使用 git 工作树来做到这一点。

\- 一种迅速发展的智能体工作流设计模式是，让一个计算量较大的智能体工作数分钟或更长时间来完成一项任务，同时另一个智能体监控第一个智能体，并向用户提供简短更新以使其了解情况。由此，很容易发展到并行智能体，它们在后台运行，而用户界面智能体让用户了解情况，或许还会将异步用户反馈路由到其他智能体。

对于人类管理者来说，很难将一项复杂任务（比如构建一个复杂的软件应用程序）分解成较小的任务，让人类工程师并行处理；扩展到大量工程师尤其具有挑战性。同样，为并行智能体分解任务以执行也很有挑战性。但是大语言模型（LLM）推理成本的下降使得使用更多的令牌变得值得，并且并行使用它们可以在不显著增加用户等待时间的情况下完成任务。

关于并行智能体的研究不断增加，这也让我备受鼓舞。例如，我很喜欢阅读瑞安·埃利希等人撰写的《代码猴子：扩展软件工程的测试时计算能力》，它展示了并行代码生成如何帮助探索解决方案空间。王君林提出的智能体混合架构是一种组织并行智能体的惊人简单方法：让多个大语言模型（LLMs）给出不同答案，然后让一个聚合大语言模型（LLM）将它们整合为最终输出。

在如何最好地利用并行智能体方面，仍有大量研究和工程工作有待探索，而且我相信能够并行高效工作的智能体数量——就像能够并行高效工作的人类一样——将会非常多。
