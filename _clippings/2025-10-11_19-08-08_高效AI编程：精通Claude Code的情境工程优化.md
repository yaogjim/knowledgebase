### 高效AI编程：精通Claude Code的情境工程优化

随着代码库日益复杂，如何确保AI编程助手（如Claude Code）能够持续高效地工作，而不是陷入循环往复的困境，让开发者感到沮丧？答案在于优秀的情境工程（Context Engineering）。通过精细化管理和优化提供给AI的上下文信息，我们可以显著提升其性能。

### 情境工程：优化AI的“记忆”

情境工程的核心在于优化输入到AI对话历史线程中的内容，确保只有相关且必要的信息被包含在内，从而引导AI的下一步行动。像Claude Code这样的编码AI拥有高达200k（二十万）令牌（token）的上下文窗口，这为我们提供了巨大的操作空间。

通过在Claude Code中运行`/context`命令，可以获得一个详细的令牌消耗分解报告。这份报告将上下文分为几个关键部分：
*   **System Prompt (系统提示) 和 System Tools (系统工具):** 这些是AI自带的固定部分，用户无法更改。
*   **MCP Tools (元认知提示工具) 和 Custom Agents (自定义代理):** 用户自定义的工具和代理，是可优化的部分。
*   **Memory Files (记忆文件):** 通常指`CLAUDE.md`文件，随着项目变大，它可能消耗大量令牌。
*   **Messages (消息):** 用户与AI之间的实际对话和工具调用历史。

优化的目标是减少不必要的令牌消耗，为真正重要的对话内容留出更多空间。例如，通过移除当前任务不需要的MCP工具或自定义代理，可以立即释放一部分上下文窗口。

### 优化策略一：利用子代理（Sub-agents）分解任务

子代理是减少主对话线程上下文消耗的强大工具。当AI需要执行一个复杂的任务时，例如“帮我添加Google认证”，其中大部分操作并非直接修改代码，而是进行研究以确定最佳实施方案。这些研究步骤，如搜索、网页抓取和阅读文档，会产生大量的对话历史，迅速填满上下文窗口。

通过子代理，我们可以将研究任务完全委托出去。主代理只需向子代理发出一个高级指令，如“请研究如何添加Google认证”。子代理将在其独立的对话环境中完成所有研究步骤，然后仅将最终的总结（Summary）返回给主代理。这样，主对话线程中只保留了简洁的任务指令和关键的研究结论，极大地节省了上下文空间，让AI能更专注于核心的编码任务。

为了触发这种行为，开发者可以在提示中明确指出，例如：“帮我添加Google认证，**请先使用任务（Task）或子代理（sub-agent）进行研究**”。此外，在AI完成一个相对独立的任务（如研究）后，可以主动使用`/compact`命令来压缩和清理对话历史，只保留关键行动的摘要。

### 优化策略二：构建可扩展的文档系统（Doc System）

最有效、最根本的优化方法是为你的代码库建立一个专门的AI文档系统。这个系统的目的是创建一个代码库的“摘要快照”，让AI不再需要每次都从头扫描整个项目来寻找信息。当需要实施新功能时，AI可以直接读取相关的、高度浓缩的文档，从而减少噪音，确保所有关键信息都被纳入考虑。

一个行之有效的文档结构是在项目根目录下创建一个`.agent`文件夹，其中包含：
*   **Tasks (任务) 文件夹:** 存放每个功能的产品需求文档（PRD）或实施计划。在开始任何功能开发前，先用计划模式（plan mode）让AI生成详细的实施计划并保存于此。
*   **System (系统) 文件夹:** 存放关于项目整体的文档，如项目结构、数据库模式（schema）、API端点等跨越多个独立功能的系统级信息。
*   **SOP (标准操作程序) 文件夹:** 记录执行特定任务的标准流程和过去AI曾犯过的错误。例如，集成一个新的数据库表或添加路由的具体步骤。当AI成功完成一项任务或修正一个错误后，可以要求它生成对应的SOP，以备将来参考，避免重蹈覆辙。
*   **README.md 文件:** 作为整个文档系统的索引，清晰地列出所有可用的文档及其路径和用途。

为了维护这个系统，可以创建一个名为`update-doc.md`的自定义命令。该命令包含一组指令，指导AI如何在不同情况下（如初始化文档、更新文档、创建新文档）与这个文档系统进行交互。例如，每次完成一个新功能后，运行`update-doc`命令，AI会自动更新相关的SOP、PRD，并刷新根目录的`README.md`索引。

### 实践案例与社区智慧

在一个实际演示中，开发者首先使用`update_doc init`命令，让AI扫描新项目并自动生成初始的`.agent`文件夹结构，包括项目架构文档和`README.md`索引。随后，在实现一个“文本到图像”功能后，开发者让AI创建了相应的SOP，并更新了索引文件。接下来，当需要添加一个相似但更复杂的“文本到视频”功能时，AI能够首先阅读`README.md`索引，找到并查阅所有相关的现有文档（如项目架构、之前的实施计划和SOP），从而在充分理解上下文的基础上，一次性成功地完成了新功能的开发，且代码完全可用，没有任何错误。

这种结构化的方法不仅限于新项目。AI Builder Club的成员Simon Wallace-Jones分享了他们团队为大型遗留代码库构建文档系统的经验。他们创建了一个“指针文档”（pointer doc），作为所有文档的中心枢纽。他们的工作流是先让AI更新代码文件内的行内文档（inline documentation），然后基于这些最新的行内文档，再生成更宏观的、独立的Markdown文档。这种分层的方法确保了文档的准确性和可维护性，无论是对于人类开发者还是AI助手都同样友好。
