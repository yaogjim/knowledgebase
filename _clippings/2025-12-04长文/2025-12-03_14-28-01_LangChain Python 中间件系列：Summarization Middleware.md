## 介绍与上下文工程 (Context Engineering)

大家好，我是来自 LangChain 的 Sydney。非常高兴能带着我们 Python 中间件系列的另一集内容回归。这一次，我们将介绍我们的 **Summarization Middleware（摘要中间件）**。

“上下文工程 (Context Engineering)”在最近非常流行，但这到底意味着什么呢？上下文工程指的是为您的模型（即驱动 Agent 的核心）在正确的时间提供正确的信息和工具，以便它可以执行给定的任务。

为了优化 Agent 的上下文，您可以使用的最重要的工具之一就是**摘要 (Summarization)**。

特别是在当下，我们看到 Agent 的运行时间越来越长，这意味着会产生非常长的对话历史记录，其中包含了重要的信息。但是，为了让您的 Agent 在下一步操作中表现良好，它需要从完整的对话历史中获取正确的信息片段。这就是摘要发挥作用的地方。

通过摘要，您可以帮助您的 Agent 专注于正确的信息。在现实世界中，您可能已经在日常生活中见过这样的例子：**Claude Code** 会在对话历史变得过长时自动压缩 (auto-compact) 历史记录。例如，如果您要求 Claude Code 帮助您进行相当复杂的代码重构，几分钟后，它可能会自动进行压缩。

现在，使用 LangChain 新的摘要中间件，您只需几行代码即可实现相同的功能。

## 文档概览

好的，我们正在查看 LangChain 新的中间件文档。这里我们可以看到内置的摘要中间件的文档。

它有一个非常简单的接口。当您使用此原语创建 Agent 时，通常需要指定模型和工具，然后您可以传入摘要中间件，并调整几个参数：

1.  **Model**：用于生成摘要的模型。
2.  **Context Size (Trigger)**：触发摘要的条件。这可以用 Token 数、消息数或可用上下文窗口的比例来指定。
3.  **Retention Policy**：保留策略，即您希望保留多少上下文内容。

让我们跳转到 LangChain 新的 API 文档做更深入的了解。同样，我们可以看到这些类型定义。我提到了上下文大小，我们还可以自定义诸如**摘要提示词 (Summary Prompt)** 之类的内容，以及是否要在进入摘要模型之前修剪 (Trim) 上下文。此外，还有一个详细的 Token 计数器。

您也可以在这里看到我们所有其他预构建的中间件，以及用于构建自定义中间件的实用工具。

接着，我们为摘要中间件使用了一个自定义的摘要提示词 (`summary_prompt`)。

此外，我们配置了几个参数：
*   我们指定了用于摘要的模型。
*   我们设定了触发机制：当使用了 **70%** 的上下文窗口大小时触发摘要。
*   我们的保留策略是保留 **30%** 的内容。

您可能会好奇，LangChain 是如何知道 GPT-3.5 Turbo 模型的 70% 上下文窗口大小是多少的？我们刚刚发布了一个新的 **Model Profiles (模型配置文件)** 包，其中包含了关于模型能力的信息。我们在底层使用这些信息来直观地决定 Agent 的行为。该包包含诸如工具调用容量、结构化输出特性、上下文窗口大小等更多信息。

## 实时调试与演示 (Live Debugger)

让我们在实时调试器中测试一下。

在这个演示中，我将获取关于几位美国开国元勋及其生日的信息。我使用这个例子是因为我预计像乔治·华盛顿、约翰·亚当斯、托马斯·杰斐逊等人的维基百科页面上有大量内容。

让我们开始第一个查询。

1.  **第一轮对话**：
    *   我们看到成功调用了 `fetch_wikipedia_data` 工具来查询“乔治·华盛顿”。
    *   虽然工具返回了非常冗长的结果，但此时还没有触发模型前的摘要工具。

2.  **第二轮对话**：
    *   接下来我们查询“约翰·亚当斯”。
    *   过程类似，依然没有触发摘要。

3.  **第三轮对话**：
    *   最后，我们查询“托马斯·杰斐逊”。
    *   **太棒了！我们可以看到摘要中间件在这里被触发了。**
    *   系统生成了一个摘要，然后使用 `fetch_wikipedia_data` 工具获取了托马斯·杰斐逊的信息，并给出了最终回复。
