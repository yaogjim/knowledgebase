# 以下是我在围绕 Claude Agents SDK 开展开发的经验中，对这两者的不同处理方式： MC

**Clelia Bertelli (/acc)** @itsclelia 2026-01-20

以下是我在围绕 Claude Agents SDK 开展开发的经验中，对这两者的不同处理方式：

MCPs 是一个暴露工具的接口：它们本质上是确定性的：模型生成输入{"location": "旧金山"} → 天气工具从 API 获取数据 → 返回{"weather": "晴天"}。给定相同的参数，工具可能总是会以相同的方式运行。就其构建方式而言，MCPs 对开发者非常友好，因为开发者可以轻松理解工具的架构和功能。

技能是\*\*情境化修改\*\*：当智能体调用技能时，看起来像是在调用工具，但实际上只是引入了一组提示/示例/代码片段，通过情境修改智能体的行为，以便（在调用技能期间）智能体能够按照提供的指令行动。以天气示例为例：智能体调用天气技能，技能告诉它去哪里查找数据，智能体发送 API 请求，然后将 API 响应整合后反馈给用户。

技能是\*\*非确定性\*\*的，因为模型始终有可能产生幻觉/偏离主要任务/误解信息，更普遍地说，即使参数相同，智能体也可能以不同方式行动，采取不同路径达成解决方案。但技能对非技术用户非常友好，因为它们提供了自然语言界面来修改智能体的行为，这种方式感觉像是在调用工具。

希望我的解释没有大错，很乐意进一步讨论这个问题！
