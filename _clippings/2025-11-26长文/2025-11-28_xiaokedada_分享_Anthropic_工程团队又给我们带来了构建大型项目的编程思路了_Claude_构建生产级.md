#分享 Anthropic 工程团队又给我们带来了构建大型项目的编程思路了

Claude 构建生产级大型项目主要面临的两种失败模式：

1\. 同时尝试做太多事情，导致在实施过程中耗尽上下文

2\. 在项目后期，Agent 构建了一些功能之后，表示已经取得进展，宣布任务完成

Anthropic 工程团队提供的一些思路：

\## 创建功能列表

在构建之初创建一个功能列表，验证完所有功能后，标记为完成。有意思的是，经过一些实验（具体细节未披露），与 Markdown 文件对比，Claude 不倾向于不恰当更改或覆盖 JSON 文件。他们使用 JSON 格式来处理功能列表。

\## 用 Git Message 和文件来管理进度

用 Git 来管理 \*\*渐进式开发\*\*，Agent 被要求一次只处理一个功能。让 Claude 将进度提交到 Git，并在文件中记录进度总结。

这是为了保证开发处在干净的状态，也方便 Agent 回滚错误代码。

\## 提供端到端的验证工具，以及 http://init.sh 脚本

为了不让 Agent 花费 Token 了解如何运行项目，可以编写一个 http://init.sh 脚本供 Claude 执行。另外，还可以提供 Puppeteer 这类自动化工具来识别和修复一些仅从代码难以发现的问题。

所以，整个开发流程变成了这样：

1\. 在当前目录运行 Claude

2\. Claude 阅读 Git 日志和进度文件，了解最近的工作内容

3\. 读取功能列表，选择未完成的特性开发

4\. Claude 运行 http://init.sh 脚本运行服务器，使用 Puppeteer 进行功能验证

5\. 验证通过后，将进度更新到 Git Messages 和进度文件

6\. 功能列表标记为完成
