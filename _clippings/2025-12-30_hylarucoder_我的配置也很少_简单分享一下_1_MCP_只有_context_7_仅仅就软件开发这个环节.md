# 我的配置也很少, 简单分享一下 1. MCP 只有 context 7 , 仅仅就软件开发这个环节

**海拉鲁编程客** @hylarucoder 2025-12-28

我的配置也很少, 简单分享一下

1\. MCP 只有 context 7 , 仅仅就软件开发这个环节, MCP 似乎并没有我想象中的那么好用, 反而直接吼一句让AI 写好脚本直接显式调用幺蛾子更少 (比如 notion mcp 至今不支持本地md文件一次调用塞到某个database中, 让AI自己拆解任务反而容易出错, 写个脚本反而很快很稳)

2\. subagent 蛮好用, 条理清晰的写完要求, 让 cc 「开启多个agent」汇总报告, 比如你甚至你可以用同一个代码review agent 对多处模块并行调研, 最后汇总, 这块完全取决于你的提示词水准.

3\. 能和 AI 多聊一会就多聊一会, 写代码反倒在我和 claude code 中占比的时间比较少, 比如我会更多的产品的名词是什么, 技术的名词是什么, 命名是否到位, (毕竟命名不正则言不顺), 代码应该怎么放, 软件规格是什么样的, 怎么去完成验收.

4\. 能用 plan 模式就用 plan 模式

5\. Skill 之前试了几个感觉并不是很顺手, 官方 skill 中的 frontend-design 比较好用, 复杂一些的需求感觉用代码写也并不复杂, 我就直接写了个 electron 壳用 agent sdk 调 cc 了.....

> 突然意识到我使用 Claude Code、Codex 和 Gemini 的方式还是极为朴素，MCP 只加一个 context7，别的设置几乎都是 Vanilla 的。

> 一看推上的人要加一大堆花里胡哨的 MCP 和 Skills……
