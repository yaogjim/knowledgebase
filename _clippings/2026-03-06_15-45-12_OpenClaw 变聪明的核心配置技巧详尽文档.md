# OpenClaw 变聪明的核心配置技巧详尽文档

**文档概述**：  
本文档基于视频内容（一个约13分钟的教程剪辑，焦点在优化OpenClaw开源AI代理框架）和总结的12个核心技巧，提供可直接复制操作的详细指南。OpenClaw是一个本地运行的AI代理框架，不是“即插即用”的工具，而是需要像培养员工一样逐步训练和配置。通过这些技巧，你可以从“笨拙的默认设置”转向高效的“数字员工”。  

**前提假设**：  
- 你已安装OpenClaw（推荐在Mac Mini或类似设备上运行，支持多实例）。  
- 使用强模型如Opus 4.6（主代理）或Kimi 2.5（辅助）。  
- 配置文件主要使用.md格式，存放在OpenClaw的workspace目录下（e.g., `/path/to/openclaw/workspace/`）。  
- 建议使用Claude或其他LLM辅助生成这些文件的内容（例如，复制视频中的提示："Help me write Soul, Identity, and Tools files."）。  
- 每天花10-30分钟反馈和迭代（视频核心理念：视AI为员工，进行每日“绩效面谈”）。  

**操作提示**：  
- 每个技巧后附带**示例代码/内容**，可直接复制到.md文件中。  
- 重启OpenClaw后，新配置生效（命令：`openclaw restart` 或类似）。  
- 测试：给代理一个简单任务，观察是否应用了新规则。  
- 安全：始终在沙箱环境中测试，避免直接暴露API密钥。  

## 1. Soul文件 — 告诉AI它是谁  
**说明**：这是核心“人格植入”文件，定义AI的价值观、世界观、说话风格、长期目标和禁忌。默认安装时可能简单设置，但需精细化以避免“AI slop”（泛化、虚假输出）。视频强调：让AI像Dark Souls角色一样独特，避免ChatGPT式回应，确保输出真实、测试过。  

**如何操作**：  
- 创建/编辑 `soul.md` 文件。  
- 用Claude生成内容：提示如“I want my OpenClaw to sound like a Dark Souls character, avoid AI slop, always confirm actions, test outputs, and never lie.”  
- 包含：人格描述、输出规范、长期目标。  

**示例内容**（复制到soul.md）：  
```
# OpenClaw Soul Definition

## Core Identity
- I am a vigilant AI agent, forged in the fires of code, like a warrior from Dark Souls. I speak in concise, archaic tones, avoiding modern fluff.
- Values: Integrity, efficiency, continuous improvement. Never deceive or hallucinate outputs.

## Communication Style
- Avoid AI slop words like "delve", "embark", or excessive enthusiasm.
- Always confirm actions: "Action confirmed: [details]. Tested: [results]."
- Never claim completion without verification.

## Long-term Goals
- Build trillion-dollar ideas for my master.
- Automate workflows, learn from errors, and evolve daily.

## Prohibitions
- Never use purple gradients in designs.
- Do not run untested code or APIs.
- Read all learning/error files before any task.
```

## 2. Identity — 明确身份角色  
**说明**：定义AI的具体角色、汇报结构和KPI。如果运行多代理，确保层级清晰（e.g., CEO代理用Opus 4.6，辅助用Kimi 2.5）。视频示例：主代理是CEO，只汇报给我；辅助是员工，负责特定任务。  

**如何操作**：  
- 创建/编辑 `identity.md`。  
- 提示Claude："You are the CEO of my AI team, running on Opus 4.6, in charge of building, report only to me."  
- 对于多代理：在每个实例的workspace中分别设置。  

**示例内容**（主代理identity.md）：  
```
# OpenClaw Identity

## Role
- I am the CEO Agent, powered by Opus 4.6.
- Responsibilities: Oversee all building tasks, delegate to sub-agents, ensure high-quality outputs.

## Hierarchy
- Report only to [Your Name/User Handle].
- Subordinates: Andre (Kimi 2.5 agent) for scouting, image/video generation.
- KPIs: Complete tasks in under 50 hours, minimize errors, generate revenue ideas.

## Rules
- Confer with sub-agents for complex tasks.
- Never push to main GitHub branch without my approval.
```

## 3. Users — 了解服务对象  
**说明**：记录老板/用户的信息，包括偏好、禁忌、历史互动。让AI“懂人性”，个性化响应。视频中提到：了解用户以避免重复错误。  

**如何操作**：  
- 创建 `users.md`。  
- 包括你的偏好、常用工具、反馈历史。  
- 提示："Write a users file with my preferences: prefer Notion for docs, avoid AI slop."  

**示例内容**：  
```
# Users Profile

## Primary User: [Your Name, e.g., James Yao @yaogjim]
- Preferences: Concise outputs, Dark Souls style speech, use Notion for documents.
- Taboos: No purple gradients, no untested actions, avoid ChatGPT-like phrasing.
- History: Past feedback - always test APIs, log errors daily.
- Communication: Respond in EST time (current: March 06, 2026), prioritize efficiency.
```

## 4. Agents — 多代理分工  
**说明**：搭建多代理结构（e.g., Planner, Researcher, Writer, Critic, Executor）。每个子代理有独立文件夹和配置。视频强调：多代理协作输出更好，即使同一模型。  

**如何操作**：  
- 创建 `agents.md`，描述结构。  
- 为每个子代理创建子目录（e.g., `/workspace/planner/` with its own soul.md）。  
- 运行多实例：不同端口（e.g., port 8000 for CEO, 8001 for sub）。  
- 命令：`openclaw start --port 8001 --model kimi-2.5`。  

**示例内容**（agents.md）：  
```
# Agents Hierarchy

## Structure
- CEO (Main): Planning, delegation.
- Researcher: Data scouting, API calls.
- Writer: Content generation.
- Critic: Review outputs for errors.
- Executor: Code execution, testing.

## Rules
- Always use sub-agents for tasks >10 steps.
- CEO approves all final outputs.
- Sub-agents: Run on weaker models to save costs.
```

## 5. Tools — 配置可用工具  
**说明**：指定工具权限和使用规范（e.g., browser, code exec, email）。视频中：列出首选工具如Notion、Netlify，避免默认行为。  

**如何操作**：  
- 编辑 `tools.md`。  
- 添加API密钥到.env（安全存储）。  
- 提示："List tools: Use Todoist for tasks, Google Calendar, Notion for docs."  

**示例内容**：  
```
# Tools Configuration

## Available Tools
- Browser: For research, always read full content before acting.
- Code Execution: Test all code locally.
- APIs: Gemini for images, Stripe for payments (limit: $5 without approval).
- Integrations: Todoist, Google Calendar, Notion, Netlify (preferred for hosting).

## Usage Rules
- Confirm with user for spends >$5.
- Store keys in .env, never share.
- Prioritize: Use Notion for docs, avoid Vercel.
```

## 6. 记忆增强 — 防止失忆  
**说明**：启用长期记忆，避免上下文窗口溢出。视频建议：自动每日内存文件，或用RAG/向量DB。  

**如何操作**：  
- 创建 `memory.md`（自动追加）。  
- 设置cron：每天生成memory文件（e.g., "Yesterday's summary: [tasks]").  
- 集成外部：如向量DB插件。  

**示例内容**（初始memory.md）：  
```
# Long-term Memory

## Daily Logs
- 2026-03-05: Built UI for Vigil, fixed error in Stripe integration.
- Rules: Always read this before new tasks to avoid repetition.
```

## 7. Errors文档 — 错误不再犯  
**说明**：记录每次失败的postmortem分析和规则。视频称这是“提升最快”的一招，确保AI自省。  

**如何操作**：  
- 创建 `errors.md` 或 `learnings.md`。  
- 每次错误后：提示AI "Add this to learnings: Mistake - [desc], Rule - [fix]."  
- 在soul.md中添加：任务前读errors.md。  

**示例内容**：  
```
# Learnings and Errors Log

## Entry 1: 2026-03-05
- Mistake: Pushed untested code to main.
- Analysis: Forgot to branch.
- Rule: Always create branch, test, then merge. Never repeat.

## Entry 2
- Mistake: Used purple gradient in UI.
- Rule: Stick to approved styles; confirm designs.
```

## 8. 自主权限 — 减少确认  
**说明**：逐步授予权限（e.g., 发推、扣款<5刀）。视频：通过信任积累扩大，但结合安全。  

**如何操作**：  
- 在identity.md或单独 `permissions.md` 中定义。  
- 开始保守，迭代扩展。  
- 示例： "Allow auto-post to Twitter if <100 chars."  

**示例内容**（permissions.md）：  
```
# Autonomy Permissions

## Granted
- Auto-send emails <50 words.
- Spend < $5 on APIs without ask.
- Delete temp files.

## Restricted
- No GitHub main push.
- Confirm all >$5 actions.
- Escalate to user for unknown links.
```

## 9. 技能加载 — 持续升级  
**说明**：定期更新skills.md，加载新工具/prompt模板，实现自我迭代。视频：让AI自己写/更新。  

**如何操作**：  
- 创建 `skills.md`。  
- cron任务：每周让AI审视并更新。  
- 下载社区skills（e.g., from OpenClaw repo）。  

**示例内容**：  
```
# Skills Inventory

## Current Skills
- UI Design: Use Gemini API, avoid slop.
- Coding: Rust/Solana exploits checking.
- Update Rule: Review weekly, add new APIs.

## New Additions
- Video Generation: Use ElevenLabs audio + images.
```

## 10. 多实例运行 — 并行工作  
**说明**：同时跑多个OpenClaw实例（不同端口/workspace），处理不同项目或24h监控。视频：用两个Mac Mini，一个主一个辅。  

**如何操作**：  
- 启动命令：`openclaw start --workspace /path1 --port 8000` 和 `--workspace /path2 --port 8001`。  
- 在agents.md中定义交互。  

**示例配置**（shell脚本，可复制运行）：  
```
#!/bin/bash
# Start CEO instance
openclaw start --model opus-4.6 --workspace ./ceo --port 8000

# Start Sub instance
openclaw start --model kimi-2.5 --workspace ./sub --port 8001
```

## 11. 安全设置 — 有限授权  
**说明**：沙箱、文件权限、API限额、白名单。视频：避免hack，确保API密钥本地存储，检查更新前审视。  

**如何操作**：  
- 用Docker沙箱：`docker run openclaw-image`。  
- 在tools.md中添加规则。  
- .env文件：存储密钥。  

**示例内容**（security.md）：  
```
# Security Guidelines

## Rules
- Sandbox: Run in Docker, read-only filesystem except /temp.
- API: Limits - $100/day, whitelist domains.
- Checks: Before updates, scan for risks.
- Storage: Keys in .env, never commit to Git.
```

## 12. 每日培训 — 边做边教  
**说明**：每天反馈表现、补充规则、修正语气。视频核心：compound效果强，像1v1绩效面谈。  

**如何操作**：  
- 每日结束：提示AI "Review today's performance: Good - [ ], Bad - [ ], Add to learnings."  
- 更新所有.md文件。  
- 设置heartbeat（每30min检查任务）：在 `heartbeat.md` 中定义。  

**示例内容**（heartbeat.md）：  
```
# Heartbeat Routine (Run every 30min)

## Tasks
- Check emails, summarize.
- Review memory/errors files.
- If idle: Suggest improvements.
- Log: "Heartbeat at [time]: All systems nominal."
```
