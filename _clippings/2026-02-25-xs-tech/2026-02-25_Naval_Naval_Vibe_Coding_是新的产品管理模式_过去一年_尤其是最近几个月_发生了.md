# Naval Vibe Coding 是新的产品管理模式。“过去一年，尤其是最近几个月，发生了

**Naval**

Vibe Coding 是新的产品管理模式。“过去一年，尤其是最近几个月，发生了显著的变化——其中最引人注目的是 Claude Code，它是一种内置编码引擎的特定模型，非常出色。我认为现在出现了 Vibe Coders，他们以前很少写代码，或者很久没写代码了，现在却使用英语作为编程语言——作为输入到这个代码机器人中的代码——它可以完成端到端的编码。它不仅能帮助你调试中间环节，还能让你描述你想要的应用。你可以让它制定计划，甚至可以根据计划对你进行‘面试’。你可以随时提供反馈，然后它会将代码分解并构建所有必要的框架。它会下载所有库、连接器和钩子，然后开始构建你的应用、构建测试框架并进行测试。你还可以通过语音不断地提供反馈和调试，比如告诉它‘这行不通’。”这行得通。改改这个，改改那个，”然后它就能为你构建一个完整的应用程序，而你甚至无需编写一行代码。对于一大批不再写代码或从未写过代码的人来说，这简直令人难以置信。它让他们直接从想法、观点和喜好层面进入产品领域。所以我的意思是——产品管理已经取代了编码。Vibe 编码就是新的产品管理。你不再需要通过告诉工程师该做什么来管理产品或一群工程师，而是可以告诉计算机该做什么。而计算机不知疲倦，它没有自我意识，它会一直工作下去。它会接受反馈而不会生气。你可以启动多个实例。 它将全天候运行，并能持续输出有效内容。这意味着什么？就像现在任何人都可以制作视频或播客一样，现在任何人都可以开发应用程序。因此，我们应该预料到应用程序将会如潮水般涌来。并非说 App Store 里没有应用程序，但与即将出现的应用程序数量相比，简直是小巫见大巫。然而，当应用程序数量如此之多时，这是否意味着它们都会被使用，或者它们之间会存在竞争呢？并非如此。我认为情况会分为两类。首先，针对特定用例的最佳应用程序往往仍然会在整个类别中胜出。当内容如此丰富多样时，无论是视频、音频、音乐还是应用程序，平庸之作都无足轻重。 没人想要平庸之作。人们想要的是能满足需求的最佳产品。首先，这意味着更多的机会涌现。因此，优秀的产品也会更多。更多的细分市场将被填补。你可能想要一款功能非常具体的应用程序，比如在特定情况下追踪月相，或者进行某种性格测试，又或者玩一款能唤起你怀旧情怀的特定类型的电子游戏。以前，市场规模太小，不足以支撑聘请工程师花费一两年时间进行开发的成本。但现在，一款优秀的编程应用程序或许就能满足你的需求或填补市场空白。因此，更多的细分市场将被填补，随着这种情况的发生，市场将会蓬勃发展。优秀的应用程序——以及开发这些应用程序的工程师——将得到更大的发挥空间。他们将能够添加更多功能，修复更多漏洞，完善更多细节。因此，优秀的应用程序将不断变得更好。更多细分市场将会得到填补。甚至一些特定的细分市场——例如，你想要一款专门满足你特定健康追踪需求，或者特定建筑布局或设计需求的应用程序——这款原本不可能存在的应用程序现在也会出现了。”

### 热门回复

**@Shikhar** ♥ 11 · 💬 7

老生常谈的问题又来了：如果每个人都在开发应用程序，那么谁在使用这些应用程序呢？

**@Christopher Karani** ♥ 11 · 💬 1

直觉式编码一开始有效，但过不了多久就会失效。你可以用提示符快速搭建一个可运行的原型，但维护它需要大量的内存。 代理需要记住你为什么选择那个数据库，你在第三次迭代中讨论过哪些权衡取舍，以及上次你修改身份验证时出现了哪些问题。

**@Chris Sloane** ♥ 11 · 💬 1

Claude Code 在 CRUD 应用方面表现出色，但如果交给它处理交易系统或固件，就会出现各种竞态条件，需要花费数周时间才能调试完毕。Vibe 编码在遇到真正的延迟限制之前也能正常工作。

**@Palindrome** ♥ 9 · 💬 0

不受欢迎的观点 如果你不懂编程， 那说明你还不了解如何更好地编写代码。

**@ejae dev** ♥ 6 · 💬 2

这里缺失的关键一点是：小众应用不会上架任何应用商店。如果你能在短短一小时内开发出一个定制应用，你不会安装它，而是在需要时启动，用完就扔。真正的转变不在于应用数量的增加，而在于一次性应用的出现。
