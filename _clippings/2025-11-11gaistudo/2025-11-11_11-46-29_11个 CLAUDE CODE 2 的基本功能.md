**核心功能一：新模型**

核心功能一可能是 Claude Code 2.0 中最大的升级，那就是新模型。

Claude Code 现在有三种模型供你选择，以完成你的编程任务。

首先是 Sonnet 4.5，这是 Claude Code 新的默认模型。Anthropic 声称 Sonnet 4.5 是世界上用于代理、编程和计算机使用的最佳模型，基准测试也证实了这一点。在衡量真实世界软件工程能力的 SWE-bench 软件工程基准测试中，Sonnet 4.5 击败了 Opus 4.1、OpenAI 的 GPT-5 Codex 和 Google 的 Gemini 2.5 Pro。

Sonnet 4.5 现在还能处理比以前更长、更复杂的任务。Anthropic 声称它可以在复杂的、多步骤的任务上专注超过 30 个小时。

我一直把 Sonnet 4.5 作为我在 Claude Code 中进行规划和执行的默认模型。老实说，它真的很棒。对我来说，它绝对取代了 Opus 4.1，成为我最常用的模型。

其次，我们有 Haiku 4.5，这是第二个新模型，也是 Claude Code 中最快、最便宜的模型。Haiku 4.5 最适合与 Sonnet 4 进行比较。它的速度是后者的两倍，成本只有三分之一，同时保持了相似的编程性能。我自己的使用体验也证实了这一点。它速度飞快，对于直接的编程任务真的很有用。

关于 Haiku 4.5 最酷的一点是，当你在计划模式下时，Claude Code 会自动使用 Sonnet 4.5 进行规划，使用 Haiku 进行执行。这被称为 SonnetPlan。如果你还记得旧的 OpusPlan 模式，这和它很相似。我认为这可能会成为大家的新宠，因为它既能利用 Sonnet 4.5 的强大规划和推理能力，又能使用更快、更便宜的 Haiku 4.5 模型进行实现。

Claude Code 2.0 中的第三个模型是 Opus 4.1，这是一个高级模型，用于处理你要求最高的编程任务。在 OpenAI 新发布的 GDPVal 评估框架中，Opus 4.1 也名列前茅。该框架衡量 AI 在金融、医疗和客户支持等领域的真实世界、具有经济价值的工作任务上的表现。Opus 4.1 在这项评测中表现最佳，击败了 GPT-5、Gemini 和 Grok 等模型，成为在金融、医疗和客户支持等领域的真实世界任务中表现最好的模型。

最后，请注意，你现在能访问的模型取决于你的 Claude 计划。每月 20 美元的 Pro 用户可以使用 Sonnet 和 Haiku，但不能使用 Opus。而 Max 用户，每月 200 美元，则可以使用所有模型。

**核心功能二：探索子代理**

第二个必须了解的功能是“探索”（Explore）子代理。这是一个专门的代理，旨在快速从你的代码库中获取上下文。

探索代码库是那种既常见又重要的任务之一，无论你是在计划实现一个功能、编写文档，还是只是想快速了解一个项目。

“探索”子代理由新模型 Haiku 4.5 驱动，这意味着它能快速高效地搜索你的代码库。

“探索”子代理的一个很酷的地方是，Claude 实际上会自动使用它。你不需要做任何不同的操作就能从中受益。当 Claude 检测到你要求的任务符合其能力时，它会自动使用“探索”子代理。

但你也可以通过使用“探索代码库”或“使用‘探索’子代理”等短语来明确调用“探索”子代理。你甚至可以指定搜索的详尽程度。使用关键词“快速”（quick）进行基本搜索，“中等”（medium）进行中等程度的探索，或者“非常详尽”（very thorough）来进行跨多个位置的全面分析。例如，你可以说：“使用‘探索’子代理，以中等详尽程度，查找应用中的所有分析跟踪事件。”

**核心功能三：检查点和回滚**

Claude Code 2.0 中第三个必须了解的功能是社区呼声最高的功能之一，那就是检查点（checkpoints）和回滚（rewind）。

通过检查点功能，Claude Code 现在会在每次由 Claude 发起更改之前，自动保存你的代码状态和 AI 对话状态。你每提交一个提示，就会创建一个检查点。

最好的部分是，你不需要做任何事情来启用检查点，它会自动发生。

如果 AI 开始走偏，你可以使用“回滚”（rewind）命令立即回到之前的检查点。只需输入 `/rewind` 就可以查看所有检查点，并选择你想回到的那个。

在回滚时，你有三个选项：你可以回滚代码、上下文，或者两者都回滚。正是这种能够同时恢复代码和可能被“污染”的对话上下文的能力，使得检查点功能成为 Claude Code 2.0 中改变游戏规则的功能，因为它让你能够充满信心地探索新的方向，而不用担心搞砸，因为恢复就像输入一个“回滚”命令一样简单。

关于检查点的两个专业提示：首先，一旦你回滚到一个检查点，你只能从那里继续后退，不能来回跳转。其次，检查点不能替代 Git，它是一个补充。它被设计用于快速的会话级别恢复，不包括由 bash 或直接文件编辑所做的更改。所以你仍然需要使用 Git 来对你的项目进行整体的版本控制。

**核心功能四：全新的终端界面**

这个“必须了解”部分的最后一个功能，也是你会立刻注意到的，就是 Claude Code 2.0 有一个完全刷新的终端界面，而且它非常干净。

增强的终端用户界面更流畅、更灵敏，信息也比以前更丰富。我个人最喜欢的一个变化是新的螃蟹吉祥物，叫做“Clawd”，每当你启动 Claude Code 时它都会出现。这是一个很不错的点缀。

还有一个新的动画，用于像“思考”（think）和“深度思考”（ultrathink）这样的思考关键词，现在当你输入这些关键词时，思考模式会自动开启。

然后是状态栏，现在可以进行更多的自定义，让你对项目上下文一目了然，比如显示当前文件夹和 Git 分支等信息。要配置状态栏，使用 `/statusline` 命令。我把我的状态栏设置为显示当前文件夹和当前 Git 分支，因为我同时用 Claude Code 处理多个项目，这有助于我不会搞混。

通过 VS Code 扩展，你还可以获得实时的内联差异对比和拖放支持，以便将文件和文件夹直接添加到聊天中。Claude Code 扩展在 VS Code 应用商店中可以找到，这意味着你可以在 VS Code 中使用它，也可以在 Cursor、Winsurfer 和其他基于 VS Code 的 IDE 中使用。要安装它，只需在 VS Code 应用商店中搜索 Claude Code，安装后，你可以从设置菜单中打开它，或者直接使用 `/ide` 命令来回切换。

下一个进阶功能完全改变了你使用 Claude Code 的方式和地点。你现在可以直接从 Claude 移动应用或网页应用，在沙箱中运行编程任务。这对于随时随地进行开发来说是巨大的进步。

让我们深入了解一下沙箱。当你在网页或移动应用上启动一个编程任务时，它会在 Anthropic 管理的沙箱中运行。每个会话都在其自己隔离的环境中运行，并可以实时跟踪进度。你可以根据需要选择完全放手或主动干预。你可以让 Claude 自由发挥，或者在它执行任务的过程中主动引导和调整方向。你甚至可以在不同的 GitHub 仓库上并行运行多个任务。所以你可以让 Claude 在一个仓库里修复 bug，同时在另一个仓库里同步更新文档，所有这些都通过你的手机或浏览器完成。

但我在网页和移动应用体验中最喜欢的功能是“传送”（teleporting）。传送功能让你能轻松地将你的网页会话切换到本地开发环境。它会将所有的上下文、所有的消息和所有的编辑都移动到你的本地环境，这样你就可以保持流畅的工作状态。这使得在本地和远程执行之间切换变得非常容易。要开始使用，只需将你的 GitHub 连接到 Claude，选择你的权限级别，就可以开始了。

请注意：在网页和移动设备上访问 Claude Code 目前是一项处于研究预览阶段的测试功能。所以如果你还没看到它，希望你很快就能用上。

下一个进阶功能是一套新的上下文管理工具。如果你曾意外地达到使用限制，那么这些功能对你将非常有帮助。

首先，你有两个新命令可以帮助你更好地了解你的使用情况。`/context` 命令可以让你可视化当前会话的上下文，而 `/usage` 命令则显示你的使用情况，并告诉你是否接近当前会话或本周的任何使用限制。这些功能非常棒，可以让你随时了解自己的使用情况，从而避免在任务中途遇到速率限制。

接下来，长期使用 Claude Code 的用户可以证明，在自动压缩（auto-compact）发生后，任务的性能会变得更差。所以，使用 Claude Code 的一个专业技巧是，主动清除上下文窗口，而不是让它自动压缩。现在实际上有三种方法可以做到这一点。

有 `/clear` 命令，它会将所有内容重置为零。这是一个完全的重新开始。我建议在你切换到开发一个全新的功能，或者调查一个全新的问题，并且不需要任何之前建立的上下文时使用它。

然后是 `/compact` 命令，它会清除对话历史，但在上下文中保留一个摘要，这与上下文窗口满了之后自动压缩时发生的情况一样。这个“压缩”命令在你完成一个大计划中的一个小部分之后很有用。这样你就可以将一些已经发生的事情的知识带到未来的子任务中。

还有一个新功能叫做“微压缩”（micro-compact），这是“压缩”的一个更智能的版本。但这不是一个你可以运行的命令，它实际上是 Claude Code 调用的一个自动命令，用来清除旧的工具调用结果，当上下文变大时。这有助于延长你的会话长度，而无需手动干预，这是 Claude Code 2.0 的一个全新功能。

本部分的最后一个功能，是关于如何更好地向 Claude 提问。这里的最大亮点是交互式提问工具。当 Claude 需要更多信息时，它可以向你提问。这使得使用 Claude Code 的体验更具对话性，尤其是在你使用计划模式时，Claude 会在深入实施之前询问一些澄清性问题。这能帮助你从 Claude 那里得到更好的结果，因为它会在实施之前寻求澄清，而不是让你在事后提供反馈。这种模式让我想起了 ChatGPT，特别是它的深度研究功能，它会在开始整理研究报告之前问你一些澄清性问题。这总是迫使我去思考：我到底想做什么？这不仅有助于更好地思考，还能帮助我得到更好的结果。所以，我很高兴看到像 Claude Code 这样的工具更广泛地采用这种模式。

首先，是 Claude Code 2.0 中最强大、也是讨论最多的功能之一，它能帮助 Claude 学习专业知识，这个功能就是“技能”（Skills）。

技能是打包好的指令，用来教 Claude 你的工作方式。你可以把技能看作是一种按需加载专业知识到 Claude 中的方式。你不需要为每件事都构建自定义代理，而是将知识打包成可重用的能力，Claude 在需要时可以加载它们。

从核心上讲，技能其实很简单。它只是一个包含 `skill.md` 文件的文件夹。该文件以名称和描述开头，然后包含指令、代码和资源，以及指向文件夹中其他文件的指针。

酷的是，一旦你创建了一个技能，你就可以在任何地方使用它——在 Claude Code 中、在 Claude 应用中，以及通过 Claude API。

技能使用渐进式披露，Claude 最初只会看到技能的名称和描述，只有在与任务相关时才会加载完整的技能。这有助于保持你的上下文窗口整洁，这对于管理 token 使用限制非常有帮助。

Anthropic 为 Claude Code 发布了一些预置技能，包括处理 PDF、Word、PowerPoint 和 Excel 等常见文件格式的技能，还有一个示例技能库，其中包含了用于测试本地 Web 应用的网页测试技能（使用 Playwright）、用于创建 MCP 服务器的 MCP 服务器指南，甚至还有一个技能创建器技能，你可以用它来构建自己的技能。

社区也已经在构建一些很棒的第三方技能，从测试驱动开发框架到 EPUB 电子书分析器和会议洞察工具。

你可以使用插件来安装技能，我们接下来会讲到。技能是我计划要深入探索的一个功能。所以，如果你已经尝试过技能，请在评论中告诉我你的使用体验。

下一个高级用户功能是插件。插件是一种发现和分享使用 Claude Code 的最佳实践和自定义设置的方式。插件是一个大功能，因为它意味着你可以轻松使用其他 Claude Code 用户的最佳自定义设置，而无需自己复制或设置它们。一个插件可以包含自定义命令、子代理、MCP 服务器、钩子和技能。

要开始使用插件，使用 `/plugin` 命令来浏览和安装新插件。插件的一个关键概念是“市场”（marketplaces）。你可以把市场看作是由特定开发者或公司制作的插件集合。要添加新市场，你也可以使用 `/plugin` 命令。公司和像你我这样的 Claude Code 用户都可以创建这些市场，它们通常以 GitHub 仓库的形式存在。

自发布以来，现在已经有数百个插件了。但让我向你展示我最喜欢的三个，我觉得它们很有用，这样如果你对插件感到好奇，就可以开始使用了。

首先是 Anthropic 自己的 Claude Code 市场，它包含多代理功能开发工作流和 Git 提交插件等。

其次是用于复合工程的 Every 插件。这是一套旨在帮助 Claude Code 自我改进的自定义设置，使你制作的下一个功能总是比上一个更容易。

第三是 Seth Hobson 的 agents 仓库，其中包含超过 60 个用于现代软件开发中智能自动化的插件。

要找到更多插件，有许多社区聚合器，比如 `claudecodemarketplaces.com`，你可以在那里找到更多可以尝试的插件。在使用之前，请务必确认它不是恶意插件。

关于插件的最后一个专业提示是，它们有时会占用大量上下文，所以你可以按需启用或禁用它们，以避免上下文过载。

最后一个高级用户功能是 Claude Agent SDK。这以前被称为 Claude Code SDK。Claude Agent SDK 是创建你自己的 AI 代理的完美基础。它基于这样一个理念：Claude Code 及其由工具和文件系统组成的代理框架，实际上是创建通用自定义代理的完美基础。Claude Agent SDK 让你和你的团队可以访问驱动 Claude Code 的相同核心工具，包括其工具执行系统、上下文管理和权限框架。例如，我用 Claude Agent SDK 创建了一个个人旅行代理，为我和我的妻子根据我们的喜好规划我们即将到来的旅行。当然，我用 Claude Code 来完成实现。Anthropic 也用这个 SDK 构建了他们的 GitHub Actions。这个 SDK 支持创建自定义子代理和以编程方式定义钩子行为。如果你想深入了解 Claude Agent SDK，请在评论中告诉我，如果有足够的需求，我一定会做一个。

这就结束了第三部分，也就是高级用户功能。但在结束之前，还有一个重要的部分我想谈谈。对某些人来说，这可能是最重要的部分，那就是成本。

首先，Claude Code 目前仍然只在付费计划中提供，还没有免费版本。你可以选择的两个付费计划是 Pro 计划和 Max 计划。Pro 计划每月 20 美元。这是 Claude Code 最便宜的计划，你可以访问 Haiku 4.5 和 Sonnet 4.5。如果你是 Claude Code 的新手或只是偶尔使用，我建议你从 Pro 计划开始。

对于 Max 计划，你实际上有两个选择：Max 5x 每月 100 美元，Max 30x 每月 200 美元。5x 计划提供 5 倍的速率限制，而 30x 计划提供 20 倍的速率限制。两个 Max 计划都可以让你访问所有模型，包括 Haiku、Sonnet 和 Opus。如果你认真地想在真实项目中使用 Claude Code，我推荐 Max 计划。这是我个人使用的计划，如果你有预算的话，它绝对物有所值。

第三，你也可以使用 API 计费，但我只建议在你的公司为 Claude API 访问付费的情况下使用。否则，我发现它太贵了。所以如果你是自费使用 Claude，我建议选择 Pro 或 Max 计划。
