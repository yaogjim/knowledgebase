# [将杂乱的电子表格转换为适合 AI 处理的数据，1 月 22 日参加我们的网络研讨会！](https

[将杂乱的电子表格转换为适合 AI 处理的数据，1 月 22 日参加我们的网络研讨会！](https://landing.llamaindex.ai/messy-spreadsheets-to-ai-ready-data) ![](https://cdn.sanity.io/images/7m9jw85w/production/5966194b77ec5eb2bdb376024c6ad6eb235cd8cc-1200x676.png?w=1200)

我们注意到一个有趣的趋势，即智能体读取和交互非结构化上下文的主要方式是通过文件。这篇博客概述了核心界面、文件的使用场景，以及我们未来仍需探索的问题。

我注意到文件有 3 种主要的使用方式：

1.  作为智能体存储和检索长期对话历史的主要方式
2.  作为智能体检索海量外部上下文的主要格式，以取代简单的 RAG 模式
3.  为了给代理配备“技能”并完全绕过 MCP

这些模式主要借助流行的编码代理工具（如 Claude Code 和 Cursor）得到应用。不过，编码代理本质上等同于通用推理代理，而且我观察到一个普遍趋势：代理类应用正围绕文件和文件系统进行集中化，将其作为上下文管理的核心抽象。

## The File Interface

代理的文件和你电脑里的文件是一样的。文件有各种不同的形式和格式：

1.  纯文本文件：所有代码文件（.py、.tsx、…），以及其他纯文本文件，如.txt、.md、.csv、.json 等。你可以直接将这段文本输入到 LLM 的上下文窗口中。
2.  文档格式包括：.pdf、.docx、.pptx、.xlsx。这些格式并非原生的机器可读格式，需要经过解析才能转换为 LLM 就绪格式（后续会详细说明！）
3.  图片格式：.png、.jpeg 等
4.  其他任何东西（视频、音频、应用程序二进制文件）——它们目前对智能体而言无关紧要，至少在计算机真正被使用之前不会（变得相关）。

代理以多种方式与文件和文件系统进行交互。默认情况下，它们可以访问命令行界面(CLI)，并使用 `ls` 和 `grep` 等命令来遍历和搜索文件（尤其是纯文本文件）。它们还配备了 `Read` 等内置工具，以便读取纯文本文件的子部分。如果您希望，还可以为编码代理配备语义搜索能力。

不再是一个配备数百个工具的智能体，我们正朝着一个智能体仅能访问文件系统和约 5-10 个工具的世界演进：

- CLI over filesystem
- code interpreter
- web fetch

而且，这的通用性与拥有 100 多个 MCP 工具的代理相当，甚至可能更强。

## 文件用于存储长上下文和操作

**1\. 文件是智能体用于存储和检索更长时间对话历史的核心抽象概念

**上下文窗口仍然是在长期知识工作任务中部署前沿智能体的主要瓶颈之一。这一点在编码智能体中尤为明显。每次在 Claude Code 上看到“Context left until auto-compact”（直到自动压缩剩余上下文）的通知弹出时，我都会感到一阵不安。一旦触发压缩，智能体就会不可避免地失忆，无法可靠地完成剩余任务。

主要的权宜之计之一，无论是由人类还是代理自身触发，就是将这些对话存储到文件中。Claude Code 采用了这种方法中最简单的实现方式之一，即使用 Claude.md 文件——这是一个静态文件，使编码代理在实例化时能够访问一个通用的上下文池。最近，Cursor 的博客文章介绍了他们在触发上下文压缩时，将过去的聊天记录存储为可搜索文件的方法；这使得代理在觉得现有上下文窗口不足以解决当前任务时，能够动态查询之前的对话历史。

![](https://cdn.sanity.io/images/7m9jw85w/production/f67b428a48cc10cd657f43574bbe4b8a693399a8-7309x4083.png)

用户正在手动定义工作流程，以在其编码代理环境中创建和编辑文件。Dex Horthy 在这里拥有大量资源。他提出了一个令人难以置信的三步流程——研究、计划、实施，据传闻，该流程极大地提升了编码代理的性能。这一流程让代理首先创建 research.md 文件，接着生成 plan.md 文件，后者可对现有上下文进行压缩以供人工审核，随后将其传递至后续步骤。此外，Kyle Mistele 也阐述了“渐进式披露”的概念，即引导代理指向嵌套的 MD 文件。

**2\. 文件是智能体检索大量外部上下文的主要格式，已取代简单的 RAG 模式**

RAG 表现不佳是 2023 年的一个问题，我制作了大量视频，详细介绍了改进方法。问题在于，所有这些技术都只解决了问题的一部分。我们仍然远未实现一个智能体的潜力——这个智能体能够从任意规模的代码仓库中动态读取任何量的上下文，以回答任何复杂度的问题。

拥有简单文件搜索工具的智能体能让我们更接近目标。智能体可以将搜索与 `Read()` 操作交错进行，就像人类一样，它们可以选择扫描多个文件或在单个文件中上下滚动来完成任务。

最近，在我们自己的实验中，我们发现了两件事：

1.  借助文件系统工具和语义搜索功能，推理型智能体能够动态遍历上下文，进而回答任何复杂度的问题。
2.  即使仅文件搜索，在中小型文档集合中也优于简单的语义搜索（忽略延迟）

实际上，你可能还是需要语义索引，不过无论如何，你都可以将其作为一个命令来补充现有的文件系统 CLI 命令（见 semtools）。

文件抽象的好处在于，你还可以将任何已有的大量非结构化上下文池转化为一个文件。Cursor 和 Claude Code 都会自动将长 MCP 工具响应写入文件，这使得代理能够使用上述文件系统工具对这些内容进行后处理，且不会被截断。

**3\. 作为一种为代理配备“技能”并彻底绕过 MCP 的方式**

![](https://cdn.sanity.io/images/7m9jw85w/production/f41539888f4f2f1c7a33a2fed4cb56fb8ec498cf-480x480.gif)

Anthropic 于 10 月首次提出了“技能”的概念。这个概念非常容易理解。类似于 Claude.md 文件，Claude 技能实际上也只是文件，有时是文件夹（内含文件），你可以将这些文件提供给智能体以教会它做事。智能体依靠文件系统工具遍历这些文件，通过遍历这些文件，它学会如何做事。

西蒙·威利森（Simon Willison）率先提出：技能或许能取代 MCP。与其直接为代理配备 MCP 工具，不如直接给它一堆文件，再加上命令行界面、代码解释器或网页访问权限，让它去完成任务。从理论层面来看，这种方法存在一些优势。

1.  它们定义和分享起来要简单得多。只需将一些 API 规范复制粘贴到一个 Markdown 文件中，或者输入几个非结构化的项目符号列表即可。然后，就这样！这个代理现在就知道该怎么做了。根据我自己的经验，编写 MCP 工具相对来说要麻烦得多。
2.  它们不会自动扩大代理的上下文窗口。如果 MCP 服务器定义了一个 `search` 端点并返回 10 万+ tokens 的搜索结果，调用 MCP 的代理默认会全盘接收。文件为代理提供了一个自然的接口，以便读取和搜索相关的上下文片段。
3.  他们使代理能够通过代码执行任意且更灵活的操作。借助技能，代理能够通过代码任意地与任何服务的 API 进行交互，即使该服务未定义 MCP。他们还允许代理执行诸如上传文件二进制数据之类的操作，而这在代理直接编写工具调用参数时是不可能的。

## 差距与前路

我提到过，通用代理推理 + 文件系统是计算机使用的一个良好初步替代方案（参见 Claude 协作）。话虽如此，为了让编码代理能够更准确、可靠、可扩展地解决更多任务，仍然存在一些需要解决的核心差距。

1.  解析非纯文本文档：代码代理并不具备读取 PDF、Word、PowerPoint、Excel 等非纯文本文件格式的先天能力。为了实现这一功能，它们需要调用优质的 OCR 工具，将这些文件转换为 LLM 可理解的格式。这正是我们在 LlamaCloud 中正在构建的核心能力，我们提供了包括解析、提取、表格处理等在内的一整套工具。我们还开发了 semtools 等开源封装工具，以便能轻松地将这些能力作为命令提供给代码代理使用。
2.  可扩展文件搜索：编码代理已将命令行工具作为文件搜索的主要手段，但我们发现，这种方法无法扩展到海量文档集合（1000-100 万+）。如 Mac OSX 等操作系统中的原生搜索工具并不理想。值得关注的是，我们如何将语义/关键词索引与文件搜索操作相结合，以实现可扩展且动态的搜索。
3.  文件编辑与生成：编码代理能够轻松为代码和纯文本文件应用编辑补丁。但它们需要专业工具来处理更复杂的格式和更繁重的工作负载，例如制作演示文稿、编辑图像或填写表单。目前针对 PPTX、DOCX、XLSX 格式已有初步的 Claude 技能集，但这些技能使用的是基础的开源工具。有很大的机会创建一套针对性的工具，使编码代理具备解决更多端到端工作任务的能力。

目前尚不清楚，作为一种格式的文件是否仍将是代理读取和与上下文交互的主要机制，但它目前正逐渐成为最佳模式。这与我们观察到的通过自然语言而非代码进行编程的整体趋势高度吻合。它也是实现通用计算机使用的踏脚石。

我们并非在构建通用的编码/计算机使用代理，但我们很荣幸能成为这一进程的核心组成部分。文档类文件需要处理，我们提供业界领先的技术，帮助您把 PDF、PowerPoint、Excel、Word、HTML 等文件转换为可供代理使用的上下文。来看看我们！
