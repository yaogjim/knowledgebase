# 我的 10 代理 OpenClaw 配置（+提示）

大多数人安装 OpenClaw 后，给它一个系统提示，然后疑惑为什么他们的代理没有做任何有用的事。

我花了好几个星期从零开始重建我的设备。

这是我运行的具体架构——任务控制仪表盘、Telegram 主题路由、模型选择和提示。

## 1\. 任务控制 - 本地 Next.js 仪表盘

你需要一个单一的真实来源。如果你的经纪人看不到发生了什么，他们就无法采取行动。

我在 Next.js 里搭建了一个本地运行的看板式仪表盘。每个特工都会从这块板子上读。这不是“可有可有”——而是协调层。没有它，代理人会重复工作或闲置。（最初灵感来自 @AlexFinn）。这里有一个关键点，我是在电脑本地运行的——因为我有全新的设备，或者你可以在 Mac Mini 或其他你喜欢的选项上运行！我之前用 VPS 运行过，但发现设置不太适合我的需求。

提示：

> 用看板风格的任务板 Next.js 创建一个任务控制仪表盘。它应实时更新，作为代理检查可用任务的主要中心。包括待办清单、进行中、审核和完成等列。

关键设计决策：代理自动检查待办列表。如果他们的领域里有任务，他们会排队然后接手。不需要布置。

## 2\. 模型选择——大家都忽略的部分

这比你的提示更重要。对每个特工都用克劳德·十四行诗，是你一周内消耗人类学积分的方式。

这是我的实际分摊：

10 个特工中有 5 个运行在 Kimi K2.5 上。 它作为分代理的工作比 Claude 便宜 5-8 倍。对于研究、趋势扫描和数据拉取等任务，你不需要前沿模型——你需要一个可靠且不会占用预算的模型。

成本堆栈：

- Claude Max：每月 100 美元（网页界面）
- Anthropic API：为 OpenClaw 代理提供独立计费
- Kimi Allegretto：每月 39 美元（含 OpenClaw 部署+2 次 K2.5 使用）
- Gemini API：Flash 免费套餐

规则是：将模型与任务复杂度匹配。克劳德→创意和推理性强的工作。有结构化检索和监控→Kimi。双子座闪电→简单作。如果你用 Sonnet 做一个每天检查两次黄金价格的 Cron 任务，那你就是在点燃金钱。

## 3\. 电报主题 - 孤立代理上下文

这是大多数人完全忽略的部分。

一个 Telegram 聊天涵盖所有内容=一个巨大的上下文窗口，对话交织在一起。Telegram 主题解决了这个问题。

8 个主题=8 个孤立的语境。 每个主题都有自己的内存文件。当我在“内容来源”中标记我的经纪人时，它会侦查并记录该主题的记忆。在“产品管理器”中，它会更新任务板。

路线：

```text
const topicRouter = {
  1: 'general',
  20: 'content-sourcing',
  32: 'product-manager',
  162: 'writing-agent',
};

function routeMessage(topicId, message) {
  const context = topicRouter[topicId] || 'general';
  writeToMemory(context, message);
  updateDashboard(context, message);
}
```

内存文件结构：

顺便说一句：Telegram 的机器人 API 把每个话题都当作一个独立的聊天 ID。你的机器人需要每个主题明确权限。漏掉一个→无声故障，没有错误提示。

## 4\. 心跳 - 克隆计划自主

心跳是特工保持主动而非被动的方式。每个间隔，代理都会醒来，检查仪表盘，扫描内存，并决定是否采取行动。

我开始时间隔30分钟。太激进了——空值机时烧代币。最终定了1-2小时的主动特工，夜间速度较慢。研究和趋势代理可以每3小时运行一次，因为他们的任务时间不紧迫。

提示：

> 每隔一个\[间隔\]，检查任务控制仪表盘，查找与你领域匹配的待办任务。如果有任务可用，排队，更新看板为“进行中”，然后开始工作。如果没有任务可用，可以扫描你最近的记忆，寻找值得标记的后续任务。无论如何都要记录简短的状态更新。

这也是模型选择的复杂性所在。一个 Kimi 特工每两小时跑一次心跳几乎不花钱。一个十四行诗代理人做同样的事情，积累起来很快。

## 5\. 全同步流

```text
Telegram message
 ↓
Parse topic ID → route to context
 ↓
Write to topic-specific .md file
 ↓
Dashboard reads memory/*.md → live UI
 ↓
Extract tasks → update taskboard
 ↓
Agent heartbeat picks up task → executes
 ↓
Result logged back to topic memory
```

## 6\. 约束条件 - 代理角色提示

每个代理都得到相同的结构：

提示：

> 你是\[角色\]。你的领域是\[特定范围\]。你可以使用\[工具\]。你的质量条是\[标准\]。你不能超出你的领域工作——如果任务超出你的范围，就在通用主题中标记它。每当心跳跳动时，查看仪表盘上你领域的任务。要主动出击，而不是被动应对。

这就是人们误解的地方。他们认为更多自由=产出更好。恰恰相反。当你限制了域时，代理实际上可以在这些框架内快速移动。当某样东西出现故障时，你可以隔离问题，因为每个代理的范围都是明确的。

不受约束的代理人就像一个黑匣子。一个受限的，你可以调试。

下一步是让代理之间能够沟通，并让任务交接更加顺畅！
