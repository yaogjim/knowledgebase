### **开场：Devin 的异步工作模式**

**Scott Wu：** Devin 是异步的。一旦你启动一个 Devin 会话，它就会开始工作，浏览代码，但你不需要一直陪着它。这就像你给实习生一个项目，然后你的实习生就去独立工作了。

**Claire Vo：** Devin 是我团队里最喜欢的实习生，而且我可以拥有无数个。

**Scott Wu：** 是的。

**Claire Vo：** 为什么你不挑选一个你可能会为你的产品处理的任务，并向我们展示你是如何端到端地完成它的？

**Scott Wu：** 我会说，“请去研究 ChatPRD MCP 服务器。” 这会为我们生成一个拉取请求（pull request）。通常你可以同时运行好几个这样的任务，这是一种很好的并行处理多个任务的方式，你只需要时不时检查一下每个任务的进展就可以了。

**Claire Vo：** 从“我如何使用 AI”的角度来看，这样做的一个好处是，你可以使用这样的工具进行大量的多线程工作，同时启动两、三、四、五甚至十个任务在不同项目上运行，而不用感觉自己必须坐在那里像“当保姆”一样盯着它们。

### **核心对话：Scott Wu 的 AI 工作流**

**Claire Vo：** Scott，感谢你加入“How I AI”。作为 Devin 在 X 上的头号回复者，我真的对这次对话感到非常兴奋，也期待你展示你的公司和你自己是如何使用这款至少让我非常开心的产品的，我相信它也让很多软件工程团队感到开心。所以，欢迎你。

**Scott Wu：** 非常感谢你邀请我。能来到这里是我的荣幸。我是你们和你们所有工作的忠实粉丝。

**Claire Vo：** 太好了。我们想深入了解……我们有很多要谈的，但我们真正想做的是深入了解你如何使用 AI，特别是你如何使用你所构建的产品。对于一个正在构建 AI 产品的人来说，有趣的是，这是一种你每天都能使用的东西，并且能变得非常擅长，但同时也可能向我们的听众和观众展示一些使用你构建的工具的技巧和窍门，这些是他们可能从未想过的。所以，我们正在从专家的视角来了解如何使用 Cognition 的产品。那么，你首先要向我们展示什么？当你进行工程工作或试图推动产品前进时，你的一些常见工作流程是什么？

**Scott Wu：** 当然。对我们来说，作为一群编程爱好者，构建一个能编码的 AI 可能是我们能投入时间做的最酷的事情之一。我想展示几个关于我们如何使用 Devin 技术栈的工作流程，因为它涉及到几个不同的部分：Slack、Linear、当然还有 Wiki、Ask Devin，以及启动 Devin 会话并从中获得拉取请求。我认为在如何与 Devin 这位“员工”共事方面，存在一些真正的细微差别，因为它与许多现有的工具非常不同，那些工具更多是像 IDE 或终端用户界面。我认为 Devin 首先是一个工程团队的成员。

**Claire Vo：** 完全正确。

**Scott Wu：** 那么，你通常会求助于 Devin 和其功能来解决哪些问题，你认为这些功能作为软件工程师，能真正带来改变？

**Scott Wu：** 我们喜欢把它描述为，Devin 是一个初级工程师。所以 Devin 不会去解决一些非常困难的架构问题，或者做出重大的战略决策，然后你在接下来的一个月里去执行。你可能还是想参与这些过程。Devin 可以在决策中帮助你，当然，通过参考正确的东西或者提供一些输入。但 Devin 真正闪光的地方是……我们有一种说法是“任务，而不是问题”。所以，当你有一个非常清晰的……“这就是我们需要做的具体事情”，并且有任务和所有我们需要的细节时，Devin 非常擅长去执行，并且能让这个过程快得多。所以自然而然，下一个问题就是，你如何确定规格或者……或者任务的具体内容，你想让它做什么。所以，许多其他工具，比如 Wiki 和搜索，都是为了让你能够提出正确的问题，了解代码库，或者了解需要做什么，然后把任务整合起来。在实践中，我们看到的大量用例，可能排第一位的就是处理你的问题积压（issue backlog）。每当有问题出现时，或者我们在很多 Slack 频道里讨论问题，我们都会把 Devin 作为处理任务的第一人选。这是一个很重要的方面。比如说，有人说“哦，我们需要修复前端的这个东西”，或者“我们需要支持另一个 MCP”，就像我们马上要展示的。诸如此类的事情。然后，对于许多其他所谓的“工程琐事”用例，它也做得非常好。所以，通常是进行版本升级，或者在你的代码仓库中添加文档，或者为你的特定功能添加单元测试，或者响应一个刚刚出现的崩溃报告并尝试诊断出问题所在。

**Claire Vo：** 我很喜欢你说的，Devin 是一个初级工程师。我说 Devin 是我团队里最喜欢的实习生，而且我可以拥有无数个。然后我喜欢这个关于范围界定是“任务而非问题”的想法。我确实认为，对于使用 AI 的人来说，甚至是工程领域之外的其他 AI 工具，真正考虑以任务为导向能让你更容易成功，或者说一系列任务会很有帮助。那么，你为什么不挑选一个你可能会为你的产品处理的任务，并向我们展示你是如何端到端地完成它的？

**Scott Wu：** 是的，我们开始吧。

**演示环节**

**Scott Wu：** 如你所知，我是 ChatPRD 的忠实粉丝。所以，我自然而然想到的事情是，我们需要将 ChatPRD 集成到我们的 MCP 服务器中。所以我正在研究如何用 Devin 来做这件事。

我通常开始的第一步是我们称之为 DeepWiki 的东西，它基本上可以为任何公共或私有代码仓库，生成一个由 AI 驱动的完整文档。所以在这里，有……Devin Web 应用的代码仓库……希望这里没有太敏感的信息。但它基本上……解释了 Devin，它从 Readme 文件或者系统架构中提取了很多信息。我可以搜索这个，调出不同的东西。所以，如果我想了解 MCP 市场是如何设置的，它会指出有哪些具体的组件或者哪些具体的文件被调用了。

**Claire Vo：** 所以你既得到了关于这个服务器列表如何实现的自然语言解释，同时在右侧，对于那些没有在观看的听众来说，你还能得到实际的代码片段和参考文件，你可以查看并真正理解代码的深层结构。所以你等于同时拥有了“让我解释它是如何工作的”和“这是具体细节”两部分。

**Scott Wu：** 是的，是英语和代码的结合。这很有趣，因为我觉得，总有一天可能全部都会是英语，但我觉得，特别是在现在这个时期，我们正处于一个工程师既想看英语又想看代码的时代。你可以看到这里，它给出了答案，指出了特定的内容，比如这里有我们的 Atlassian MCP，HubSpot MCP 等等。从这里，我接下来自然想做的事情是……我们发现这对很多人来说是一个很棒的工作流程，就是利用这个来为 Devin 生成一个提示（prompt）。

整个想法是，现在我们在这个上下文中，我们知道问题是什么，我们知道我们正在看代码库的哪个部分，这为 Devin 提供了一个很好的起点。如果我们心中有一个实际的任务，那么我们就可以开始执行了。所以我会说，“请去研究 ChatPRD MCP 服务器，并将其添加到这里的列表中。”

这个操作会……我用了“从此构建一个 Devin 提示”的功能。所以，它有我的提示，也就是我刚刚输入的，不是很精炼。但它也包含了……我们正在看的代码部分和组件的详细信息，等等。然后它会为我生成一个 Devin 的提示，我可以直接使用。你可以看到，它说，你要遵循像 Atlassian 和 HubSpot 这样的现有服务器的模式，这是它使用的具体类型定义结构，这是你应该调用的函数，这是你应该检查以确保它工作正常的东西。

**Claire Vo：** 我想为观众指出的一点，在工作流程方面他们应该思考的是，很多人，包括我自己，抱歉 Devin，会直接发送那个提示，也就是“将 ChatPRD 的 MCP 服务器添加到市场服务器列表”。我确实认为，这个虽然简短但很重要的循环——“获取这个提示，并根据你已知的上下文将其转化为一个有效的提示，然后再发送去执行任务”，能为你节省很多麻烦。而且，当时可能感觉像是额外的步骤，但我认为很快……第一，这会成为工具本身需要完成的工作，无论是通过这些推理模型还是某个应用层来管理它；第二，这对人们来说是值得的。所以，当你想发送一个五个词的提示时，不如先想一想，“这是我五个词的提示，帮我构建一个更好的提示”，然后再把它发送到你的系统中。

**Scott Wu：** 是的，完全正确。这是一个很好的提醒，因为就像我们说的，Devin 是异步的。从这一点开始，好处在于，一旦你启动了 Devin 会话，它就会开始工作，浏览代码，在网上阅读关于 ChatPRD 的资料等等。而你不需要一直陪着它。它会自己工作。这就像你给实习生一个项目，然后你的实习生就去独立工作了。他们可能会在 Slack 上联系你，问你问题，或者你可以去快速看一下你的实习生做得怎么样，但你不需要一步一步地陪着 Devin。

### **多线程工作与团队协作**

**Claire Vo：** 我们之前也谈到过，Devin 的异步特性使多线程工作成为可能，让你能够同时管理多个项目。在你的日常工作中，你是如何利用这一点的？

**Scott Wu：** 对，我大部分时间都在开会。能够在会议间隙启动这些任务，或者处理积压的问题，比如今天有三四个我想看的事情，然后为每一个都启动一个 Devin 任务，这对我帮助很大。Devin 会异步地去完成这些工作，然后创建拉取请求，展示它做了什么。如果是一个前端的改动，它会给你发送修改前后的截图，这样你就能在 Slack 里直接评审。

**演示 Slack 集成**

**Scott Wu：** 我可以展示几个例子。Devin 已经成为了我们处理很多问题时的第一道防线。基本上，几乎所有事情，第一个被标记的人就是 Devin。当然，它不可能一次性解决所有问题，但我们会和 Devin 来回沟通，它会提交拉取请求，如果需要一些微调，我们的工程师会介入。这是一个很好的协作方式。

比如这里，一个同事说：“Devin，你能把通知的 command-click 功能做成在新标签页打开吗？” 这是一个很自然的功能请求，可能来自我们的用户。然后我们就启动了一个 Devin 会话。Devin 会给出一个进度更新，说“这是我目前正在做的事情，这是我正在看的文件。” 在这个例子里，它的信心是“中等”，然后另一个工程师 Ethan 介入，给了一些建议。Devin 收到反馈后，就去修改了拉取请求。你可以看到，Devin 创建了初版，然后又根据反馈提交了新的修改。最终，工程师 Dave 合并了代码。

这个过程就像一个团队协作的线索，Devin 是其中的一个参与者。大家可以在同一个地方沟通，看 Devin 在做什么，然后一起解决问题。

### **Devin 的五大最佳应用场景**

**Claire Vo：** 那么，回到最初的问题，能不能总结一下，你认为 Devin 最擅长的五类任务是什么？

**Scott Wu：** 好的，前五名。
1.  **各种前端修复**：这对它来说太棒了。因为通常这个流程需要三个人参与，现在你只需要用截图向 Devin 解释清楚，比如“把这个按钮调圆一点”，它就能找到相关的代码并完成。
2.  **版本升级和迁移**：比如升级 Node.js 版本或更新依赖包，这些我们都必须做，但过程很繁琐。Devin 在这方面是个巨大的时间节省器。
3.  **文档**：无论是 DeepWiki 自动生成文档，还是让 Devin 编写具体的文档页面，它都做得很好。我们自己的外部文档网站几乎都是 Devin 写的。
4.  **事件响应**：我们设置了让 Devin 成为 PagerDuty 上的第一响应者。当有崩溃报告时，首先是 Devin 去分析，它会运行一个会话，写一份报告说“我看了，觉得是上周的某个改动导致的”，然后把相关信息发出来。
5.  **添加测试**：这是每个工程师在提交代码前都应该做的，但也是最容易被忽略的。Devin 可以很好地完成这项工作，它会编写测试，在本地运行确保通过，还会检查 CI/CD 流程。

**Claire Vo：** 我完全同意。我的清单和你的很接近。前端修复，我特别会用它来做“润色”的工作，那些让用户体验更好的小细节。文档，我有一个 GitHub Action，每次有新的拉取请求，都会让 Devin 帮忙重写描述，PR 合并后，Devin 会自动把更新同步到我们的内部文档库里，这样 Devin 自己就能访问最新的文档了。事件响应，我也有类似的设置。还有就是“橡皮鸭调试”（rubber ducking），随时随地都能和它讨论问题，这非常有用。

### **AI 语音助手与未来的人机交互**

**Claire Vo：** 我们来聊聊 Devin 生态系统之外的一个话题——语音。你之前跟我提到了一个很有趣的 ChatGPT 语音用例。

**Scott Wu：** 是的，我非常喜欢语音功能。我们甚至在 Wডসurf 中也加入了语音功能，部分也是因为这个原因。在会议中，总会有各种问题冒出来，比如“有多少公司的软件工程师超过一万名？” 过去，大家会在会议中偷偷拿出手机查，这其实很没礼貌。现在，我可以直接打开 ChatGPT 的语音模式，就像在会议里加入了一个新成员一样。我问它问题，它会回答，这比大家低头看手机要自然得多。它就像一个更好的 Google，能更快地给你答案，而且是完全同步的，就在对话中完成。

这其实是一个人机交互的自然演进。以前查资料要翻百科全书，可能花五分钟；后来有了 Google，变成了十秒钟；现在有了语音，可能只需要一两秒，你就直接说出你想问的。这种效率的提升意义重大。

**Claire Vo：** 最后一个问题：IDE、终端还是 Agent，你认为哪种形式会主导未来的 AI 工程？

**Scott Wu：** 我认为这其实是关于人机交互的下一代形态。托尼·斯塔克没有笔记本电脑，他有贾维斯。未来，你可能不需要通过看代码来构建软件，而是直接看着你的产品，通过对话来修改它，比如“把这个按钮变圆一点”，“在这里加个新东西”。你的 AI 代理会去实现这些。

就今天而言，这取决于你的角色。对于一个每天写八到十小时代码的工程师来说，IDE 是最自然的起点。但对于像我这样整天开会的人，或者产品经理，通过 Slack 或 Linear 来启动任务就更自然。最终，我认为这些界面会融合，变成一种更加直接、以产品为中心的交互方式。

**Claire Vo：** Scott，非常感谢你今天的分享。我们可以在哪里找到你和你的产品？

**Scott Wu：** 我们在 Twitter 上是 @cognition 和 @devin，也可以访问我们的网站 devin.ai。

**Claire Vo：** 再次感谢。

### **第二部分：利用 Devin 完成具体开发任务的实战演示**

**主题与要点：**
*   **任务分配：** Scott Wu 演示了如何通过一个明确的指令，让 Devin 为其平台添加一个新的 ChatPRD 服务器到市场服务器列表中。
