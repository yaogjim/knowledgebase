提示工程正在逐渐式微

进入上下文工程

（也许还没死透——而是正在演变成更强大的东西）

随着人工智能从简单的聊天机器人发展为自主智能体，仅靠巧妙的提示是不够的。真正的挑战在于协调一整个信息和工具的生态系统，以便模型能够真正完成任务。

那么，上下文工程在实践中是什么样的呢？

核心组件：

👤 用户信息：偏好设置、历史记录和个性化数据

⚒️ 工具与应用程序编程接口：计算器、搜索引擎，或大型语言模型完成任务所需的任何东西

📖 检索到的知识：来自数据库或外部来源的动态信息

💻 用户输入：任务或查询本身

⛓️ 大语言模型推理：思维链与决策逻辑

🧠 对话记忆：提供连贯性的先前交互

内存起着至关重要的作用：

• 短期记忆：存在于上下文窗口中，用于当前对话

• 长期记忆：存储在外部（向量数据库、知识库），以留存偏好和过往交互记录

大语言模型不是读心术。输入垃圾，输出垃圾的原则仍然适用。不同的是，现在我们要考虑整个输入正确“垃圾”……我是说，上下文……到我们模型中的流程。

你要问自己的关键问题是：“基于我所提供的信息，大语言模型（LLM）有可能完成这项任务吗？”

上下文工程不仅仅是提示之后的下一步，它是构建能让人工智能真正取得成功的系统。

## 摘要与评价（论断）

- 这张图主张：要让智能体给出更好答案，关键在于“上下文工程”（Context Engineering）——把短期记忆（对话上下文）、长期记忆（数据库/MCP 资源）、RAG 检索与工具调用，在一个“Agent”里按步骤编排，动态拼装成 Prompt，再产出答案并回写记忆。
- 价值判断：
    - 优点：把信息流清晰分层（短期/长期）、引入检索与工具、可持续学习（写回记忆），符合当前最有效的 LLM 系统设计范式。
    - 可能不足：未显式展示安全与隐私控制、记忆写入的“门控策略”、冲突/过时信息的处理、成本与时延优化，以及评估闭环。

## 深度解读（深入浅出）

### 关键构件与它们解决的问题

- 短期记忆（Short-Term Memory）
    - 就是本轮对话窗口里的“可见上下文”，容量受 token 限制，用于即时对齐语境。
- 长期记忆（Long-Term Memory）
    - 数据库/向量库、文件库、以及 MCP 服务器（把外部工具/资源通过统一协议暴露给模型）。用于持久知识、用户偏好、历史结论等。
- Agent（智能体编排）
    - 负责“要不要检索/用什么工具/怎么计划调用”的决策与协调，并把拿到的结果融合进 Prompt。
- RAG（检索增强生成）
    - 对长期记忆做向量搜索，取回与问题最相关的片段，降低幻觉、补齐事实。
- Action Tools（行动工具）
    - 代码执行、调用 API、读写文件、运行工作流等，把“会说话”变成“会办事”。

### 颜色与内容类型（图例）

- 浅紫：用户输入
- 深紫：工具用法/Schema
- 青蓝：RAG 检索上下文
- 浅绿：Agent 推理/计划
- 橙色：聊天历史
- 淡紫灰：用户信息

### 按步骤看数据流（图中 1→8）

1. 用户输入进来（短期）
2. Agent 读入当前 Prompt（含历史、用户信息、工具说明）开始计划
3. 如需要事实支撑，触发 RAG：向量检索长期记忆，取回相关片段
4. 如需要行动，调用工具（API/代码/工作流），拿到结果
5. Agent 把检索/工具结果写回 Prompt，形成完整上下文
6. 生成答案返回给用户
7. 把本轮的关键上下文写入短期记忆（用于后续轮次连贯）
8. 选择性写入长期记忆（总结、嵌入、去重），用于持久化个性化与知识沉淀

### 为什么要这样“工程化上下文”

- Token 预算有限：把“最必要的信息”装进 Prompt 才高效。
- 事实与行动分离：用 RAG 提供证据、用工具完成动作，Agent 只做编排与推理。
- 持续学习：对话结束不等于记忆结束，写回长期记忆让系统越来越懂你。
- 可观测与可控：每一步都能度量与优化（召回率、延迟、成本、正确率）。

### 一个迷你例子

- 任务：给我制定一周低碳饮食计划，考虑我对花生过敏且周三只吃两餐。
    - 1 输入：用户需求+过敏信息
    - 2 Agent：判断需要个性化与营养事实
    - 3 RAG：检索长期记忆中的用户档案（过敏）、营养数据库
    - 4 工具：可选调用热量计算器 API
    - 5 融合：把检索片段与工具结果塞回 Prompt
    - 6 输出：周计划+热量/宏量营养素
    - 7 短期：把“周三只吃两餐”的偏好加入当轮上下文
    - 8 长期：总结为“用户饮食偏好档案”，下次自动避开花生并优先两餐模板

## 我的意见（可操作建议）

- 记忆写入要“有门槛”
    - 引入记忆评分与去重：相似度阈值+新鲜度+置信度；只写“稳定偏好/结论/事实来源”，避免把瞬时噪声固化。
    - 设置 TTL 与版本化，定期重写长记忆的摘要。
- RAG 最小可行配置
    - 文档分块 300–800 tokens；存 metadata（来源、时间、作者）；Top-k 取 5–10，再用重排序模型精排；对引用片段加标注。
- Prompt 工程
    - 固定系统提示+角色目标+工具说明+约束（引用必须来自 RAG 片段、不得臆测）。
    - 对工具返回格式强约束（JSON Schema），减少解析失败。
- Agent 决策
    - 先检索再行动的优先级；多步调用设上限与中止条件；为关键动作加“复核回合”（self-check）。
- 评估与观测
    - 指标：答案正确率/引用命中率、时延、成本、工具成功率、用户满意度。
    - 回放流水线（日志+prompt/检索片段/工具调用）便于复盘。
- 隐私与合规
    - 长期记忆分级加密；对 PII 做脱敏摘要；提供“遗忘”与导出机制。
- 成本与延迟优化
    - 先低成本嵌入+粗排，再小模型重排；缓存热门检索与工具结果；对长历史做滚动总结。
- 渐进式落地
    - 从“RAG + 简单工具 + 记忆门控”开始；稳定后再加多工具编排与复杂工作流。

一句话归纳：上下文工程=用“检索与工具”补强“短期 Prompt”，再用“门控的长期记忆”让系统持续进化；工程化每一步，让模型既聪明、又稳健、又可控。
