# Human in the Loop Middleware (Python)
YouTube 视频地址：https://www.youtube.com/watch?v=SpfT6-YAVPk

大家好，我是 Sydney，LangChain 的一名开源工程师。今天我非常激动地向大家介绍我们全新推出的“人在回路”（Human in the Loop）中间件。

### 核心 Agent 循环

首先，我们来了解一下核心的 Agent 循环。Agent 本质上是一个在循环中调用工具的模型，直到它决定提供最终的响应。我们对这个循环稍作修改，以便加入“人在回路”的环节。

“人在回路”中间件在您希望执行工具前获得人工反馈的场景下非常有用。这对于那些运行成本高昂或存在风险的工具尤其关键。您可以在图表中看到，模型调用工具后，在实际运行这些工具之前，我们会根据条件将其通过“人在回路”中间件节点进行处理。

### 用户反馈的类型：批准、编辑与拒绝

该中间件为用户响应“人在回路”中断提供了几种不同的方式。三种最常见的方式是：批准、编辑和拒绝。

举个例子，假设我们正在开发一个邮件助手，Agent 在实际发送邮件前需要征求用户意见。
*   **批准（Approval）**：意味着我们完全按照草稿的原样发送邮件。
*   **编辑（Edits）**：我们可以更改邮件的收件人或正文内容。
*   **拒绝（Rejection）**：意味着完全拒绝该草稿，并可能向模型返回一条消息，解释如何重写草稿。

接下来，让我们进入代码演示部分。

### 代码演示

好了，这里是我们的发送邮件示例。我们编写了一个基础的 `send_email` 工具，包含收件人、主题和正文三个参数。然后，我们用这个工具创建了一个 Agent。这个 Agent 使用了 GPT-4，并带有一个简单的系统提示，告诉它它是一个为我（Sydney）服务的、能发送邮件的得力助手。

我们来模拟回复一封来自 Alice 的邮件。我们将跳转到 LangSmith Studio，这是一个非常棒的、可以交互式测试 Agent 的平台。我们模拟发送这条人类消息，可以看到消息被发送到模型，模型随后调用 `send_email` 工具，然后邮件成功发送至 alice@example.com，内容是：“下周很乐意与你一起喝杯咖啡。”

现在，我们回来用两行代码添加“人在回路”中间件。

我们要做的第一个改动是导入“人在回路”中间件：`from langchain.agents.middleware import human_in_the_loop_middleware`。
然后，在这里我们添加 `middleware=human_in_the_loop_middleware`，并通过设置一个布尔值为 `true` 来指定在 `send_email` 这个工具上进行中断。

我还要补充一点，这个中间件有更多可用的配置。例如，您可以指定一个允许的决策列表，也就是我们前面提到的“批准、编辑、拒绝”等类型。但在目前这个例子中，我们只需要使用这个简单的布尔值就够了。

现在，让我们回到 Studio，体验一下如何回复收到的邮件。

#### 场景一：批准

我们回到了 Studio，可以看到我们的流程图已经更新了。我将开启一个新线程，模拟回复那封来自 Alice 的、风险不高的邮件。

同样，我们看到了工具调用的流式过程，但这一次，在“人在回路”中间件中，一个中断被触发了。在这种情况下，邮件风险很低，草稿看起来也很好。所以，我们可以直接用一个简单的“批准”决策来回应。我们点击“继续”，然后可以看到邮件成功发送给了 Alice。

#### 场景二：编辑

现在，我们来模拟回复一封稍微重要一些的邮件。这次，我们要回复 partnerstartup.com，邮件内容是关于签署第一季度一百万美元的工程预算。

我们模拟 Agent 的运行，同样看到了操作请求。在这种情况下，草稿表明我们已经审阅并批准了该提案。我觉得在这里我们可能需要表现得更谨慎一些。所以，让我们来模拟一下对“人在回路”请求进行“编辑”的回应。

我在这里粘贴了另一个决策内容。这一次，它的类型是“编辑”，后面跟着一个经过编辑的动作，其结构与邮件工具的调用结构相同：`name` 是工具的名称 `send_email`，`args` 是我们在工具调用签名中看到的参数。我将它发送给同一个收件人，但附上了一段简短的正文。

当我们使用“编辑”类型的决策继续时，我们应该会看到工具仍然被执行，只是直接使用了这些被编辑过的参数。所以，流程的下一步应该是工具节点。我们点击“继续”，看到工具节点被执行，邮件成功发送，并且正文是我们编辑过的内容。

#### 场景三：拒绝

作为最后一个案例，也就是“拒绝”的案例，我们再次来回复这封更重要的邮件。我们看到的草稿说我们已经批准了它。但实际上，我们想向模型反馈一条消息，要求它修改草稿，并说明我们在批准前需要了解更多关于提案的细节。

这是我们新的响应内容，决策类型为“拒绝”，并附上了那条反馈消息。看起来模型现在再次调用了 `send_email` 工具，并使用了修改后的邮件正文，按照我们的要求询问了提案的更多细节。

请记住，我们的流程中仍然有“人在回路”这个节点。所以，在最终邮件发送前，我们还需要进行批准。

好了，我们的邮件已经成功发送。
