## Claude-Code

### 又调整了一下我的 Agent Coding 工作流

**Kevin Ma** @kevinma_dev_zh 2026-01-01

又调整了一下我的 Agent Coding 工作流：

1. 安排任务，用 Plan Mode 确认方案，然后开始编码

2. 编码完成后自动跑 code-reviewer subagent，有问题自己处理

3. 调试、测试、迭代

4. 测试没问题，跑 code-simplifier 看看有没有能简化的代码，确认后优化

5. 跑 codex-reviewer 做 PR 前的 Code Review，自动评估和修复

6. 创建 PR，触发 Gemini bot 做 Code Review

7. 处理 Review 意见，没问题就合并到主分支

8. 打包、验证、发布

整套流程跑下来，相比以前更方便了，人主要就是安排任务、确认、决策和测试。

**跟帖精选：**

- **Meepo**: 只管给 Claude 布置任务，不考虑 Token 消耗，只对结果进行验收对吧。
- **Kevin Ma**: 不考虑 Token 消耗，布置任务、对结果验收，再给指令迭代。可以按照自己的需求优化那两个插件，有作用的
- **Ethan AI实验室**: 我现在的工作流是用4分屏模式：左上角用来娱乐，右上角用来调试，左下角用来规划下一个功能如何做，右下角用来实际工作。规划功能，用claude code来做，实际开发用opencode搭配codex来做。效率贼高，开发出来的质量非常好。
- **Ticky**: plan mode 那步可以优化下，用openspec提需求，迭代需求。我自己还会用个.rule，让他静默记录我的提示词过程，让他录到history.log，目的是探测有没有可能基于我的工作习惯，提炼出新的workflow。

## Skills开发

### Claude Skills 入门

**Wang Shuyi** @wshuyi 2026-01-12

你有没有这种感觉——AI 领域的新名词，比手机型号更新还快？

昨天刚搞懂「函数调用」(Function Calling) 是怎么回事，今天又冒出来个「Skills」。前天有人跟你说「MCP」，你还没反应过来，后天又有人聊「Agent」。

**三层架构理解：**

1. **函数**：程序员几十年来最基本的生产力工具，把一件事情的做法「打包」起来，以后谁都能用。

2. **函数调用**：给那个「只会聊天的 AI」配了一部电话和一本通讯录。AI 可以自己判断该不该调用某个函数。这是一个巨大的进步——AI 不再只是「知识库」，它开始变成「行动者」。

3. **Skills**：「员工手册」+「工具箱」的组合。一个 Skill 就是一个文件夹，里面有三样东西：
   - 指令文件（自然语言写的）
   - 脚本（Python、JavaScript 等）
   - 资源文件（参考文档、模板、配置文件）

**核心区别**：函数调用是「单个工具」，Skills 是「整套解决方案」。

**真实案例**：
- Markdown 转 X Articles：原本 20-30 分钟的手动操作，现在几分钟内全自动搞定
- 会议管理：自动从会议记录里提取摘要、决策和行动项
- 数据分析：自动识别关键指标、找出异常值，生成报告

**最重要的一点**：创建 Skill 不一定需要会写代码。里的指令是自然语言写的。

### 你可能不再需要 workflow，大部分场景 skills 足矣

**宝玉** @dotey 2026-01-12

我的观点是：大部分 workflow 编排场景，都可以被 Agent + Skills 取代。

**传统 workflow 的问题**：
- 它不够强大。可视化节点能做的事情有限，复杂逻辑很难表达。
- 它不够灵活。一旦流程定死，遇到输入变化就容易出错。
- 它难以移植。平台锁定效应明显。

**五步框架：**

1. **拆分模块**：把工作流拆成单一职责的 skill 或 subagent。每个模块只做一件事，做好一件事。

2. **编排协作**：在主 skill 里用自然语言描述整个流程。不需要写代码，就像给同事交代任务一样说清楚就行。

3. **持久化中间态**：可追溯、可断点续传、可人工干预。

4. **传路径不传内容**：传路径，subagent 自己去读文件，上下文就干净很多。可以并行启动多个 subagent。

5. **持续迭代优化**：发现某个 skill 的提示词不够好？让 Claude Code 帮你改。

**Agent + Skills 最大的优势**：可以持续进化。你的 skills 会越用越好，而不是搭完就放在那儿吃灰。

### 手把手教你多平台使用Skill

**岚叔** @LufzzLiz 2026-01-12

最近skill 已经火出圈了，如何让你的skill在多平台或者多个模型用起来？

**步骤：**

1. 安装 openskills：`openskills install anthropics/skills`
2. 安装你想要的 skill：`openskills install ~/.claude/skills/notebooklm`
3. 同步至 Antigravity 或其他平台：`openskills sync --output ~/.gemini/GEMINI.md`

**原理**：渐进式披露。触发机制一致，推荐使用 openskill 管理你的 skill。

### 上下文管理：Issues 和 PR 的正确用法

**Kevin Ma** @kevinma_dev_zh 2025-12-30

跟 AI 协作久了，容易踩一个坑：把聊出来的东西都往文档里塞。时间一长，过时信息一堆，AI 读了反而被干扰。

**这个问题的根源**：混淆了过程性上下文和持久性文档。

**解决方案**：
- Issues 和 PR 本来就是管理"过程"的工具，直接复用就行。
- 每个任务创建一个 Issue，把背景、方案、任务拆解、验收标准都放进去。做完就关掉，过程性的东西随之归档。
- docs 目录只存放真正需要长期维护的持久性文档（PRD、架构设计、API 规范等）。

**本质**：复用成熟的人类团队协作经验，把每个 Agent 当作团队成员。

**跟帖精选：**
- **Jimmy_JingLv**: 你是通过GitHub MCP之类的让agent去读issue内容吗？
- **Kevin Ma**: 我使用gh命令，模型自动会去找这个命令。只需要安装授权一次，任意 agent 都能调用，比mcp优雅。

### 我的开发工作流：Claude Code + Codex + Gemini

**Kevin Ma** @kevinma_dev_zh 2025-12-29

我主力使用 Claude Code, Codex CLI 和 Gemini CLI，组成一个开发团队。

**分工**：
- **Claude Code**：写代码快，小任务一把梭没问题。但任务一大，几乎必定有 Bug。
- **Codex**：负责 Review。无论是技术方案还是代码实现，我都习惯交叉评审。
- **Gemini**：做 planning，输出设计文档。我更适应它的文字风格，跟它聊起来比较舒服。

**工作流**：Gemini 做 planning → Claude Code review 这个 plan，然后负责执行 → Codex 依据 planning doc，review 代码并优化。

**工具配置**：一个终端窗口，用 tmux 管理，能随时在三个 agent 窗口、nvim 和一个运行服务的窗口之间随意切换。

**付费情况**：都付费的，这三家基本上是日常必备模型和工具了。Gemini 免费也可以有额度用。

### 不要再吹 OpenCode 了，推荐 Droid

**老鬼** @laogui 2026-01-11

不要再吹 OpenCode 了，我在他们分家之前就开始用了，从来没感觉到它好用。

如果你真的在找一个可以匹敌 Claude Code，还支持 BYOK 的编程工具，我更推荐 Droid。

**Droid 的强项**：
- 上下文工程管理做的好
- 有一套多层"上下文栈"，把工具组织好的一切信息逐步蒸馏成"当前任务刚好需要的内容"

我现在遇到一些很复杂的任务，如果对 Claude Code 的结果不太满意，就换成 Droid 再做一遍，经常给我带来惊喜。

### Claude Code 觉得完美的代码，Codex review 出无数的 Bug

**Larry & Leo Bro** @xqliu 2025-12-29

Claude Code 觉得完美的代码, Codex review 出无数的 Bug ... 重点是, 贴给 Claude, 一个劲说对对对,确实有这个问题...... 这可咋搞

**解决方案汇总：**

1. **双重 Review**：Opus 和 Codex 都 review
2. **MCP 集成**：在 claudecode 里面接一个 codex 的 MCP，每次 claude 会自动跟 codex 进探讨、review、交叉对话
3. **自动循环**：Claude，你提出方案后，请立马交给 Codex Review，循环上述两个步骤，直到通过为止

**分工建议**（Mr.Wong）：
- CC 写大代码，CDX 检查，CC 改，CDX 复查
- CDX 写不了量级比较大的代码，很容易出错，但 CDX 改错定位能力很强
- CC 的能力是广度的，CDX 的能力是深度的
