### Claude Code的偶然诞生与全新范式的确立

Claude Code 的诞生并非源于一个精心设计的宏伟蓝图，而是一系列偶然事件和工程师为解决自身问题而进行的探索性尝试的产物。Boris 分享道，这个过程充满了意外的发现。在他刚加入 Anthropic 时，团队内部已经存在一个名为 “Clyde” (CL-IDE 的谐音) 的工具，这是 Claude Code 的前身。然而，Clyde 是一个相当笨重的研究项目，启动需要一分钟之久，并且依赖于一个复杂的 Python 环境进行大量索引工作。作为一个新人，Boris 对这些内部工具并不了解，于是他像一个“新手”一样，手动编写并提交了他的第一个拉取请求 (Pull Request, PR)。他的直属经理 Adam Wolf 看到后，直接拒绝了这次提交，并留下了这样的评论：“你这是手写的？你在干什么？用 Clyde。”

这次经历促使 Boris 第一次尝试使用 Clyde。尽管当时使用的是较早期的模型（大约是 Sonnet 3.5 版本），并且工具本身非常陈旧，整个过程耗时约五分钟，但他依然被结果深深震撼了。他仅仅给出了任务的描述，Clyde 几乎是一次性就完成了任务，只剩下一些小问题需要他手动修复。这次体验让他大开眼界，意识到这套工作流是完全可行的，并开始在他脑中种下了一个念头：也许工程师根本不需要一个传统的集成开发环境 (Integrated Development Environment, IDE)。

这个想法的真正落地，源于他之后的一次原型开发。为了快速测试 Anthropic 的 API，最便捷的方式是在终端 (Terminal) 中构建一个小型应用程序，这样可以完全绕过构建用户界面 (UI) 的繁琐工作。他先是开发了一个简单的聊天应用，随后便萌生了“不如做一个精简版 Clyde”的想法。出乎意料的是，这个没有经过太多复杂设计的精简版工具，在实际使用中展现出了远超预期的实用性。而整个过程中最关键、最具启发性的一个时刻，是当他们开始赋予模型“工具”的时候。Boris 描述那个瞬间为“疯狂的时刻”。他说：“模型就是想要使用工具。我们给了它 Bash，它就开始使用 Bash，甚至编写 AppleScript 来自动化处理一些问题。这简直是我见过最疯狂的事情。” 在此之前，他所接触的 AI 编程工具，无论是单行还是多行的代码补全，都局限于在 IDE 内部进行文本编辑。而现在，模型展现出了直接与操作系统环境交互的强大能力。这个由原型开发、对现有工具的观察以及一个突破性发现共同催生的产物，最终演变成了我们今天看到的 Claude Code。Cat 补充说，对她而言，那个神奇的“顿悟时刻”发生在使用 Sonnet 4 或 Opus 4 模型时，那一刻她才真正感觉到：“天啊，这东西真的能用了。”

### 为人与模型设计的双重用途工具及“Ant Fooding”文化

Claude Code 的一个核心设计哲学在于其工具的构建方式，特别是它与底层操作系统环境的深度融合。与许多 AI 代理 (Agent) 架构选择为模型封装特定工具（例如 `find_file` 或 `open_file`）不同，Claude Code 从一开始就大胆地赋予模型直接使用 Bash 的能力，并且模型在实际应用中表现得异常出色。Dan 提出，这种直接使用 Bash 的方式似乎是 Claude Code 的“特殊之处”，并询问团队从中获得了哪些经验。Boris 解释说，虽然 Claude Code 目前实际上拥有一系列（大约十几个）专门的工具，并且团队每周都会对其进行增删调整，但其最终目标是尽可能地“去工具化”，让模型的交互界面保持简洁。

目前保留特定工具（如搜索工具）主要有两个原因。首先是为了优化用户体验 (UX)，这样可以在界面上更友好地向用户展示搜索结果，因为在大多数任务中，人类仍然是整个流程中不可或缺的一环。其次是为了权限管理。用户可以在 Claude Code 的配置文件（如 `settings.json`）中指定某些文件或目录是不可读的，而拥有一个专门的搜索工具可以更高效地执行这些权限策略。尽管如此，团队的长期方向是简化这一切。Boris 举例说，他们最近就移除了一个操作系统 (OS) 工具，因为过去需要它来配合权限系统，但现在他们已经构建了一套能够直接为 Bash 命令强制执行权限的机制。这意味着，如果系统知道 Claude Code 无权读取某个目录，那么任何试图访问该目录的 Bash 命令都会被阻止。由于实现了这种一致性的强制执行，那个专门的 OS 工具就变得多余了，这不仅为模型减少了选择的复杂性，也节省了宝贵的上下文空间。

这种独特而高效的产品迭代和功能创新，离不开 Anthropic 内部一种被称为“Ant fooding”的文化。当被问及团队成员如何分工时，Cat 谦虚地表示 Boris 负责设定技术方向和产品愿景，而她自己更多扮演支持角色，确保定价、包装符合用户需求，并引导新功能完成整个发布流程。她特别强调了“Ant fooding”的重要性。“Ant fooding”实际上是科技行业常见的“Dog fooding”（内部测试）的 Anthropic 版本，因为 Anthropic 内部员工的昵称是“Ant”（蚂蚁）。Cat 透露，超过 70% 甚至 80% 的 Anthropic 技术员工每天都在使用 Claude Code。这意味着，每当团队构思一个新功能时，他们会先在内部发布，然后就能迅速获得海量的反馈。他们的反馈渠道几乎每五分钟就会有一条新消息，这使得团队能够极快地判断一个功能是受欢迎、存在缺陷，还是应该被直接放弃。Dan 对此深表赞同，他认为只有当构建者自己也在高频使用产品时，产品的“人体工程学”才能真正做到合理，这种自下而上的开发模式是创造优秀工具的关键。Boris 补充说，团队中的每一个人都是产品方向的贡献者，许多核心功能，如待办事项列表 (to-do lists)、子代理 (sub-agents) 和钩子 (hooks)，都是团队成员自下而上创造出来的。例如，`bash mode`（通过输入“!”来直接执行 Bash 命令）这个功能，就是 Boris 在日常使用中感到在两个终端间来回切换很烦人，于是他让 Claude Code 帮忙构思解决方案，模型提出了这个想法，他觉得很棒，便让模型实现并发布了。这个功能不仅对人类用户非常有用，对模型本身也同样有价值，因为模型能看到命令的完整输出，这完美体现了 Claude Code “双重用途”(dual use) 的设计哲学。

### 构建可扩展的代理与本地优先的开发哲学

Claude Code 的强大之处不仅在于其功能，更在于其架构设计上的几个关键决策，这些决策共同构成了一个简洁而又极具可扩展性的系统。首先，它摒弃了传统的代码编辑器界面，选择将交互完全置于终端之中。其次，它是一个运行在用户本地计算机上的工具，而非云端的虚拟机。这两个决策使得 Claude Code 能够无缝访问用户的本地文件系统和开发环境，从而实现高度的组合性和可扩展性。用户可以通过编辑 `claude.md` 文件、创建自定义斜杠命令 (`/command`) 等方式，从一个非常简单的起点逐步构建出极其强大的个人工作流。

当被问及如何构建这样一个能够随时间推移而不断扩展的简洁核心时，Boris 引用了 Y Combinator 的经典理念：“你必须首先解决自己的问题。” 他认为，如果你能为自己创造一个有效的解决方案，那么这个方案很有可能也能解决其他人的问题。对于编码这个场景，从本地环境开始是最合理的选择。他强调，虽然现在 Claude Code 也提供了网页版，支持在虚拟机或远程环境中使用，这对于在移动设备上进行紧急修复（例如，他在等红灯时通过手机在 GitHub 上 `@claude` 修复问题）非常有用，但对于大多数核心开发工作而言，本地优先的原则依然是正确的。

斜杠命令是体现其可扩展性的一个核心功能。Cat 提到她最常用的命令是 `/commit`，这个命令能让 Claude 更快地知道需要运行哪些确切的 Bash 命令来完成一次代码提交。Boris 进一步解释了斜杠命令背后的技术细节。它不仅仅是一系列预设的命令，还内置了一套强大的模板系统。这意味着在执行命令前，系统可以预先运行一些 Bash 命令，并将结果嵌入到最终发送给模型的提示中。此外，斜杠命令还支持预先授权特定的工具调用。例如，在 `/commit` 命令的定义中，可以预先允许 `get commit`、`get push` 等操作，这样用户在执行该命令时就不会被频繁地请求权限确认，从而极大地提升了流畅性。有趣的是，这些命令通常会使用更轻量、更快的 Haiku 模型来执行，以降低成本和延迟。

除了 `/commit`，团队内部还广泛使用其他强大的斜杠命令。例如，`/feature dev` 是一个由团队成员 Sid 创建的命令，它将复杂的特性开发过程结构化。它会引导 Claude 首先与用户沟通，明确需求规格，然后制定详细的计划，创建一个待办事项列表，并逐步执行。这为新功能的开发提供了一个更加严谨和可控的流程。此外，团队还使用 `/security review` 和 `/code review` 等命令，Claude 甚至承担了 Anthropic 内部所有代码审查的第一遍工作，虽然最终仍需人类批准，但这极大地提高了效率。

### 高级代理工作流：规划、原型与子代理

随着用户对 Claude Code 的掌握越来越深入，一系列高级的代理工作流和使用模式也随之涌现，这些模式极大地拓展了 AI 编程的边界。Dan 分享了一个他自己摸索出的、看似有违直觉但非常有效的技巧。当他对一个新功能只有一个模糊的想法时，他会先让 Claude 在几乎没有任何详细说明的情况下直接尝试实现它。他会观察 Claude 的实现过程，分析它犯了哪些错误，或者做了哪些他意想不到的决策。通过这个“一次性”的开发过程，他能够更好地理解自己真正的需求是什么。然后，他会清空这次尝试的全部内容，利用从中获得的洞见，来编写一份更精确、更完善的计划规格，用于真正的功能开发。这种在传统开发中因成本过高而无法实现的方法，在 AI 时代变得可行。

Boris 对此表示赞同，并将其归纳为几种不同的工作模式。第一种是“原型模式”(prototyping mode)，其目标是快速构建一个能触及所有相关系统的最简可行产品，以便了解系统中的未知因素并打通整个流程。这种模式下，他也会像 Dan 一样，让 Claude 先尝试，观察其失败之处，然后通过按两次 `Escape` 键回滚到上一个检查点，再重新尝试。第二种是“一键完成模式”(one-shot tasks)，适用于那些他有足够信心 Claude 能够一次性成功完成的简单任务。在这种情况下，他会下达指令，然后使用 `Shift+Tab` 组合键设置自动接受所有权限请求，接着便可以切换到其他终端去处理别的事情。第三种则是针对“更困难的特性开发”，这些任务在过去可能需要数小时的工程时间。对于这类任务，他会使用 `Shift+Tab` 进入“计划模式”(plan mode)，首先与 Claude 就详细的执行计划达成一致，然后再让它开始编写任何代码。Boris 指出，随着模型能力的提升，需要使用计划模式的任务边界也在不断外移，许多过去需要详尽规划的任务，现在更先进的模型已经可以直接处理。这体现了一个总体趋势：过去需要通过外部脚手架（如复杂的提示工程）实现的功能，正逐渐被模型本身的能力所吸收。

子代理 (sub-agents) 是另一个强大的高级功能。Dan 分享了一个非技术性的应用案例：报销。他构建了一个 Claude Code 项目，该项目首先使用金融 API 下载他所有的信用卡交易记录，然后启动两个子代理：一个代表他自己，另一个代表公司。这两个代理会进行“辩论”，以确定哪些是合理的报销项目。这种“对抗性过程”的模式展现了子代理的有趣用法。Boris 解释说，子代理的核心价值在于“不相关的上下文窗口”，即让两个或多个代理在互不知情的情况下独立工作，这往往能产生更好的结果。在团队内部，子代理被用于大规模的代码迁移和复杂的代码审查。例如，在代码审查时，他们会启动多个子代理，一个负责检查代码是否符合 `claude.md` 中的规范，一个负责追溯 Git 历史记录，另一个负责寻找明显的 bug。这些子代理找到大量潜在问题后，团队会再启动新的一批子代理，专门负责检查和排除其中的“假阳性”(false positives)，最终得到一份高质量、高准确度的问题列表。Cat 也提到她正在尝试构建一个用于前端测试的子代理，它使用 Playwright 来发现客户端错误并尝试执行更多的应用测试步骤。

### 拥抱潜在需求与 Claude Agent SDK 的演进

Claude Code 的产品哲学深受一个经典产品理念——“潜在需求”(Latent Demand) 的影响。Boris 详细阐述了这一理念，即通过构建一个“可被破解”(hackable) 且足够开放的产品，观察用户如何“滥用”它来满足其最初设计之外的需求，然后基于这些观察到的行为来开发新功能，因为这些行为已经证明了市场需求的存在。他以自己在 Meta 的经历作为例证：Facebook Dating 的诞生源于他们发现，个人主页 60% 的浏览量来自于非好友的异性；而 Marketplace 的推出，则是因为他们观察到 Facebook 群组中 40% 的帖子是买卖交易信息。

这种哲学在 Claude Code 的开发中得到了充分体现。团队专注于为开发者提供强大的扩展点，并观察他们如何利用这些扩展点进行创造。Boris 分享道：“开发者热爱破解和定制工具，作为我们自己产品的用户，这让构建和使用过程充满乐趣。” 一个典型的例子是“钩子”(hooks) 功能的诞生。团队收到了大量用户反馈，抱怨 Claude Code 经常在他们离开座位（比如去冲咖啡）时请求权限，导致任务中断。用户希望能在 Claude Code 请求权限时收到 Slack 通知。为了满足这个需求，团队并没有直接构建一个 Slack 集成，而是由工程师 Dixon 开发了钩子功能。这允许用户在 Claude Code 执行流程的几乎任何一个节点插入自定义的确定性逻辑，从而可以轻松实现发送 Slack 通知，或者任何其他用户想要的功能。

正是这种对潜在需求的敏锐洞察，最终推动了产品定位的重大转变。团队发现，无论是内部员工还是外部用户，越来越多的人开始将 Claude Code 用于非编码任务。Cat 举例说，她用 Claude Code 来进行市场研究，比如抓取并分析全球公司的工程师数量并进行排名。人们用它来写博客、管理数据输入、构建邮件助手，甚至进行法律和金融分析。其核心能力——一个能够长时间运行、访问互联网、编写并执行代码的代理循环——被证明具有极强的通用性。只要给予明确的任务和必要的数据源，它几乎可以构建任何东西。当团队意识到数以千计的公司已经在使用该产品的 SDK 构建各种非编码应用时，他们决定将“Claude Code SDK”正式更名为“Claude Agent SDK”，以更准确地反映其作为通用智能代理开发工具包的本质。Boris 提到，像 Noah Brier（播客之前的嘉宾）那样，使用它来构建 Obsidian 笔记和思维导图的应用案例，在用户中非常普遍，这进一步证明了其通用性和强大的潜力。

### 代理式搜索的崛起与复合式工程范式

在技术选型上，Claude Code 团队做出了一个与业界主流不尽相同的决策：他们优先采用“代理式搜索”(agentic rag/search) 而非向量搜索 (vector search)。Cat 解释了这一选择背后的考量。首先，向量嵌入 (vector embeddings) 的维护成本非常高，代码库需要被持续不断地重新索引，而且很容易因为本地的代码变更而变得过时。其次，对于希望在企业内部部署的客户来说，向量数据库暴露了更多的攻击面和安全风险。最关键的是，团队发现 Claude 模型本身非常擅长进行代理式搜索，即通过主动执行命令（如 `grep`, `find` 等）来查找信息。这种方式不仅可以达到与向量搜索同等级别的准确度，而且部署方案更为简洁和安全。同时，对于那些确实需要语义搜索能力的用户，他们仍然可以通过 MCP (Machine-Readable Capability) 工具的方式，自行管理索引并将其能力暴露给 Claude Code 使用。

这一技术理念与 Dan 提出的“复合式工程”(Compounding Engineering) 范式不谋而合。在传统的工程模式中，每增加一个新功能，都会使下一次的开发变得更加复杂。而复合式工程的目标恰恰相反：你刚刚完成的功能应该让下一个功能的构建变得更加容易。Dan 的团队通过将每次开发过程中的所有学习和经验——例如，计划的制定和修改、测试中发现的问题等——进行编码化，将其固化到提示 (prompts)、子代理和斜杠命令中，从而构建一个不断积累知识的“记忆系统”。这样一来，即使是对代码库不熟悉的成员（比如 Dan 自己），也能够迅速上手并高效地贡献代码。

Boris 表示，Anthropic 内部也在实践类似的方法，他们通过多种方式为 Claude Code 注入“记忆”。最直接的方式是维护一个名为 `claude.md` 的文件，当团队成员在代码审查中发现一个错误时，他们会直接指示 Claude：“将这个规则添加到 `claude.md` 中”，这样下次模型就不会再犯同样的错误。另一种方式是编写测试用例。Boris 感叹道：“我再也不会因为要求别人写测试而感到内疚了”，因为 Claude 可以轻松地完成这项工作，团队内部接近 100% 的测试都是由 Claude 编写的。此外，对于那些需要频繁强制执行的规则，团队会创建内部的 lint 规则，而这些规则同样 100% 由 Claude 编写。这个系统非常有效，Boris 提到团队新来的经理 Fiona，尽管已经有十年没有写过代码，但在她入职的第一天就成功地提交了 PR，因为 Claude Code 帮助她跨越了重新学习编码和熟悉新代码库的双重障碍。这种将 power-user 的行为模式产品化，并带给所有用户的过程，是团队的核心工作之一。

### 未来的交互形态与主动式代理的展望

关于命令行界面 (CLI) 是否是 AI 编程工具的最终形态，团队普遍认为答案是否定的。尽管当前他们非常专注于将 CLI 体验打磨到极致，使其尽可能智能和可定制化，但这仅仅是探索过程中的一站。Cat 和 Boris 都承认，没有人能确切知道未来的交互形态会是什么样，整个领域的发展速度实在太快。因此，团队正处于一个广泛的“实验模式”中。他们已经推出了 CLI 工具、IDE 插件（包括一个更易于上手的 GUI 版本）、在 GitHub 中通过 `@claude` 进行交互的方式，以及可以在任何设备上使用的网页版和移动版。

Boris 认为，未来一个重要的趋势是模型将拥有“更长的自主运行时间”。团队内部会持续测试，在没有人类干预的情况下，模型能够在容器中自主完成任务多长时间。这个时间已经从最初的几小时，增长到了最新的两位数小时级别（约 30 小时）。他预测，下一代模型将能够自主运行数天。这种能力的飞跃也带来了新的挑战。首先是运行环境的问题。用户显然不希望为了让一个长时间任务持续运行而必须保持自己的笔记本电脑开着。这就需要一个稳定可靠的容器化执行环境。其次，随着代理能力的增强，很可能会出现“Claude 监控 Claude”的新范式。人类需要能够随时检查和理解这些自主运行的代理系统正在做什么，但同时，交互界面也需要为代理之间的通信进行优化，以实现更高的带宽。

与此同时，团队也深刻认识到，纯粹的命令行界面对于非技术用户，甚至对于一些不习惯在终端中工作的工程师来说，都存在着很高的门槛。Cat 分享了一个有趣的例子：她曾指导一位市场团队的同事使用 Claude Code，结果对方的屏幕上弹出了 30 多个权限请求弹窗，因为她的电脑是第一次使用终端环境。为了解决这个问题，团队正在积极探索更多图形化界面。VS Code 的 GUI 插件和网页版 Claude Code 都是朝着这个方向迈出的第一步，旨在为技术背景较弱的用户提供一个更友好的起点。一个令人鼓舞的现象是，Anthropic 内部的数据科学家们已经开始自发地学习并使用 Claude Code，这再次印证了产品在“代码相关”领域的潜在需求。团队的策略是，在核心上继续为顶尖工程师打造最强大的工具，同时通过提供更多易于上手的界面，让更多人能够“破解”和使用这个产品。最终，他们甚至设想，模型本身可以成为教会用户如何使用工具的老师，通过向用户展示其能力和用法，实现一种渐进式的学习体验。
