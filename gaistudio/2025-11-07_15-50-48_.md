### **开发自己的 Agent Skills：前言与回顾**

本期视频将分享如何开发专属于自己的 Agent Skills（智能代理技能）。在之前的分享中，我们介绍了 Claude 发布的这项新特性——Skills。目前，这项功能已经集成在 Claude 的各类产品中，包括桌面应用、Claude Code 以及 Claude API。通过使用 Skills，我们可以极大地拓展 AI 应用的能力边界。简单来说，Agent Skills 是一种让 Claude 能够遵循的、可重复使用的、可定制化的指令集。感兴趣的朋友可以回顾上一期的视频，详细了解什么是 Agent Skills 以及如何使用它们。

本期视频将在此基础上更进一步，尝试开发一个属于我们自己的 Agent Skills，从而充分挖掘和拓展 AI 的潜力。开发自己的 Agent Skills 最大的优势在于，它不仅能让我们将在过去任务执行中，特别是与 AI 协作完成任务时积累的宝贵经验和技巧进行总结与整理，还能将这些固化的能力轻松地在后续任务中重复使用，极大地提升了效率。同时，它还促进了团队协作。我们可以将封装好的能力以 Skill 或插件（plugin）的形式分享给团队成员，从而在整个团队内部形成一个统一的、标准化的技能库，这对于提高整个团队的工作和学习效率非常有帮助。

### **Agent Skills 的核心架构与工作原理**

要开发自己的 Agent Skill，首先需要了解其基本架构和工作原理。

#### **Skills 架构：Agent + Skills + Computer**

官方文档中提供了一张名为“Agent + Skills + Computer”的架构图，清晰地阐述了其核心构成。整个架构可以分为两个主要部分：Agent configuration（代理配置）和 Agent virtual machine（代理虚拟机）。

1.  **Agent configuration（代理配置）**：这一部分定义了 Agent 的基础能力和配置信息。
    *   **Core system prompt（核心系统提示）**：这是 Agent 运行的基础指令。
    *   **Equipped Skills（已装备的技能）**：这里列出了 Agent 当前具备的各种技能，就像个人拥有的技能包一样，例如处理 `bigquery`、`docx`、`pdf`、`xlsx` 等不同格式文件的能力。
    *   **Equipped MCP servers（已装备的 MCP 服务器）**：这部分配置了 Agent 可以连接和使用的 Model Context Protocol (MCP) 服务器，使其能够与外部系统或远程服务进行交互。

2.  **Agent virtual machine（代理虚拟机）**：这是 Agent 执行代码和与文件系统交互的虚拟环境。
    *   **运行环境**：这个虚拟机支持多种脚本语言和命令，如 `Bash`、`Python` 和 `Node.js`。这意味着 Agent 具备了直接执行命令和代码的能力。
    *   **File system（文件系统）**：Skills 以目录和文件的形式存在于这个虚拟机的文件系统中。每个 Skill 通常对应一个独立的目录，目录内包含了定义该技能所需的所有文件。例如，一个名为 `bigquery` 的 Skill 目录中可能包含 `SKILL.md`（技能的核心描述和指令文件）、`auth.json.enc`（加密的认证信息）和 `notes.md`（附加说明）等文件。同样，一个处理 `pdf` 文件的 Skill 目录可能包含 `SKILL.md`、`forms.md`（表单填写指南）、`reference.md`（API 参考）以及一个 `scripts` 子目录，其中存放着如 `fill_form.py` 这样的 Python 脚本。

这个架构的核心思想是：Skills 在一个代码执行环境中运行，Claude 在这个环境中拥有文件系统访问权、bash 命令执行能力和代码执行能力。可以将其想象成，这些 Skills 作为目录存在于一台虚拟机上，而 Claude 使用与我们在自己电脑上操作文件时相同的基本命令来与它们进行交互。

#### **Skills 的工作方式与加载机制**

Skills 的工作方式遵循一个三层内容、三级加载的渐进式披露（progressive disclosure）系统。这种基于文件系统的架构使得 Claude 能够按需分阶段加载信息，而不是一次性将所有上下文全部消耗掉，从而提高了效率。

*   **三类 Skill 内容**：
    1.  **指令（Instructions）**：这是 Skill 的核心部分，包含了指导 Claude 如何执行任务的详细步骤、工作流程、最佳实践和指南。
    2.  **代码（Code）**：可执行的脚本文件，例如 Python 或 Node.js 脚本，让 Claude 可以通过运行这些脚本来执行确定的、自动化的操作。
    3.  **资源（Resources）**：额外的参考材料，如数据库模式、API 文档、模板或示例等。

*   **三级加载机制**：
    1.  **Level 1: Metadata (元数据) - 始终加载 (always loaded)**：每个 Skill 的 `SKILL.md` 文件头部都包含一个 YAML 格式的元数据部分（frontmatter）。这部分提供了关于 Skill 的基本发现信息，主要包括 `name`（技能名称）和 `description`（技能描述）。Claude 在启动时会加载所有可用 Skills 的元数据，并将其包含在系统提示中。这种轻量级的方法意味着用户可以安装许多 Skills 而不会产生上下文惩罚，因为 Claude 只需要知道每个 Skill 的存在及其用途，而无需加载其全部内容。
    2.  **Level 2: Instructions (指令) - 触发时加载 (loaded when triggered)**：这是 Skill 的主体部分，包含了具体的执行步骤和知识。当用户请求的内容与某个 Skill 的描述相匹配时，Claude 才会通过 `hash` 从文件系统中读取该 Skill 的 `SKILL.md` 文件，并将其指令内容加载到上下文窗口中。只有在这个时候，这部分内容才会进入上下文。
    3.  **Level 3: Resources and code (资源和代码) - 按需加载 (loaded as needed)**：这部分内容包含了指令、代码和资源等其他辅助材料。只有在执行 Skill 的过程中确实需要时，这些额外的文件才会被加载。

### **如何创建自定义 Skills**

要创建一个自定义 Skill，核心是创建一个包含 `Skill.md` 文件的目录。这个文件是 Skill 的核心，它定义了 Skill 的元数据和执行指令。

#### **创建 Skill.md 文件**

每个 Skill 都必须包含至少一个 `Skill.md` 文件。该文件由两个主要部分组成：元数据（Metadata）和 Markdown 主体（Markdown Body）。

*   **必需的元数据字段（Required metadata fields）**：
    *   `name`: 为你的 Skill 指定一个人类友好的名称，最多64个字符。例如：“Brand Guidelines”。
    *   `description`: 清晰地描述这个 Skill 的功能以及何时使用它，最多300个字符。这个字段至关重要，因为 Claude 会根据它来决定何时调用你的 Skill。

*   **可选的元数据字段（Optional Metadata Fields）**：
    *   `version`: 用于追踪 Skill 的版本，方便迭代和管理。例如：“1.0.0”。
    *   `dependencies`: 列出 Skill 运行所需的软件包依赖。例如：“python>=3.8, pandas<=1.5.0”。

#### **添加资源和脚本**

*   **添加资源（Adding Resources）**：如果一个 `Skill.md` 文件需要包含过多信息，或者某些部分只适用于特定场景，你可以通过在 Skill 目录中添加额外的文件来组织内容。例如，创建一个 `REFERENCE.md` 文件来存放补充信息和参考资料。在主 `SKILL.md` 文件中引用它，可以帮助 Claude 在需要时访问这些资源。
*   **添加脚本（Adding Scripts）**：对于更高级的 Skill，可以将可执行的代码文件（如 Python 或 JavaScript 脚本）附加到 `Skill.md` 文件中，从而允许 Claude 运行代码。通常的做法是创建一个名为 `scripts` 的子目录，并将脚本文件放在其中。需要注意的是，Claude 和 Claude Code 可以从标准仓库（如 Python PyPI, JavaScript npm）安装软件包，但在使用 API Skills 时，所有依赖项都必须预先安装在容器中。

#### **打包与测试 Skill**

当 Skill 文件夹完成后，需要将其打包成一个 ZIP 压缩文件以便上传。打包时需要遵循正确的结构：

*   **正确结构**：ZIP 文件解压后，应该是一个与 ZIP 文件同名的文件夹，该文件夹内包含 `Skill.md` 和其他相关文件/目录。
    ```
    my-skill.zip
    └── my-skill/
        ├── SKILL.md
        └── resources/
    ```
*   **错误结构**：直接将 `Skill.md` 等文件放在 ZIP 文件的根目录下是错误的。

打包完成后，就可以上传并进行测试。在 Claude 桌面应用中，可以通过 `Settings > Capabilities` 页面上传 ZIP 文件。上传后，在对话中尝试使用能够触发该 Skill 的提示词，并检查 Claude 的思考过程，确认它是否正确加载了你的 Skill。

### **实战演练：用 AI 开发个人写作风格 Skill**

接下来，通过一个具体的实例来演示如何开发自己的 Agent Skills。我们将利用 Claude 桌面应用，让 AI 帮助我们创建一个关于“个人写作风格”的 Skill。

首先，让 Claude 学习如何开发 Skills。讲者将官方文档的链接（`https://docs.claude.ai/docs/agent-skills-overview`）发送给 Claude，并要求它阅读该文档，以理解 Agent Skills 的工作原理以及如何开发自定义 Skill。Claude 迅速抓取并阅读了文档内容，并给出了一个全面的学习摘要，证明它已经理解了核心概念。

接着，讲者提出了具体的开发任务：“为我的个人写作风格开发一个简单的 Skill。如果你能构建正确的文件夹结构并打包成一个 ZIP 包让我下载，那就最好了。”为了让 Skill 更符合个人偏好，讲者详细描述了自己的写作风格要求：
1.  **常规操作**：通常会给 AI 一个链接，让其翻译或重写成一篇介绍 Agent Skills 的中文文章。
2.  **避免 AI 味**：AI 生成的文章通常带有典型的“AI 味”（AI flavor），例如过多地使用项目符号（bullet points）、有序列表，以及“引言-正文-结论”的刻板结构。希望新的 Skill 能够避免这些。
3.  **行文流畅**：期望句子和段落能够平滑地衔接，写作风格不应仅仅是技术文档的罗列。
4.  **正确使用标点**：要求在目标语言（中文）中正确使用标点符号。
5.  **交互式澄清**：讲者坦言自己不擅长精确表达个人风格，因此要求 Claude “向我提问以帮助你理解我的真实想法，然后再完成 Skill 的开发”。

Claude 接收到指令后，立即提出了一系列澄清问题，以更好地理解讲者的偏好。这些问题围绕几个方面展开：
*   **关于结构与流程（About Structure & Flow）**：询问叙事风格（故事性散文、信息丰富的博客文章还是学术论文）、段落结构（长度变化、焦点集中还是使用过渡句）。
*   **关于语言与语调（About Language & Tone）**：确认中文标点符号的使用规范、技术内容的语调偏好（专业但平易近人、轻松的科技博客风格，还是权威但不枯燥）。
*   **关于内容组织（About Content Organization）**：询问信息呈现方式（融入自然句子和段落，还是通过示例和解释）、章节过渡方式等。

讲者针对这些问题给出了自己的偏好和解释。例如，他指出写作的语调取决于主题和内容，技术博客可以专业，个人博客可以更具对话性；在转述第三方文章时，人称需要做相应调整，比如将原文的“我发现 AI 很幼稚”（I found AI is pretty naive）改写为“Kim 发现 AI…”（Kim found AI...）。

在经过两轮深入的问答和澄清后，Claude 表示已经清晰地掌握了讲者的写作风格画像。随后，它开始执行开发任务，步骤如下：
1.  **创建主 `SKILL.md` 文件**：为个人写作风格 Skill 创建核心的 `SKILL.md` 文件。
2.  **创建 ZIP 包**：将 `writing-style` skill 打包成一个 ZIP 压缩文件。
3.  **移动文件**：将 ZIP 文件移动到可供用户下载的输出目录。

最终，Claude 成功创建了一个名为 “Natural Writing Style” 的 Skill，并提供了一个可下载的 ZIP 文件。它还详细列出了这个 Skill 包含的核心行为，如自适应语调、流畅衔接、智能列表使用等，并说明了如何使用它。

最后，讲者进行了对比测试。他先让未加载新 Skill 的 Claude 根据一篇技术文章撰写博客，生成的文章带有明显的 AI 风格，频繁使用项目符号和列表，结构较为刻板。接着，他将新开发的 `personal-writing-style.zip` 文件上传并启用。然后，他向 Claude 发出相同的指令，并明确要求“使用 personal-writing-style”。这一次，Claude 生成的文章风格迥然不同，全文更加流畅自然，几乎没有使用列表，段落之间衔接得当，可读性大大提高，完全符合讲者预期的“去 AI 味”的个人写作风格。这个实例充分证明了通过开发自定义 Agent Skills，可以有效地让 AI 的行为和输出更符合个人或团队的特定需求。
