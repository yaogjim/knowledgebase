### 使用 Deep Agents 解决“史上最佳”之争：梅西 vs C罗

视频开篇，演讲者展示了一个引人注目的应用场景：利用一个 AI 代理 (Agent) 来回答体育界最具争议的话题之一——“谁是史上最佳球员（GOAT）？梅西还是C罗？”。他指出，这是一个复杂且需要大量研究才能回答的问题。

当用户提出 “Who is the GOAT? Messi or Ronaldo?” 的问题后，AI 代理的执行流程在屏幕上清晰地展现出来。这个代理并不仅仅是简单地进行一次网络搜索，而是展现出了一套复杂且智能的工作流程。首先，AI 代理接收到问题后，它立即认识到这个问题的复杂性，并规划了解决该问题的步骤。它的第一步是“现在让我对这两位球员进行深入研究。我将并行研究梅西和C罗，以收集关于他们职业生涯、成就和影响的全面信息。”

紧接着，代理自动生成了两个并行的子代理 (Sub-agents)，分别命名为 `research-agent` (研究代理)。这两个子代理的任务被明确地分离开来：一个子代理专门负责全面研究利昂内尔·梅西（Lionel Messi）的职业生涯，而另一个则专门研究克里斯蒂亚诺·罗纳尔多（Cristiano Ronaldo）的职业生涯。代理为每个研究任务都设定了详细的要求，包括需要收集的信息类别：
1.  **职业生涯统计数据**：包括俱乐部和国家队的进球数、助攻数和出场次数。
2.  **主要奖杯和成就**：如欧洲冠军联赛、联赛冠军、国际赛事冠军等。
3.  **个人奖项**：例如金球奖（Ballon d'Or）、FIFA 年度最佳球员等。
4.  **比赛风格和技术能力**。
5.  **职业生涯时间线和关键时刻**。
6.  **保持的记录**。
7.  **对球队和整个足球运动的影响**。
8.  **近期成就**：特别提到了包括 2022 年世界杯在内的近期表现。

在两个研究子代理并行工作，执行了十几次网络搜索并收集完所有必要信息后，主代理进入了下一个阶段：撰写报告。它给自己下达了指令：“现在，根据所有进行的研究撰写一份全面的最终报告。” 这份报告被写入一个名为 `final_report.md` 的文件中，内容详尽，包含了对两位球员的全面分析，并附上了引用的来源。

为了确保报告的质量和公正性，代理的工作流程并未就此结束。它启动了最后一个步骤：自我评判。代理给自己下达了新的指令：“现在让我对最终报告进行评判，看看是否需要改进。” 它生成了一个评判任务，要求检查最终报告的多个方面，包括信息的准确性、两位球员之间的平衡性、分析的完整性、结构和可读性，以及来源和引用的质量。这个评判过程旨在发现报告中可能存在的任何遗漏或偏见，并进行修正。演讲者最后总结道，这个能够自动规划、并行研究、撰写报告并进行自我评判的复杂工作流，正是通过 Deep Agents 轻松构建的。

### Deep Agents 深度解析：超越传统工具调用的强大框架

为了让观众理解 Deep Agents 的工作原理，演讲者首先从基础概念讲起。他展示了一张简单的示意图，描述了传统的大语言模型（LLM）与工具（Tools）之间的交互，这是一个简单的循环调用过程。他将 Deep Agents 定义为“一个更强大的工具调用循环 (a more powerful tool calling loop)”，并提到业界将这种灵活的、通用的代理框架称为“代理工具套件 (Agent Harness)”。Deep Agents 之所以强大，是因为它在传统的工具调用循环基础上，扩展了几个至关重要的核心能力。

首先是**规划工具 (Planning Tool)**。在工具集中增加了一个专门用于规划的工具。这个工具的核心作用是帮助代理“为更复杂的任务追踪一个待办事项列表 (to-do list)”。当面对一个需要多个步骤才能完成的复杂任务时，代理可以利用这个工具来制定计划、分解任务，并按部就班地执行，确保不会偏离目标。

其次是**文件系统工具 (Filesystem Tools)**。Deep Agents 不仅内置了一套文件系统工具，还具备连接到自定义文件系统后端（如 State、Store 或本地文件系统）的能力。这项能力带来了两个非常实用的应用模式：
1.  **卸载上下文 (Offloading Context)**：当工具调用的返回结果非常大时（例如，一个很长的文档或大量数据），如果将这些信息全部塞进 LLM 的上下文窗口，不仅成本高昂，还可能超出上下文长度限制。文件系统工具允许代理将这些大型结果保存到文件中，然后只将文件的路径或摘要信息传递给 LLM，从而极大地节省了上下文空间。
2.  **存储指令和记忆**：演讲者提出了一个更有趣的模式，即使用文件系统来“存储代理的实际指令或记忆”。这意味着代理的核心行为逻辑（即它的系统提示或长期记忆）可以作为文件存储。开发者可以通过修改这些文件来动态地更新和改进代理的行为，而无需重新部署整个应用程序，这为代理的长期演进和迭代提供了极大的便利。

第三项，也是最具特色的核心能力，是**生成子代理 (Sub-Agents)**。Deep Agents 可以将其他代理作为工具来调用，这些被调用的代理就是子代理。这一特性使得 Deep Agents 的架构“超级灵活 (super flexible)”。主代理可以将一个复杂问题中“孤立的部分 (siloed parts)”委托给专门的子代理去处理。这样做的好处是显而易见的：它能够“保持主代理的上下文窗口干净”，因为主代理无需关心每个子任务的执行细节，只需分派任务和接收结果。同时，每个子代理可以专注于一个更狭窄的任务领域，从而更高效、更精确地完成工作。视频开头的梅西与C罗的例子，就是通过生成两个并行的研究子代理来高效完成信息收集的。

最后，演讲者展示了一张集成的架构图，清晰地描绘了这些组件如何协同工作。整个 Deep Agents 框架构建在 LangChain 和 LangGraph 之上。LangChain 提供了 LLM 与工具交互的基础，而 LangGraph 则负责管理代理的状态和控制流程的执行，将规划、文件系统和子代理等高级功能有机地组织在一起，形成了一个强大而可靠的代理系统。

### 实践入门：构建一个基础的 Deep Agents 研究员

在解释了 Deep Agents 的核心概念之后，演讲者进入了实际编码环节，演示如何从零开始构建一个简单的研究代理。他选择使用 TypeScript 进行开发，整个过程清晰地展示了 Deep Agents 的易用性。

首先是环境准备和包的安装。演讲者打开终端，执行了命令 `pnpm install deepagents` 来安装 Deep Agents 的相关依赖包。这个命令执行完成后，他展示了一个名为 `researcher.ts` 的代码文件，所有的实现都将在这个文件中完成。

接下来是代码的导入部分。他特别指出了几个关键的导入语句，这些是使用 Deep Agents 的基础。`import { createDeepAgent, type SubAgent } from "deepagents";` 这行代码从 `deepagents` 包中导入了 `createDeepAgent` 函数和 `SubAgent` 类型。`createDeepAgent` 是用于组装和创建最终代理实例的核心函数，而 `SubAgent` 类型则用于后续定义子代理的结构。

构建代理的第一步是为其配备工具。演讲者定义了一个名为 `internetSearch` 的工具，用于执行网络搜索。这个工具的实现遵循了 LangChain 的标准工具定义模式。他使用了 LangChain 提供的 `tool` 辅助函数来创建一个工具对象。该工具的底层能力由 `TavilySearch` 提供，这是一个专门用于网络搜索的集成服务。工具的实现逻辑被封装在一个异步函数中，该函数接收一个名为 `query` 的字符串作为输入参数。在函数内部，代码会实例化一个 `TavilySearch` 客户端，并设置了一个参数 `maxResults: 5`，表示每次搜索最多返回 5 个结果。然后，它调用搜索服务的 `invoke` 方法，并将用户的查询传递进去，最后返回搜索结果。

为了让 LLM 能够理解和使用这个工具，工具的定义还包含了一些元数据：
*   `name`: "internet_search"，这是工具的唯一标识符。
*   `description`: "Run a web search"，这是一段简短的描述，告诉 LLM 这个工具的功能是什么。
*   `schema`: 使用了 `zod` 库来定义工具的输入模式，明确指出 `query` 参数是一个字符串。

演讲者强调，这只是一个标准的 LangChain 工具，开发者可以根据自己的具体需求，定义更多连接到不同数据源（如数据库、API 等）的自定义工具，从而极大地扩展代理的能力。这个简单的工具定义过程为后续构建更复杂的代理功能奠定了基础。

### 模块化与专业化：定义研究与评判子代理 (Sub-Agents)

在定义了基础的搜索工具后，演讲者深入探讨了 Deep Agents 的核心特性之一：子代理（Sub-Agents）。他强调，“子代理非常适合处理孤立的多步骤任务”。为了让这个概念更具体，他举了一个生动的例子：规划一个为期两周的日韩旅行。这样一个复杂的任务可以被巧妙地分解：创建一个子代理负责规划日本的行程，另一个子代理负责规划韩国的行程。由于这两部分任务相对独立，它们可以并行执行，从而提高效率。

基于这一理念，演讲者为他的研究代理定义了两个功能截然不同的子代理。

第一个是**研究子代理 (Research Sub-Agent)**。这个子代理专门负责执行深入的研究任务。
*   **系统提示 (System Prompt)**：首先，他定义了一个名为 `subResearchPrompt` 的字符串，作为该子代理的系统提示。内容是：“你是一个专注的研究员。你的工作是根据用户的问题进行研究。进行彻底的研究，然后用详细的答案回复用户。” 这段提示为子代理设定了明确的角色和职责。
*   **子代理定义**：接着，他创建了一个名为 `researchSubAgent` 的对象，其类型为 `SubAgent`。这个对象包含了几个关键字段：
    *   `name`: "research-agent"，这是子代理的唯一名称。
    *   `description`: "用于研究更深入的问题。一次只给这个研究员一个主题。不要传递多个子问题。" 这段描述至关重要，它告诉主代理在何种情况下应该调用这个子代理。
    *   `systemPrompt`: 引用了上面定义的 `subResearchPrompt`。
    *   `tools`: 将之前创建的 `internetSearch` 工具分配给这个子代理，使其具备网络搜索的能力。

第二个是**评判子代理 (Critique Sub-Agent)**。这个子代理的功能更加特殊，它不负责直接回答用户的问题，而是扮演着质量控制的角色，负责评审主代理生成的研究报告。
*   **系统提示**：同样，他为这个子代理定义了一个详细的系统提示 `subCritiquePrompt`。内容是：“你是一个专注的编辑。你的任务是评判一份报告。” 提示中明确指出，报告可以在文件系统中的 `final_report.md` 路径下找到，而原始问题则在 `question.txt` 文件中。这体现了子代理与文件系统的无缝集成。提示还包含了一个非常详尽的检查清单（`Things to check:`），要求编辑检查报告的各个方面，例如：每个部分的标题是否恰当、报告是否全面、文章是否深入分析了原因、影响和趋势、结构是否清晰、语言是否流畅易懂等。
*   **子代理定义**：他创建了 `critiqueSubAgent` 对象：
    *   `name`: "critique-agent"。
    *   `description`: "用于评判最终报告。给这个代理一些关于你希望它如何评判报告的信息。"
    *   `systemPrompt`: 引用了 `subCritiquePrompt`。
    *   这个子代理在这个例子中没有被分配工具，但可以根据需要添加（例如，如果评判需要再次搜索以验证事实）。

演讲者通过定义这两个子代理，展示了如何将一个复杂的任务分解成模块化、专业化的子任务，并通过主代理进行调度，这正是 Deep Agents 强大灵活性的体现。

### 统筹与执行：组装并运行主 Deep Agent

在完成了工具和两个核心子代理（研究代理和评判代理）的定义之后，演讲者进入了最后一步：将所有组件整合起来，定义并运行主代理。

首先，他为主代理精心设计了一个系统提示（System Prompt），存储在 `researchInstructions` 常量中。这个提示是主代理的“大脑”，详细规定了它的工作流程和行为准则。这个指令集非常详尽，包含了多个步骤：
1.  **记录问题**：指示代理做的第一件事是“将原始用户问题写入 `question.txt`，以便你有一个记录”。
2.  **委派研究任务**：明确指示代理“使用 `research-agent`（研究子代理）进行深度研究”。这告诉主代理应该如何利用其子代理。
3.  **撰写报告**：“当你认为有足够的信息来撰写最终报告时，将其写入 `final_report.md`”。这指定了报告的生成时机和输出位置，利用了文件系统工具。
4.  **委派评判任务**：“你可以调用 `critique-agent`（评判子代理）来获取对最终报告的评判。” 并且补充说，这个过程可以重复多次，直到对结果满意为止，这展示了一种迭代优化的工作模式。
5.  **最终报告格式要求**：提示中还包含了关于如何撰写最终报告的具体说明，例如报告的结构（引言、主题A概述、主题B概述、A与B的比较、结论），以及严格的引用规则，要求提供来源标题和URL。

有了这些组件，演讲者使用 `createDeepAgent` 函数来实例化主代理。这个函数的配置对象清晰地将所有部分联系在一起：
*   `model`: 指定了使用的 LLM，这里是 `new ChatAnthropic`，并选择了 `claude-sonnet-4` 模型。
*   `tools`: 将 `internetSearch` 工具直接提供给主代理，使其能够处理简单的、一步到位的搜索请求。
*   `systemPrompt`: 传入了上面定义的 `researchInstructions`。
*   `subagents`: 将 `critiqueSubAgent` 和 `researchSubAgent` 作为一个数组传入，正式将这两个子代理注册为主代理可调用的“工具”。

最后，他编写了一个 `main` 异步函数来调用并执行这个刚刚创建的 Deep Agent。他使用 `deepAgent.invoke()` 方法，并传入一个包含用户问题的 `HumanMessage` 对象：“Who is the GOAT? Messi or Ronaldo?”。在执行代码之前，他提醒观众，他已经在后台配置好了必要的 API 密钥（用于 Tavily 搜索和 Anthropic 模型调用）以及 LangSmith 追踪，以便后续观察代理的内部工作流程。一切准备就绪后，他运行了脚本，启动了代理来解决这个复杂的“史上最佳”之争。

### 幕后揭秘：通过 LangSmith 追踪分析 Deep Agent 的执行流程

当代理完成任务后，演讲者切换到了 LangSmith 的追踪（Trace）界面，对代理的整个执行过程进行了详细的复盘。这个可视化界面揭示了 Deep Agent 在后台执行的每一步操作，将其复杂的“思考”过程变得透明。

首先，追踪日志清晰地显示了代理的**规划阶段**。代理执行的第一个关键动作是 `write_todos`（写入待办事项）。这表明代理首先根据系统提示和用户问题，制定了一个行动计划。这个计划包含了多个待办事项，例如：研究梅西的职业生涯成就、统计数据和影响；研究C罗的职业生涯成就、统计数据和影响；分析和比较两位球员；撰写一份综合性的最终报告；以及对最终报告进行评判并根据需要进行完善。

接下来是**并行执行研究任务**的阶段。在追踪视图中，可以清楚地看到两个并行的 `task`（任务）模块。演讲者指着这两个模块解释道：“这些是专门研究梅西和C罗的子代理，我们可以看到它们是并行启动的，这为我们节省了一些时间。” 在每个任务模块内部，可以看到对应的研究子代理多次调用 `internet_search` 工具，执行具体的搜索查询，以收集所需信息。网页搜索返回的结果可能包含很多原始、杂乱的数据，但子代理能够处理这些信息，并返回干净、简洁、只包含核心信息的响应给主代理。

在两个研究子代理完成各自的任务后，主代理整合了它们返回的信息，并执行了 `write_file`（写入文件）操作。它将一份详尽的分析报告写入了 `final_report.md` 文件。这份报告结构清晰，内容全面，并且包含了所有引用的来源链接。

报告撰写完毕后，代理流程并未结束，而是进入了**自我评判阶段**。追踪日志显示，主代理启动了另一个 `task`，调用了评判子代理（`critique-agent`）。该子代理的任务输入是明确的指令：“请评判我写的关于梅西与C罗GOAT之争的最终报告。” 它会根据预设的评判标准，对 `final_report.md` 文件中的内容进行审查。

最后，演讲者总结道，这个演示只是 Deep Agents 功能的一个简单示例。其核心是一个高度灵活的“工具套件 (harness)”，用户可以根据自己的需求随意扩展这些预置的工具和能力。他透露，未来还会有更多功能在 Python 和 JavaScript 版本的库中推出，并感谢观众的收看。
